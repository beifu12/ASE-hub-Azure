排查思路

  • For all issues, check the following log files:
  • DiagnosticsTestResults,json: Located at the top-level of the support package. Check the test status of each test to determine whether it’s passed or failed. If any test has failed, troubleshooting should start from here.
  • hcsmgmt.Primary: Located at \\<Device_Logs>\SupportPackage\<Device_Name>\<Device_Serial>\hcslogs. Check for any instances of [Err].

操作步骤 / 命令

  • Get-HcsApplianceInfo.txt: Located at \\<Device_Logs>\SupportPackage\<Device_Name>\<Device_Serial>\cmdlets\PodCmdLets. Check the device software version. If the expected version and the version listed in this log are different, an update issue occurred on the device.
  • Get-HcsTimeSettings.txt: Located at \\<Device_Logs>\SupportPackage\<Device_Name>\<Device_Serial>\cmdlets\PodCmdLets. Check the time zone. If there is a discrepancy between the expected time zone and the time one listed in this log, update the time zone via the local WebUI and try the failed operation once more. If it fails, check the time settings once again and see if the discrepancy still exists.
  • Get-HcsNetInterface.txt: Located at \\<Device_Logs>\SupportPackage\<Device_Name>\<Device_Serial>\cmdlets\PodCmdLets. Check the ‘State’ of each port. If any ports show status other than ‘Up’, (Or blank, for any ports that are not connected), troubleshooting should start from here.
  • Get-ClusterResource.txt: Located at \\<Device_Logs>\SupportPackage\<Device_Name>\<Device_Serial>\cmdlets\PodCmdLets. Check the ‘State’ of each resource. There are some resources that are down by design and should be in an Offline state. These can be ignored. Any resources in a Failed state should be investigated further.
