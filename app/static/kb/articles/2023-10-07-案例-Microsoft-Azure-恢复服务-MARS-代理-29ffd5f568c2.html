Choose Action – Change Properties

Set Passpharase follow the below screenshot.

You can generate the Security Pin in the Recovery Services Vault.

Erro when Re-generate passphrase

结论:

As the VM is installed from scratch, the new installed VM will be considered as a new VM which has different operation system, disk volume ID and system GUID. This will lead to a mismatched value between the MARS agent (on the new installed VM) and the backup agent registered matedata (on the recovery vault service in 21v cloud).

To fix the issue, we may have to remove the legacy backup agent registered matedata from recovery vault.

This operation will delete the backup data (which is from the old VM and the latest backup time is 2022/07/10). But actually, we will not be above to recover the data due the mismatched metadata.

Detailed steps are:

In the recovery service vault security settings page, disable the security features to allow the deletions of MARS backup data. This a temporary steps and we will re-enable the security feature to disallow the deletion of backup data.

From the azure portal -> backup vault -> Backup infrastructure -> Azure Backup agent page, choice the VM GOAAZRCSRV010 and delete it.

It will clear all data (include the backup data and registered metadata.

Once done, we can go to the Azure portal. In the recovery service vault security settings page, enable the security features again.

We can then register the VM again from Microsoft Azure Backup in VM GOAAZRCSRV010.

Note: as we have deleted the metadata from Azure recovery vault, the cbengine service may need some time to sync from cloud. Please wait for several minutes for service initialization before you can do register server and you will see error like below which can be ignored:

Or you can uninstall MARS and reinstall it to avoid the sync error.

Once the register is done. We can recreate backup schedule.
