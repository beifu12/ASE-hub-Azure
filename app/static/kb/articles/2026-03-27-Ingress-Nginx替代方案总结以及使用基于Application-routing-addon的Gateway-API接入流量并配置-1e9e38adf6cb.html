首先总结Azure端对Ingress Nginx的替代方案：

随着社区对Ingress Nginx项目在2026三月份停止支持，Azure端对Ingress Nginx的替代方案总结有如下几种:

1、AGIC（Application Gateway Ingress Controller）

支持Ingress API，但是中国区的AGIC 不支持AKS CNI Overlay 网络：什么是应用程序网关入口控制器？ | Azure Docs ，使用之前需要确认当前的AKS网络模型是什么。

2、Application Gateway for Containers

Application Gateway for Containers支持Ingress API and Gateway API，是主要的推荐产品。但是Application Gateway for Containers在中国区还不支持，在Global 目前是preview状态. 可以持续保持关注：What is Application Gateway for Containers? | Microsoft Learn

3、Application routing addon with Gateway API

Application routing add-on 支持gateway API，目前是预览状态 ：Azure Kubernetes Service (AKS) application routing add-on with the Kubernetes Gateway API (preview) - Azure Kubernetes Service | Microsoft Learn . 目前中国区还没有文档，但是测试可以使用，可以参考下面的配置说明，后续可以关注什么时候正式发布。

4、Istio addon for AKS

Istio service mesh add-on 支持 Gateway API和istio ingress API 。

如果使用 Gateway API， 在China和Global均是Preview ，可以参考之前的Onenote：使用基于istio addon 的K8S gateway API 接入流量，Azure文档:Kubernetes Gateway API Ingress for Istio Service Mesh Add-on for Azure Kubernetes Service (AKS) (preview) - Azure Kubernetes Service | Microsoft Learn 后续可以关注什么时候正式发布。

如果使用istio ingress API, 已经正式发布 ,可以参考之前的Onenote: 使用基于Istio addon 的istio APIs 接入流量, Azure文档：Azure Kubernetes Service (AKS) external or internal ingresses for Istio service mesh add-on - Azure Kubernetes Service | Microsoft Learn

5、Application routing add-on with NGINX

使用Ingress API，但是官方表示，随着Ingress Nginx的推移，Application routing add-on with NGINX将会继续支持到2026/11月:

Azure Kubernetes Service (AKS) managed NGINX ingress with the application routing add-on - Azure Kubernetes Service | Microsoft Learn

下面说明如何使用Application routing addon的Gateway API接入流量（测试验证3的实现）：

1、安装Gateway API CRDs

az feature register --namespace "Microsoft.ContainerService" --name "ManagedGatewayAPIPreview"

az aks update -g aks-20251117 -n aks20251117-2 --enable-gateway-api

#确认gateway crds资源正常安装

kubectl get crds | grep "gateway.networking.k8s.io"

2、安装Application routing addon with gateway API

az aks update --resource-group aks20260325 --name aks0325 --enable-app-routing-istio

application routing addon底层也是依赖的istio，因此可以在aks-istio-system namespace看到istiod的pod

以上基础架构环境就部署完成了，可以使用gateway API 发布应用

3、使用gateway API 发布应用，实现HTTP跳转到Https

(1) 使用证书创建secret

kubectl create secret tls tls-secret-0325  --cert=./fullchain.pem  --key=./privkey.pem

(2) 定义gateway资源，因为这里使用的是基于Application routing addon的gateway ,因此gatewayClassName需要填写为approuting-istio

因为这里实现tls卸载，因此tls mode为terminate

apiVersion: gateway.networking.k8s.io/v1

kind: Gateway

metadata:

name: httpbin-gateway

spec:

gatewayClassName: approuting-istio

listeners:

  • name: http

protocol: HTTP

port: 80

  • name: https

protocol: HTTPS

port: 443

tls:

mode: Terminate

certificateRefs:

  • kind: Secret

name: tls-secret-0325

allowedRoutes:

namespaces:

from: Same

(3) 定义HTTProute资源，实现应用发布，并将http跳转为Https

A . 部署应用：

Kubectl apply -f https://raw.githubusercontent.com/Abbott-fu/k8shttpbin/refs/heads/main/httpbin.yaml

该部署会创建httpbin的后端应用pod以及httpbin的cluster service

B. 部署HTTProute,并配置跳转，这部分主要是HTTPRoute的配置

#跳转rule

kind: HTTPRoute

name: httpbin-requestredirect

parentRefs:

  • name: httpbin-gateway

sectionName: http

hostnames: ["fuzl0325.azurecn.cn"]

rules:

  • matches:
  • path:

type: PathPrefix

value: /

filters:

  • type: RequestRedirect

requestRedirect:

path:

type: ReplaceFullPath

replaceFullPath: /get

scheme: https

statusCode: 301

---

#https rule

name: httpbin-https

value: /get

backendRefs:

  • name: httpbin

port: 8000
