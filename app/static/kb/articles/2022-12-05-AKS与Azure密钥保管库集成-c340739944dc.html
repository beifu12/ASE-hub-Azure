测试步骤(以下标黄处替换为自己的值)：

下载安装最新CLI ， https://docs.azure.cn/zh-cn/cli/install-azure-cli-windows?view=azure-cli-latest&tabs=azure-cli

运行az --version,验证已使用最新的CLI及aks-preview版本。

如未安装aks-preview，请运行az extension add --name aks-preview安装该扩展；如已安装，但是非最新版本，请运行az extension update --name aks-preview更新至最新版本。如未使用最新版本，可能会在运行后续命令时无法识别提供程序。

登录Azure账号

az cloud set -n AzureChinaCloud   //设置云环境为中国区

az login  //弹出登录界面，输入用户名、密码进行登录

az account set -s <subid>  //选择对应订阅

为现有集群添加azure-keyvault-secrets-provider提供程序

az aks enable-addons --addons azure-keyvault-secrets-provider --name myAKSCluster --resource-group myResourceGroup

连接至AKS群集

az aks get-credentials --resource-group myResourceGroup --name myAKSCluster

请确认已经安装了kubectl，如未安装，请使用az aks install-cli进行安装。进入kubectl安装目录（默认是C:\Users\xiaojing\.azure-kubectl），或配置全局环境变量。

检查是否在节点上安装了机密存储 CSI 驱动程序和 Azure 密钥保管库提供程序

在现有密钥保管库中创建一个机密ExampleSecret，如已拥有机密，可忽略此步骤。

az keyvault secret set --vault-name xjkeyvault -n ExampleSecret --value MyAKSExampleSecret

创建一个用户分配的托管标识并分配给规模集

az identity create -g myResourceGroup -n useridentity

az vmss identity assign -g MC_myResourceGroup_myAKSCluster_chinanorth2 -n aks-agentpool-19694923-vmss --identities /subscriptions/d3c17595-846b-42e1-8e58-

dc872136fbd2/resourceGroups/myResourceGroup/providers/Microsoft.ManagedIdentity/userAssignedIdentities/useridentity //此处资源组为vmss所在资源组及规模集名称

为标识授予可Get密钥管库中的密钥、机密或证书，此处只做了secret的授权，如需证书和密钥，请参考文档命令即可

az keyvault set-policy -n xjkeyvault --secret-permissions get --spn 09e953c2-e9cc-4208-a119-e7920ab66cb2

创建一个SecretProviderClass，

kubectl apply -f secretproviderclass.yaml

创建一个测试pod，yaml文件和文档没变化

.\kubectl.exe apply -f pod.yaml

Pod创建成功

验证机密，在测试pod上可以获取到机密。

.\kubectl.exe exec busybox-secrets-store-inline-user-msi -- ls /mnt/secrets-store/

获取机密值

.\kubectl.exe exec busybox-secrets-store-inline-user-msi -- cat /mnt/secrets-store/ExampleSecret
