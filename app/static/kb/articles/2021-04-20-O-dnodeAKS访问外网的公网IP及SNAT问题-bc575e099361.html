1、默认情况下，没有负载均衡器，此时平台会给Node随机分配一个IP出站。可以在Node上run一个Pod查看这个出站IP

kubectl run clienttest  --image=debian  --replicas=1  -i -t --restart=Never

apt-get update && apt-get install curl -y

其IP是：

{"ip": "139.217.220.26", "country": "上海市", "city": "Azure"}

2、如果创建了公共负载均衡器，那么node将使用负载均衡器的IP出站。

如何创建公共负载均衡器用于Node出站，参考如下：

（1）查找Node的资源组

az aks show --resource-group fuzlk8srg --name testk8s --query nodeResourceGroup -o tsv

或者在门户查看

（2）在以上资源组中，创建一个公网IP地址（请注意首先需要使用CLI登录Azure）

az network public-ip create     --resource-group MC_fuzlk8srg_testk8s_chinaeast2    --name myAKSPublicIP     --allocation-method static

得到IP:139.217.223.236

（3）、创建一个SVC

yamL文件如下，LOadbalancer的IP填写上面创建的IP地址

apiVersion: v1

kind: Service

metadata:

name: my-egress

spec:

loadBalancerIP: 139.217.223.236

type: LoadBalancer

ports:

  • port: 80

此时Node会在负载均衡器后端

此时再次测试Pod对外访问，将使用负载均衡器的IP.

此时如果在门户再创建第二台Node,再创建一个Pod

kubectl run clienttest2  --image=debian  --replicas=1  -i -t --restart=Never  --overrides='{ "apiVersion": "v1", "spec": { "nodeName":"aks-nodepool1-29185247-1" } }'

测试对外访问，依然得到负载均衡器的IP地址。

此种情况下，Node将使用负载均衡器的IP出站。

最后，经我测试，Node出站不再受SNAT的限制。可以轻松对外发起5000连接。远超文档https://docs.azure.cn/zh-cn/load-balancer/load-balancer-outboud-connections#problemsolving 中1024个端口的限制。

3、当然，您可以给node设置独立的公网IP地址。但是这一点官方没有提及。如果给Node设置了独立的公网IP，Node将使用独立的公网IP出站。
