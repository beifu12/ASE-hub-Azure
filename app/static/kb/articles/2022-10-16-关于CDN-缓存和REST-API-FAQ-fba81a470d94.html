  • 缓存过期后缓存文件如何处理？
  • 用户执行缓存刷新后，CDN如何处理缓存？
  • 缓存刷新分为两种情况：
  • URL刷新：执行URL刷新后，会清空所有CDN的缓存。当有用户请求时，按未缓存的场景处理缓存有效期和回源。因此，用户首次访问会看到MISS 缓存。
  • 目录刷新：把整个目录中的文件都标记为缓存过期状态。当有用户请求时，则参考缓存过期的场景进行处理。这种情况下，取决于文件是否更改，用户首次访问看到的状态可能时MISS或HIT。

  • 密钥有效期：默认是永久。

缓存有效期如何计算？

以CDN边缘节点被用户首次访问开始计时。这种方式下，未被访问的节点不会有缓存，首次被用户访问可能需要回源，有效期也是以该节点被首次访问开始算起。

例如：如用户设置了.txt后缀的缓存时间为12小时。CDN节点X于2018/1/1 8:00被首次访问以获取file.txt文件，那么该文件在节点X上的缓存有效期是2018/1/1 8:00 - 2018/1/1 20:00；CDN节点Y于2018/1/1 12:00被首次访问获取file.txt，则该文件在节点Y上的有效期为2018/1/1 12:00 - 2018/1/2 00:00。

缓存过期后缓存文件如何处理？

CDN不会立即清除缓存，但会标记文件的缓存状态为过期。当后续用户每次访问时，CDN都会回源或查询上层节点进行校验。若文件不变，则直接返回缓存内容，但不会更新缓存状态。当文件改变，则覆盖已有缓存，并开始重新计算有效期。

用户执行缓存刷新后，CDN如何处理缓存？

缓存刷新分为两种情况：

URL刷新：执行URL刷新后，会清空所有CDN的缓存。当有用户请求时，按未缓存的场景处理缓存有效期和回源。因此，用户首次访问会看到MISS 缓存。

目录刷新：把整个目录中的文件都标记为缓存过期状态。当有用户请求时，则参考缓存过期的场景进行处理。这种情况下，取决于文件是否更改，用户首次访问看到的状态可能时MISS或HIT。

注意，校验文件是否变更的条件可能有所不同，如有的可能仅以Last modified time为参考；有的会以etag为参考；或者几种条件相结合。若用户对刷新有疑问，欢迎联系技术支持。

Azure CDN Management Portal中的密钥管理，主要用于Azure Mooncake  CDN REST API 的调用。关于密钥的限制信息如下：

密钥上限：一个订阅最多生成10个Key ID和Key Value队。

密钥有效期：默认是永久。

安全管理：生成的Key ID和Key Value主要用于计算授权头。作用范围是整个订阅下的所有CDN终结点的REST API的操作。考虑到人员更新和信息安全，用户可以删除、更新或禁用密钥，以禁止某些授权。

Ibiza Portal 和CDN management portal的同步问题

8月初期进行了优化，改进了两个Portal之间的数据同步状态。尽量保证30分钟内两边的状态能完成同步。因此，能在很大程度上解决信息不同步造成的问题，提升用户体验。

CDN 对支持的TLS 协议进行了调整，目前只支持1.2版本以上的协议。若用户使用叫老版本的浏览器，可能会遇到TLS交互问题，建议使用新的浏览器，或其他支持新版本TLS的浏览器。
