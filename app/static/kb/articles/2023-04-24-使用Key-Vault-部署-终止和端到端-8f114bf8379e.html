背景：

如果需要针对新创建的APPGW 使用 Key Vault 证书配置 TLS 终止，请参阅通过 Azure PowerShell 使用 Key Vault 证书配置 TLS 终止。

目前Azure 门户上已经支持Azure 应用程序网关启用Key Vault 证书，部署出基于使用 Key Vault证书的SSL 卸载多站点、SSL 端到端功能，但是在部署引用过程中，因为应用程序网关和用户托管标识之间的分配关系、Key Vault 的访问策略权限问题，导致部署使用 Key Vault证书失败、致使Azure 应用程序网关也处于Failed 状态。

因此基于上述的使用背景、本文旨在

指导对现有的Azure 应用程序网关 使用Key Vault 来部署出基于使用 Key Vault证书的SSL 卸载多站点、SSL 端到端功能。

排查解决操作过程中导致Azure 应用程序网关失败的状态

场景1，Key Vault 访问策略分配权限错误或者未分配权限，创建后导致Azure APPGW 状态失败，并有如下报错：

#解决方案：

在Key Vault 上，修正访问权限，使得托管表示具备基于机密权限PermissionsToSecrets的 Get权限。

无需额外的配置，更新当前创建失败的Azure 应用程序网关，更新失败的HTTP 侦听器配置，点击“保持”更新即可。

场景2：没有将用户托管标识分配给应用程序网关，直接的使用Key Vault，也是无法成功的，缺少用户托管标识的权限：

解决方案：因为Azure 应用程序网关已经处于Failed 状态，任何其他的操作部署都是禁止的，所以无法直接给失败的Azure应用程序网关分配用户托管标识。因此，需要首先通过删除错误的证书、侦听器来恢复Azure应用程序网关到Healthy 状态，然后分配用户标识、并创建新的侦听器。

#此排查需要使用Azure PowerShell 等工具，具体如下：

删除创建的无效证书资源：

Remove-AzApplicationGatewaySslCertificate -Name www.contoso.comvaultCert -ApplicationGateway $appgw

删除引用证书的侦听器：

Remove-AzApplicationGatewayHttpListener -Name www.contoso.com -ApplicationGateway $appgw

更新保存配置：

Set-AzApplicationGateway -ApplicationGateway $appgw
