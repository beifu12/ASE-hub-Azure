一句话摘要

每个数据中心都被分配到一个物理区域。 物理区域映射到 Azure 订阅中的逻辑区域，不同的订阅可能有不同的映射顺序。 Azure 订阅在创建订阅时自动分配其映射。 因此，一个订阅的区域映射可能与其他订阅的不同。 例如：订阅 A 的物理区域 X 可能映射到逻辑区域 1，而订阅 B 的物理区域 X 可能映射到逻辑区域 3。

2024/11/24

每个数据中心都被分配到一个物理区域。 物理区域映射到 Azure 订阅中的逻辑区域，不同的订阅可能有不同的映射顺序。 Azure 订阅在创建订阅时自动分配其映射。 因此，一个订阅的区域映射可能与其他订阅的不同。 例如：订阅 A 的物理区域 X 可能映射到逻辑区域 1，而订阅 B 的物理区域 X 可能映射到逻辑区域 3。

创建虚拟机时显示的zone1,2,3是逻辑可用性区域, portal不会显示分配的物理可用性区域.

1, 可以通过在北三区域不同逻辑可用性区域创建虚拟机，通过ASC查看具体分配到哪个物理区域.

已我的订阅为例: 从ASC中可以看到我的订阅mapping关系为 逻辑1对应物理3, 逻辑2对应物理1, 逻辑3对应物理2

物理区域映射到 Azure 订阅中的逻辑区域，不同的订阅可能有不同的映射顺序。但同一订阅的映射关系是固定的.

2, 以上方法需要我们创建虚拟机才可以查看到对应的映射关系，也可以使用Azure CLI 或 Azure PowerShell 从 API 检索信息

CLI: az rest --method get --uri '/subscriptions/{subscriptionId}/locations?api-version=2022-12-01' --query 'value'

Powershell:

$subscriptionId = (Get-AzContext).Subscription.ID

$response = Invoke-AzRestMethod -Method GET -Path "/subscriptions/$subscriptionId/locations?api-version=2022-12-01"

$locations = ($response.Content | ConvertFrom-Json).value

可以看到对应关系与创建虚拟机通过ASC查看到的一致.
