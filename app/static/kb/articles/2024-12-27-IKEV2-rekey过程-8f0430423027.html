I’d like to share this best practices of IKEv2 phase1 SA lifetime with you since we got lots of case regarding rekey recently:

SA lifetime is local concept, it doesn’t means the peer can’t form if the lifetime’s value does not match, generally the rekey process will initiated by the lowest lifetime peer, for example, if Cisco CSR router set it to 120 seconds while Azure VPNGW fix to 28800 seconds, the rekey is always initiated by CSR at 60 ± X  seconds before lifetime expired.

Yes, the rekey message type should be CREATE_CHILD_SA, Azure side should expect this from WFPdiag log which collected from VPNGW.
