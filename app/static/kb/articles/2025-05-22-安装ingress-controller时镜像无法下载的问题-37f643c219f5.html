问题现象 / 场景

  • 参考工单：SR_2020080544134_[S500]create ingress，pulling image failed.
  • 客户想在AKS中创建ingress-nginx，根据Azure的如下文档进行操作，但是在创建的时候出现了AKS无法拉取镜像的问题。

参考工单：SR_2020080544134_[S500]create ingress，pulling image failed.

【问题】

客户想在AKS中创建ingress-nginx，根据Azure的如下文档进行操作，但是在创建的时候出现了AKS无法拉取镜像的问题。

https://docs.azure.cn/zh-cn/aks/ingress-tls

【原因】

由于nginx-controller的提供方换了repo，导致暂时无法正常下载，因为是国外的站点us.gcr.io，目前国内已经无法下载了。

helm的安装和使用：https://docs.azure.cn/zh-cn/aks/kubernetes-helm

https://gitee.com/chenze007/kube-charts-mirror

helm repo add stable  https://mirror.azure.cn/kubernetes/charts/

【解决办法】

对于中国区的AKS，建议参考如下文档（已更新）。

https://github.com/Azure/container-service-for-azure-china/tree/master/aks

k8s.gcr.io

registryk8s.azk8s.cn/ingress-nginx/kube-webhook-certgen:v1.4.0

Usgcr.azk8s.cn/k8s-artifacts-prod/ingress-nginx/controller:v0.34.1

mcr.azk8s.cn/oss/kubernetes/hyperkube:v1.15.7

修改官网配置，手工指定image的registry：

Old:

Use Helm to deploy an NGINX ingress controller

helm install nginx stable/nginx-ingress \

--namespace ingress-basic \

--set controller.replicaCount=2 \

--set controller.nodeSelector."beta\.kubernetes\.io/os"=linux \

--set defaultBackend.nodeSelector."beta\.kubernetes\.io/os"=linux \

--set defaultBackend.image.repository=gcr.azk8s.cn/google_containers/defaultbackend-amd64

New:

--set controller.image.registry=usgcr.azk8s.cn \

修改后可以正常安装使用。
