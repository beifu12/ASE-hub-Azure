Hana Liu

分享一个工单，SR_2021022280788_[MS-LED]k8s服务无法扩容。

问题描述：

===============

客户在门户扩容AKS集群时提示报错“The credentials in ServicePrincipalProfile were invalid. Please see https://aka.ms/aks-sp-help for more details. (Details: adal: Refresh request failed. Status Code = '401'. Response body: {"error":"invalid_client","error_description":"AADSTS7000215: Invalid client secret is provided.\r\nTrace ID: 85f8b193-b0b8-46ed-8fc6-5b18a3c35d00\r\nCorrelation ID: 008a9f20-1073-4b25-9c09-396f161c5019\r\nTimestamp: 2021-02-22 07:19:23Z","error_codes":[7000215],"timestamp":"2021-02-22 07:19:23Z"”

问题背景：

客户的AKS服务主体密码过期，曾在2/20 为服务主体重置过密码，但并未更新到AKS集群。

排查过程：

根据报错中提示的url https://aka.ms/aks-sp-help ，可以找到对应的Global Azure官方文档https://docs.microsoft.com/zh-cn/azure/aks/kubernetes-service-principal#troubleshoot。

根据报错，可以在github 中找到参考链接https://github.com/Azure/azure-cli/issues/13881 ，其中的解决办法为为AKS集群更新凭据。然而在实际操作过程中，发现，直接为AKS集群更新凭据，仍会遇到 的报错。根据官方文档，先删除aksServicePrincipal.json（Linux 路径$HOME/.azure/aksServicePrincipal.json，Windows 路径 %USERPROFILE%\.azure\aksServicePrincipal.json），也会提示同样的报错。

解决方案：

在为AKS服务主体重置密码后，需要先将aksServicePrincipal.json中的"client_secret"更新为新的AKS服务主体密码，然后再为AKS集群更新凭据。更新成功后，客户可以从门户上成功扩容。

Linux 环境下的参考步骤

#获取AKS集群的服务主体ID#

az aks show --resource-group group-east2 --name k8s-east2 --query servicePrincipalProfile.clientId -o tsv

#在AKS服务主体重置密码#

az ad sp credential reset --name 226b230c-c5ac-4c2a-8ab0-6bb6a47991e8 --query password -o tsv

#备份$HOME/.azure/aksServicePrincipal.json

cp $HOME/.azure/aksServicePrincipal.json $HOME/.azure/aksServicePrincipal.json.bak

#将AKS服务主体的信息密码更新到aksServicePrincipal.json 的"client_secret"中#

vim $HOME/.azure/aksServicePrincipal.json

#将AKS服务主体的密码更新至AKS 群集#

az aks update-credentials --resource-group group-east2 --name k8s-east2 --reset-service-principal --service-principal 226b230c-c5ac-4c2a-8ab0-6bb6a47991e8 --client-secret $SP_SECRET
