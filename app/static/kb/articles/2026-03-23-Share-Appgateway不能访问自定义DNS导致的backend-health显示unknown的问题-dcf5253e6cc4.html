问题现象 / 场景

  • 用户有一套正常工作的appgateway 生产环境，一切正常。 由于业务扩展需要在同一网络环境中创建了另外一套appgateway，发现在新的环境中appgateway 无法获取backend health 状态。显示unknown，提示：
  • 4， 结合Gateway manager 的日志可以看到在获取backendserver health 时失败报异常，请求被异常关闭了。
  • And this entire issue is happening because this Custom DNS server because this DNS server is not reachable from application gateway instances.  When Gateway Manager calling instances to get backend health, mutual authentication is failing at instance side because instance is not able to reach out to CRL endpoints to get Certificate Revocation List.
  • 新建appgateway 无法访问自定义DNS 服务器导致Gateway manager 与appgateway 实例通信时的证书无法访问CRL而出现通信失败，从而出现的backend health显示为unknown 的情况。
  • 针对用户的同样网络环境中生产Appgateway （WAF-CT）可以正常访问自定义DNS 的原因，是因为用户的vnet 之前应用的自定义DNS 是10.108.4.4，在firewall 上有放行规则存在。后来用户调整了vnet 自定义DNS 为10.108.71.88，但并没有对生产环境的appgateway 的实例做重启，因此该实例依然使用旧的10.108.4.4 做为DNS。而新建的appgateway （WAT-CT02）继承了vnet 的自定义DNS 的配置使用了10.108.71.88，Firewall上没有添加放行规则导致失败。

========
