2026/01/27

作为知名的服务网格产品，istio具有强大的流量管理功能，而Istio addon具有和原生istio类似的功能，istio除了支持原生K8S Gateway API发布流量外(参考Onenote：使用基于istio addon 的K8S gateway API 接入流量)，同时也支持自身的istio APIs接入流量，istio APIs同样具有强大的功能，如针对 HTTP/gRPC/WebSocket 和 TCP 流量的负载均衡, 支持灰度发布，流量管理等等。下面演示如何使用基于Istio addon 的istio APIs在AKS中发布应用。

1、安装istio addon并启用istio 入口网关(istio ingressgateway)

(1) 添加Az AKS extension ,并查看istio mesh add-on版本

az extension add --name aks-preview

az extension update --name aks-preview

az aks mesh get-revisions --location <location> -o table

#这里使用CN3区域示例.选择与现有AKS 版本兼容的addon版本

(2) 在现有集群中安装Istio addon

az aks mesh enable -g aks20260127 -n aks0127 --revision asm-1-27

az aks show -g aks20260127 -n aks0127 --query 'serviceMeshProfile.mode'

查看istio addon生成的ns以及Pod能正常运行

kubectl get pods -n aks-istio-system

(3) 启用external入口网关istio ingressgateway

az aks mesh enable-ingress-gateway --resource-group aks20260127 --name aks0127 --ingress-gateway-type external

az aks show -g aks20260127 -n aks0127 --query 'serviceMeshProfile.istio.components'

确认ingressgateway pod已经正常运行

2、使用基于Istio addon 的istio APIs发布服务

（1）部署后端的应用

因为这里使用的是istio APIs, 因此我们需要提前在应用所在的ns上打上标签istio.io/rev=asm-X-Y（istio addon的具体版本）， 这样istio控制平面才能给应用注入sidecar代理。这里是与原生istio不同的地方，原生istio的标签 istio-injection=enabled 不起作用

这里我们把应用发布在default名称空间，因此需要执行下面的打标签命令

kubectl label namespace default istio.io/rev=asm-1-27

下面的yaml文件定义了一个httpbin的Service以及httpbin的deployment，Service的服务端口为8000，这里使用了自己registry的镜像

因为已经添加了标签，因此应用pod会被istio 控制层面自动注入sidecar代理

apiVersion: v1

kind: ServiceAccount

metadata:

name: httpbin

---

kind: Service

labels:

app: httpbin

service: httpbin

spec:

ports:

  • name: http

port: 8000

targetPort: 8080

selector:

apiVersion: apps/v1

kind: Deployment

replicas: 1

matchLabels:

version: v1

template:

serviceAccountName: httpbin

containers:

  • image: fuzlreg.azurecr.cn/mccutchen/go-httpbin:v2.15.0

imagePullPolicy: IfNotPresent

  • containerPort: 8080

（2） 定义istio Gateway 以及Virtual Service接入流量

Istio Gateway和K8S Gateway的定义格式基本上差不多，其作用是定义了前端侦听的端口和TLS配置等等

Istio VirtualServicede 定义和K8s Gateway API HTTProute的定义差不多，定义了流量的转发方式

#这里使用HTTPS接入流量，首先使用证书创建secret，创建到aks-istio-ingress名称空间中，对于AKS来说，还支持将证书部署到KeyVault中，但这里采用直接部署证书

kubectl create -n aks-istio-ingress secret tls httpbin-credential --key=./privkey.pem --cert=./fullchain.pem

#创建istio gateway 和Virtual Service

apiVersion: networking.istio.io/v1beta1

kind: Gateway

name: httpbin-gateway

istio: aks-istio-ingressgateway-external #表明使用istio ingress gateway

servers:

  • port:

number: 443

name: https

protocol: HTTPS

tls:

mode: SIMPLE

credentialName: httpbin-credential #使用创建的secret

hosts:

  • fuzlistioapi.azurecn.cn

kind: VirtualService

  • "fuzlistioapi.azurecn.cn"

gateways:

  • httpbin-gateway #指明使用上面创建的ingressgateway

http:

  • route:
  • destination:

host: httpbin #指明后端使用的Service

port:

number: 8000

查看创建的Gateway 以及Virtual Service，从aks-istio-ingress名称空间可以看出，gateway pod前端的Service 163.228.228.44 的443端口已经正常的provision了

将域名fuzlistioapi.azurecn.cn解析到163.228.228.44，测试访问情况，确认访问正常，证书加载正常。

Client-> ingress Gateway 前端的Loadbalancer serice（163.228.228.44 ）-> istio ingress gateway Pod -> 后端Service
