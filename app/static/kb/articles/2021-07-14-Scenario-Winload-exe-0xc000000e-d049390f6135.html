一句话摘要

The VM screenshot shows the binary winload.exe crashing with the error 0xc000000e

问题现象 / 场景

  • The VM screenshot shows the binary winload.exe crashing with the error 0xc000000e
  • Or another option of the same issue is
  • bcdedit /store e:\boot\bcd /set {default} bootstatuspolicy IgnoreAllFailures
  • Note: On same cases you will have the on the windows partition the variables Devices and OSDevices shown as 'unknown' which is clear that this action plan needs to be followed, however it was also found some cases where those variables were pointing to the proper partition but still it was needed to overwrite those entries and only then the VM came up. In a minimum number, you could also find this two partitions merged to one, in that case the same action plan applies however pointing to the proper partition reference.

背景信息

  • The binary \windows\system32\winload.exe exist on the drive
  • Action plan
  • - Once the OS disk is attached on a working machine, run the following from an elevated CMD
  • bcdedit /store e:\boot\bcd /set {bootmgr} device partition=e:
  • bcdedit /store e:\boot\bcd /set {default} device partition=f:
  • bcdedit /store e:\boot\bcd /set {default} osdevice partition=f:
  • Where
  • E: is the partition holding the folder \boot\bcd
  • F is the volume of the Windows directory
  • {default} is the ID of the partition holding \windows folder
  • Recreate the VM
  • Note2: On the action plan on this TSG, the identifier for the windows folder is shown as {default} which is the default value however on the screenshot above, the identifier ir a hex string like {7657baf7-492a-4263-a54e-cc66570d9e23}

解决方案

  • bcdedit /store e:\boot\bcd /set {bootmgr} integrityservices enable
  • bcdedit /store e:\boot\bcd /set {default} integrityservices enable
  • bcdedit /store e:\boot\bcd /set {default} recoveryenabled Off
