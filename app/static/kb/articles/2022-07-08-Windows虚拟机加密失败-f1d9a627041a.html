问题现象：

portal加密虚拟机OS磁盘和数据磁盘时提示报错

虚拟机满足加密支持条件，向用户索要磁盘测试当作为数据磁盘附加到其它虚拟机上时是可以正常加密的。

问题排查：

加密是虚拟机操作系统日志有警告日志BitLocker问题，客户反馈现象也是虚拟机加入了AzureAD后出现的此问题

通过系统日志可以找到加密失败的原因在于虚拟机加密扩展组件进行加密时，返回如下错误：

2022-07-05T02:47:39.3137155Z    [Info]:    Win32EncryptableVolumeWrap::GetEncryptionMethod osVer = WindowsServer2016, osBuild = 19042; EncryptionMethod.XTS256

2022-07-05T02:47:39.3293409Z    [Error]:    Win32EncryptableVolumeWrap::Encrypt failed with 2147942487

通过对该错误的分析，我们怀疑加密失败与系统内部安全策略有关，参考文档如下：

Encrypt method of the Win32_EncryptableVolume class - Win32 apps | Microsoft Docs

对比了可以正常加密的虚拟机，发现在加密失败的虚拟机上增加了多条用户自定义的安全策略；在参照默认正常的注册表配置信息进行删除之后，磁盘加密的操作可以正确完成。

客户环境中的原有注册表配置信息如下：

Computer\HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Microsoft\FVE

默认正常的注册表配置信息如下：

解决方案：

在开启Azure磁盘加密之前，如果虚拟机中存在先前部署失败的AzureDiskEncryption扩展，需要先将磁盘加密disable掉，再删除AzureDiskEncryption扩展。

参考文档：Windows VM 上的Azure 磁盘加密方案- Azure Virtual Machines | Azure Docs

在调整完注册表并重启后，第一次开启磁盘加密时如果报错，建议再执行一次disable磁盘加密-delete扩展的操作，再次尝试开启磁盘加密。
