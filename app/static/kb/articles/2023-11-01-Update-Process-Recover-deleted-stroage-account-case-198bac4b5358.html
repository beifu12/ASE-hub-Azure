  • Please note that it is impossible to recover Data at the blob level. Recovery is only possible if the deleted resources meet the requirements in the supported scenarios, and have not been removed by garbage collection. It can generally take "anytime from deletion" to 15 days for the Storage service to perform garbage collection so it is not definite that the storage accounts can be recovered.
  • For supported Storage Account Restore (Both ARM and ASM), escalate to CSS

  • Supported scenarios
  • The following resources can be restored with NO guarantee if have not been removed by the garbage collector:
  • Storage accounts
  • Blob containers
  • In GRS or RA-GRS storage accounts AND have not been recreated with the same name
  • VM Disks:
  • Only Unmanaged disks (VHD files) deleted along with the storage accounts or containers (which in above Supported Scenarios) can be restored.
  • Unsupported scenarios:
  • Restoring LRS Blob container.
  • Restoring a Blob container that has been recreated with the same name
  • Restoring Queue.
  • Restoring individual blob file in the storage account.
  • Restoring partial data in the storage account, such as files inside of an unmanaged disk (VHD file).
  • Restoring partial data in Table or Queue.
  • Restoring Managed Disks/Snapshots/Images.

Azure 存储 服务的数据还原方案

2021/11/18

From <https://docs.microsoft.com/zh-cn/troubleshoot/azure/geneforal/data-restore-storage>

背景知识

删除存储帐户或 blob 容器后，它将排队等待回收和回收。然后，系统可以释放空间以供重复使用。如果垃圾回收器尚未运行且存储空间尚未清理，则可能会还原已删除的存储帐户或 blob 容器。

运行垃圾回收器的时间因许多因素而异，例如存储规模单元上的工作负载、可用存储空间数等。平均而言，存储帐户的垃圾回收发生在删除后 14 天。但是，无法保证此时间进行还原。

数据还原方案

如果垃圾回收器尚未收集以下资源，则可以还原这些资源：

存储帐户

异地冗余存储、区域冗余存储或读取访问异地冗余存储中的 Blob 容器

还原需要新的共享访问签名 （SAS） 令牌。

备注

不支持在本地冗余存储中还原 Blob 容器。

Azure 仅支持存储帐户级别或 Blob 容器级别还原。因此，不支持以下数据还原方案：

还原队列

还原存储帐户中的 Blob 数据（单个 Blob）

还原存储帐户中的部分数据，如 Blob 内的文件

还原表或队列中的部分数据
