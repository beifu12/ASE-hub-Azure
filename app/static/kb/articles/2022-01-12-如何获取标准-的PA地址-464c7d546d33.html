[MCVKB][NET]How to get the PA address of Standard ILB via FcShell

Hi Team,

I’d like to share this approach for how to get the PA address of Standard ILB via FcShell.

Generally the old way for check the basic ILB’s PA is not working to standard ILB anymore, so here are the new way to get it via FcShell:

Find an instance in the backend pool and record the cluster/container-id

Run such command via fcshell: (11.1.1.7 is ILB’s CA address)

PS C:\FcShell\ > $f = get-fabric bjs20prdapp08

PS C:\FcShell\FcShell.Release.132.879.648\lib\net45> $c = get-container 88620074-701c-4e03-b3c4-0be7cca98c19 -fabric $f

PS C:\FcShell\FcShell.Release.132.879.648\lib\net45> $mappingResult = $f | Invoke-FclApi NetworkManagementService GetVnetAddressMappingForCAFromNmAgent($c.Node.Id, $c.Id, "11.1.1.7")

PS C:\FcShell\FcShell.Release.132.879.648\lib\net45> $mappingResult

CustomerIPAddress  : 11.1.1.7

PhysicalIPAddress  : 40.73.40.136

MacAddress         : 4D4143414444

AvailabilityZoneId : 0

IsConnected        : False

IsSecondary        : False

Assign Standard ILB an public ipv4 address as PA is by design, to unblocking global vnet peering scenario without encap ipv6 gre, instead, encap ipv4 gre:

e.g.

11.1.1.5 is Dst CA address of VM in remote VNET cross global peering, then from Src VM node capture, you will see it should be encapped with ipv6 gre:

11.1.1.7 is Dst CA address of ILB in remote VNET cross global peering, then from Src VM node capture, you will see it should be encapped with ipv4 gre:

The Src ipv4 and ipv6 address are sourcing from the VFP rule:

RULE : RouteTargetVnetGlobalPeering_VNETGP_{C5E1C584-36AA-46A1-A1D5-972B0520E6F7}_0

Friendly name : RouteTargetVnetGlobalPeering_VNETGP_{C5E1C584-36AA-46A1-A1D5-972B0520E6F7}_0

Priority : 516

Flags : 1 terminating

Type : mapencap

Conditions:

Destination IP : 11.1.0.0/16

Source IP : 172.16.0.5/32

Flow TTL: 0

MSS delta: 42,0

Rule Data:

Map space : VNETGP_{C5E1C584-36AA-46A1-A1D5-972B0520E6F7}

GRE key : 7001714

Encap Type: NVGRE

CA routing with CA source MAC enabled, ttl not decremented

Encap Source IP : 2406:e500:a101:80ae::a6e:98d7

Encap Secondary Source IP : 10.12.100.55

FlagsEx : 0
