一句话摘要

使用 ASR 将虚拟机从 东1 迁移到 东2 失败，出现了代理不可用的报错。

问题现象 / 场景

  • 使用 ASR 将虚拟机从 东1 迁移到 东2 失败，出现了代理不可用的报错。
  • 由于代理不可用导致无法创建复制项

背景信息

  • 问题描述：
  • ==============
  • 问题原因：
  • 部分 VM 需先重启以完成移动服务的升级，但是虚拟机重启后未能自动启动 waagent 。之后手动开启了 waagent 服务，并且将其加入自启动服务中。但是随后发现该机器系统盘使用率达到 100%，导致复制不能继续进行。扩容磁盘后，即可实现复制。

排查思路

  • 部分 VM 的 waagent 更新/重新安装 后还是无法正常运行。之后在 /var/log/waagent 日志中发现“/usr/bin/openssl: No such file or directory”的报错。通过查看 /usr/bin/ 下 openssl 文件，发现存在一个软链接，并且原有文件被重命名为了 openssl.old。但其实软链接中的 /usr/local/openssl/bin/openssl 文件并不存在。之后恢复了 openssl.old 到 openssl。再次重启 waagent 服务之后，代理状态恢复正常，启用复制即可成功完成。

问题描述：

==============

使用 ASR 将虚拟机从 东1 迁移到 东2 失败，出现了代理不可用的报错。

问题原因：

由于代理不可用导致无法创建复制项

解决方案：

部分 VM 通过该链接 https://docs.microsoft.com/zh-cn/azure/virtual-machines/extensions/update-linux-agent （如何更新 VM 上的 Azure Linux 代理） 里面的命令更新 Linux waagent 后即可成功启用复制项。

部分 VM 的 waagent 更新/重新安装 后还是无法正常运行。之后在 /var/log/waagent 日志中发现“/usr/bin/openssl: No such file or directory”的报错。通过查看 /usr/bin/ 下 openssl 文件，发现存在一个软链接，并且原有文件被重命名为了 openssl.old。但其实软链接中的 /usr/local/openssl/bin/openssl 文件并不存在。之后恢复了 openssl.old 到 openssl。再次重启 waagent 服务之后，代理状态恢复正常，启用复制即可成功完成。
