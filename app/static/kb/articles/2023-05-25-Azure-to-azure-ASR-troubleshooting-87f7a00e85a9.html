排查站点到站点恢复的问题

使用 Azure 至 Azure Site Recovery，可以将 Azure 虚拟机 (VM) 从一个区域复制到另一个区域。 如果出现问题，请检查以下内容：

源虚拟机上的数据更改率较高

如果源虚拟机上的数据更改率超过支持的限制，Azure Site Recovery 将创建一个事件。 转到“复制的项”>“VM”>“事件” - “过去 72 小时”。 你应当会看到“数据更改率超过支持的限制”事件：

选择要显示磁盘信息的事件：

Azure Site Recovery 限制

Azure Site Recovery 限制是每个磁盘的数据变动率和每个虚拟机的数据变动率。 实际限制因特定配置而异。 例如，单个 VM Site Recovery 能够处理每个磁盘的 5 MB/秒的变动率，最多可以处理 5 个磁盘。 Site Recovery 对每个 VM 的总变动率限制为 54 MB/秒。

若要了解是否重复出现该问题，请检查“监视”下相关虚拟机的数据变动率。 需要添加以下屏幕截图中所示的指标：

网络连接问题

Site Recovery 会将已复制数据发送到缓存存储帐户。 如果将数据从虚拟机上传到缓存存储帐户时的速度有 3 秒低于 4 MB，则可能是遇到了网络错误。

若要检查延迟问题，请使用命令行实用工具 AzCopy。 这会将数据从虚拟机上传到缓存存储帐户。 如果延迟较高，请检查你是否在使用网络虚拟设备 (NVA) 控制来自 VM 的出站网络流量。 如果所有复制流量都通过 NVA，设备可能会受到限制。

Microsoft 建议在虚拟网络中为“存储”创建一个网络服务终结点，这样复制流量就不会经过 NVA。

网络连接

Site Recovery 需要 VM 提供到特定 URL 或 IP 范围的出站连接。 VM 可能位于防火墙后面，或使用网络安全组 (NSG) 规则控制出站连接。 如果是这样，则可能会遇到问题。 确保所有 URL 都已连接。 有关详细信息，请参阅 URL 的出站连接。
