SUMMARY

Most of the time we see the VM gets rebooted unexpectedly due to node reboot or Xdisk Connectivity due to Event 17.

The node may get rebooted for the following reason.

Fabric reboots the nodes

Node crashed/bugchecked

Node itself is rebooted unexpectedly due to hardware or Power issue.

Node Marked as Dead/Human Investigate.

When fabric reboots the node you see the node state as "Booting" in the node state change table.

When the node is crashed/bugchecked or rebooted unexpectedly you would see the node state as "Unhealthy"

Sometimes you may even see State "PoweringOn" in the node state change table that means fabric tried to recover the node by Powercycling as it may have not got any response from the node for a period of time.

The node state "Unhealthy" and "PoweringOn"  means the Fabric marked the node as Unhealthy as it failed to get Heartbeat from the node agent and tried recovery by Powercycling the node.

Fabric may fail to receive Heartbeat from the node agent for the following reason.

Node Agent hung

Node is hung and unresponsive

Node lost network connectivity

Node rebooted/Power down unexpectedly

Node Crashed/bugchecked

Most the time when the nodes goes to Unhealthy followed by PoweringOn we may lose the node event logs.

You can always looked at the node state table to find what happened to the node state after it was marked Unhealthy.

If the node goes to "Unhealthy" followed by "PoweringOn", it means the node was not reachable for more than 10 minutes since marking Unhealthy and fabric tried Powercycling the node to recover it and this may happen for the following reasons. Most of the time after the PowerCycle , the node event logs may be lost and in that case please file a EEE task.

Node was powered down unexpectedly

The node OS was hung and Unresponsive

If you find Node State goes to "Unhealthy" followed by "Ready", it means Fabric failed to receive Heartbeat from node for a while and marked the Node as Ready when it receives the HB again. Once the fabric marks the node as Unhealthy, it will wait for 10 minutes (Unhealthy Timeout) before it tries to recover the node by PowerCylce/Reboot.

The node goes to Unhealthy followed by Ready within the timeout period (10 minutes) may happen for the following reason.

The node lost network connectivity for few mins

The node rebooted unexpectedly and came back

The node rebooted due to bugcheck and came back

You can pull the node event logs by running the following fcshell commands and look at the node system event logs.

PS E:\sarnshare\RD\RD\rd_cmt_stable.991231-0001\Fabric> Get-NodeAgentDiagnostics WindowsEventLogs -Node $n

In the system event logs you can look for "Bugcheck" events. You can also run MDS table FaOsCrashEventTable* with server query as NodeIdentity == "Node IP" to look for node bugcheck.  If you find any bugcheck events , please file a EEE Task.
