启用 CoreDNS query log in AKS

fuzhangliang

SR_2019070937780 _ [MS-LED]service无法被解析dns名

不太懂怎么在Azure 门户中查看AKS的DNS 查询日志，所以这里采用K8S原生的方法查看DNS query log.

AKS默认的DNS是不记录查询日志的，从coredns的configmap中可以看到，其缺少log配置，只会记录error等信息。

通过查询发现，在AKS中我们不能编辑默认的CoreDns 的configmap文件去修改配置，就算修改了也是无效的。所以使用

kubectl -n kube-system edit configmap coredns 这样的方式去修改，肯定是无效的。参见Github:

https://github.com/Azure/AKS/issues/811

也就是说我们需要将自己想要的修改的配置定义到自己的configmap.这样就可以生效了。

这里提供自定义的启用dns query log的configmap如下：

apiVersion: v1

data:

log.override: |

log

kind: ConfigMap

metadata:

labels:

addonmanager.kubernetes.io/mode: EnsureExists

k8s-app: kube-dns

kubernetes.io/cluster-service: "true"

name: coredns-custom

namespace: kube-system

然后将这个配置应用:

kubectl apply -f core-dns-my.yaml

随后删除系统的coredns pod ，删除系统的core dns不会造成影响，因为系统会重建此pod。重建后，我们自定义的配置会生效：

kubectl get pod -n kube-system -o wide

delete pod -n kube-system ********

这样我们就可以看到coredns的query log了。

比如我们在一个Pod中解析svc ，这里解析我自己的internal-nginx 和internal-test（这个不存在）

通过这个命令，就可以看log了

for p in $(kubectl get pods --namespace=kube-system -l k8s-app=kube-dns -o name); do kubectl logs --namespace=kube-system $p; done

日志比较多，尽量grep一下。

可以看到查询internal-test是NXDOMAIN （none exist domain），不存在的记录

而查询internal-nginx肯定是 no error ，正常的。

注意启用query log会造成额外开销，请谨慎操作。
