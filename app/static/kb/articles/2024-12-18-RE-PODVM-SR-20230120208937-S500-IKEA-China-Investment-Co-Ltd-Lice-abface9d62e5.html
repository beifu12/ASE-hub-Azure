We can reproduce this issue in my local environment:

My test b2c user flow endpoint URL:     https://caiwanorg.b2clogin.cn/caiwanorg.partner.onmschina.cn/oauth2/v2.0/authorize?p=B2C_1_SigninOnly&client_id=a00a6a87-e104-4731-bb8a-33393bedde49&nonce=defaultNonce&redirect_uri=https%3A%2F%2Fjwt.ms&scope=openid&response_type=id_token&prompt=login

If we also add the option “&login_hint=p.ashwin7@tcs.com”, it will also redirect to global https://login.microsoftonline.com .

https://caiwanorg.b2clogin.cn/caiwanorg.partner.onmschina.cn/oauth2/v2.0/authorize?p=B2C_1_SigninOnly&client_id=a00a6a87-e104-4731-bb8a-33393bedde49&nonce=defaultNonce&redirect_uri=https%3A%2F%2Fjwt.ms&scope=openid&response_type=id_token&prompt=login&login_hint=p.ashwin7@tcs.com

The reason is that when creating the user flow, the customer chose the ‘Sign in (Standard legacy)”.  It is a not-suggested legacy version now.

(In Global Azure, it is explicitly stating that “This is the legacy user flow. Unless you have a special business need, we don’t recommend using this version.”)

So, the next action plan:

1.   Please suggest customer to use “Sign in (Preview v2 legacy’)” marked in screenshot above.

2.   We found ‘tcs.com’ is not a AAD verified domain. Please be well noted that ‘login_hint’ is not used for crossing cloud.  If customers want to use global domain/user to login in China B2C, they need to configure the global Azure AD as B2C identity providers.  Please follow the documents below:

Add an identity provider - Azure Active Directory B2C | Azure Docs

Set up sign-up and sign-in with OpenID Connect - Azure AD B2C | Azure Docs

(If customer has further questions regarding this, they may need to create a new case specially. Thanks for understanding.)

The statement about ‘Sign in (Standard Legacy)’ in Global Azure, FYI.
