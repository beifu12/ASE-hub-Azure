排查过程：

============

1， 我们排查了用户的用户邀请及给的权限情况没有发现异常，我们也可以复现portal 报错情况，尝试用powershell 命令也出现如下的报错提醒：

2， 提交了ICM 找产品组协助，产品组给powershell命令可以正常添加， 命令中的RemoteVirtualNetworkId 与我们使用的powershell 命令“-VirtualNetworkId" 是不同的，这个参数选错导致了测试时powershell命令报错，但报错提醒却是权限问题。

Incident 675277822 : [Mooncake] | [private DNS zone ] | SR_20250821369335 | failed to link vnet in tenant B(subscription 2) to private DNS zone in tenant A(subscription1)

Log into all the subscriptions in all the tenants you have access for.

Connect-AzAccount -Environment AzureChinaCloud

Check all the subscriptions to see if you have access to both the subscriptions.

Get-AzSubscription

Select the subscription for the virtual network.

Select-AzSubscription -Subscription 24bb5929-5d74-4b53-8920-db385c915508

Get the virtual network data.

$vnet = Get-AzVirtualNetwork -Name Ford-Devops-PUVPN -ResourceGroupName NI-Ford-Devops-FOPS-RG

$vnet.id

Switch to the subscription which contains the private dns zone.

Select-AzSubscription -Subscription 6251ed2e-5975-4f69-bc06-852f68b768ba

Get the private zone data.

Get-AzPrivateDnsZone -ResourceGroupName compliance-business-stage-rg -Name privatelink.postgres.database.chinacloudapi.cn

Create a virtual network link using the virtual network id.

New-AzPrivateDnsVirtualNetworkLink -ResourceGroupName compliance-business-stage-rg -Name link1 -ZoneName privatelink.postgres.database.chinacloudapi.cn -RemoteVirtualNetworkId $vnet.id

3， 当再次跟用户一起尝试使用PG 提供的power shell命令进行操作时，用户环境中的user 可以登录tenant A 中subscription 1 却无法去登录tenant B 中的subcription 2 。 用户表示自己在邀请完user 之后又对user 的名字做了改变。于是建议用户重新创建user 并重新邀请和授权， 也不改变名字，再次运行powershell 命令后可以正常添加。

然后运行如下命令 ，但在标黄色命令时报错提醒找不到相应的订阅。

重新对用户进行邀请并指定vnet 的contributor 权限后

再次登录 并选择订阅Subscription 6251ed2e-5975-4f69-bc06-852f68b768ba

最后成功运行如下命令并添加成功。

Get-AzPrivateDnsZone -ResourceGroupName compliance-business-stage-rg -Name privatelink.postgres.database.chinacloudapi.cn

New-AzPrivateDnsVirtualNetworkLink -ResourceGroupName compliance-business-stage-rg -Name link1 -ZoneName privatelink.postgres.database.chinacloudapi.cn -RemoteVirtualNetworkId $vnet.id
