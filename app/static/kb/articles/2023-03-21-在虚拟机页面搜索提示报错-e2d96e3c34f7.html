分享一个工单，SR_20230128209106_Portal无法搜索VM。

问题现象：

客户在虚拟机页面搜索虚拟机时会提示以下报错。

报错信息：

An error occured when trying to fetch resources. Additional details from the underlying API that might be helpful: Please provide below info when asking for support: timestamp = 2022-12-06T00:56:56.0805411Z, correlationId = ac4c08ee-6ebc-4480-ba41-c0e698486334. (Code: BadRequest) Query is invalid. Please refer to the documentation for the Azure Resource Graph service and fix the error before retrying. (Code: InvalidQuery) The query has 129 path expression, which exceeds the limit of 128. A path expression is a object accessor, e.g., properties['foo']. (Code: TooManyPathExpressions)

问题原因：

根据报错的提示，path expression (个人认为可以理解为查询的列)的上限为128。而客户的查询中有”128+N”个path expression。

解决方案：

通过管理视图à编辑列删除掉多于128的N列后，可以正常搜索。

更多信息：

如果需要进行超过128列的查询，可以尝试通过打开查询，然后运行查询，进入到Azure Resource Graph Explorer 中查看。

注：Azure Resource Graph Explorer 默认会查询账户下所有订阅的信息，如需筛选特定的订阅，可以在查询语句的最后加上一行通过订阅名称或订阅ID筛选特定的订阅。

接着Hana的分享，今天遇到的工单SR_20230321219203_vm的查询功能无法使用，查询条件输入后就报错，报了同样的错误，

发现是由于客户视图的列中保存了多于一个的标签列，删除多于的标签列，问题解决。供大家参考。
