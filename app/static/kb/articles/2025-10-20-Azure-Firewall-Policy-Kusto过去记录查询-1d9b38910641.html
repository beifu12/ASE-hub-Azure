2025.10.20

大家好，Azure Firewall policy有些时候，我们无法在ASC上读取，而且客户如果近期防火墙做过操作，没有操作之前的policy记录的话，客户也是无法回滚，客户会开单要求我们帮助查询。

以下为大家提供出对应的查询方式，以便大家之后进行使用。

Azure Firewall Policy的运作方式跟其他资源有所不同，并不是直接走NRP， 而是ARM ->NFVRP-> COSMOS DB

因此，我们从ARM/NRP的常规方式查询，是无法读取到修改的内容的。

我们可以采取以下方式：

cluster('aznwchinamc.chinanorth2').database('NfvRpMds').ResourceTable # 这个查询firewall policy的cluster/database

| where CustomerSubscriptionId == "32c3461a-4917-4339-9ecb-4d1df8548b6b" #客户的订阅ID

| where ResourceGroupName == "Customer resource group name" #客户的资源组名称

| where ResourceName == "Azure firewall policy name" # 客户的Firewall policy名称

| where env_time > datetime("2025-09-09 00:00:00" ) and env_time < datetime('2025-09-19 23:30:00') #这里为客户进行修改的时间戳， 不同于正常时间戳，这里使用env_time.

| project env_time,properties, CustomerSubscriptionId, ResourceName #筛选table

输出结果如下：

这里有几点需要注意：

由于输出有字符限制，因此同一个时间的操作，并不一定会只在同一行出现，比如：

从这里开始，就可以看到客户进行的操作，虽然基本在同一时间执行，但是我们可以看到里面的输出内容是具有连贯性的, 我们将rule导出的时候，一定切记要将内容复制完整。

rule在执行输出的时候，依旧是遵循rule本身的执行优先级进行分别操作，DNAT rule > Application rule > network rule。
