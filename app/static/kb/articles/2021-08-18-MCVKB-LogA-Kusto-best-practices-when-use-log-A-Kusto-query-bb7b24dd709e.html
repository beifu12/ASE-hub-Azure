Customer may expect to use Log Analytics query result as an output. For example, use Log Analytics query action in Logic App workflow and export the query result as a time chart image.

In this case, you may need to think about the below best practice to avoid any unexpected issue.

Use time filters first

Comments: In most case, Log Analytics tables (or Kusto tables) are use Timestamp as the key/index. So it is recommended to use time filter as your query’s first where condition which will lead to a better performance.

For example:

Perf

| where TimeGenerated > ago(24h)

| where ObjectName == 'Container' and CounterName  == "Memory Usage MB"

Use aggregation for large data

Comments: If you need to export the data as a chart (like time chart etc), it is recommend to Aggregation before the chart generation. This is to let the sample data in chart be smooth.

| summarize value = avg(CounterValue) by bin(TimeGenerated, 1m), Computer

| render timechart

Careful when query cross tables

Comments:

To have better query performance, it is recommended to use a small dataset to join a large dataset.

2）Please choice right join kind when do table join.

For example, if you expect the right table may have no data but still want to do cross table query, use leftouter as join kind:

Heartbeat

| where TimeGenerated > ago(1h)

| where Computer == 'myvm'

| distinct Computer

| join kind=leftouter (

) on $left.Computer == $right.Computer
