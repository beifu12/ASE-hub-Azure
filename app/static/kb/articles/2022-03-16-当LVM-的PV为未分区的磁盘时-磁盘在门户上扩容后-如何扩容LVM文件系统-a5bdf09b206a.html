2019--9-25

参考工单：SR_2019092553304_[MS-LED]第二块磁盘LVM扩容失败

问题：客户将数据磁盘在门户上由760G扩容到1.2T后，发现磁盘之前做了LVM，是直接将磁盘（磁盘并没有分区）加入到PV，然后在LVM中创建的文件系统。fdisk -l发现没有分区表，创建分区会影响现有环境的数据，LVM无法扩容。

[root@mhspbicdh05 cdhuser]# fdisk /dev/sdc

Welcome to fdisk (util-linux 2.23.2).

Changes will remain in memory only, until you decide to write them.

Be careful before using the write command.

Device does not contain a recognized partition table

Building a new DOS disklabel with disk identifier 0x3e27172f.

Command (m for help): d

No partition is defined yet!

Command (m for help):

查找了下，官网上的步骤也是直接加入磁盘到PV

https://docs.azure.cn/zh-cn/virtual-machines/linux/configure-lvm

经研究发现使用pvresize可以解决此问题。

测试过程如下：

1. 在门户上附加了一块760G的数据磁盘，然后在系统中创建LVM

2. 挂载并创建了一个测试文件test.txt

3．在门户上对磁盘进行扩容到1023G，登陆到系统中使用lsblk查看设备已经扩容，使用pvs,vgs,lvs查看还是原来的大小

4. 执行pvresize /dev/sdd

5．查看pv和vg的大小都已经更改，lv还是原来的大小

6．执行lvextend -l +100%FREE /dev/vg03/lv03   ，扩展lv

7.再次lvs查看，发现已经扩容了。文件系统还是原来的大小。

8． 使用resize2fs /dev/vg03/lv03  拉伸文件系统。

xfs系统使用xfs_growfs

9．文件系统拉伸完成

10. 查看数据是保留的。
