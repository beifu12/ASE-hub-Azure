关联工单：2104200060001457/NET/Hyatt International Hotel ... - TrackingID#2104200060001457,SR_2021041491098

问题现象：

用户在拥有VWAN后，建立中心，中心内建立VPN站点，站点内建立链接后，将该VPN站点与中心相连，VPN联通。 随后，用户在该VPN站点新增链接后，发现该新的链接没有生效，后来通过断开VPN站点与中心的连接后，重新连接才成功。

排查过程：

1.排查用户故障点时间内，发现VWAN的VPN网关收到了本地的请求，但没有响应本地的请求。

2.模拟用户的环境进行试验，确认了在已经成功建立的VPN站点与中心的连接后，在VPN站点添加新的链接后，也是vwan端无法响应本地请求。当VPN站点与中心的连接断开并重建后，新链接则可以连接成功。 因此想询问这样的功能设计是否合理？

额外补充：Virtual Wan一个中心内可以建4个链接，也就是说一个本地地址空间的站点，可以有最多四个公共IP链接至vwan。

经过CSS确认，该问题并非产品组期望值，目前该功能问题已经提交给产品组进行解决。如果希望在不中断已有链接的情况下，新建连接并生效，可以参考以下方法：

产品组确认该问题问portal的一个产品缺陷导致，可以使用以下PowerShell命令来mitigate问题：

// Get all VpnSites/VpnSiteLinks created from Portal.

$vpnSite = Get-AzVpnSite -ResourceGroupName $rgName -Name $vpnSiteName

$vpnSite.VpnSiteLinks => This will show both VpnSiteLinks (bbb and ccc)

$vpnSite.VpnSiteLinks[1] => Select index for newly added VpnSite i.e. ccc

$vpnGatewayName = "" => Copy VpnGateway name from Portal

$vpnGateway = Get-AzVpnGateway -ResourceGroupName $rgName -Name $vpnGatewayName

$vpnConnectionName = $vpnGateway.Connections[0] => This will give VpnConnectionName

$existingVpnLinkConnection1 = $vpnGateway.Connections[0].VpnLinkConnections[0] => This will give existing VpnLinkConnection with existing VpnSiteLink: bbb

$ipsecPolicies = $existingVpnLinkConnection1.IpsecPolicies

// Create new VpnsiteLinkConnection with newly added VpnSiteLink i.e. ccc

$newVpnSiteLinkConnection2 = New-AzVpnSiteLinkConnection -Name $vpnLink2ConnectionName -VpnSiteLink $vpnSite.VpnSiteLinks[1] -ConnectionBandwidth 100 -IpSecPolicy  $ipsecPolicies

// Add newly created VpnSiteLinkConnection to Parent VpnConnection

Update-AzVpnConnection -ResourceGroupName $rgName -ParentResourceName $vpnGatewayName -Name $vpnConnectionName -VpnSiteLinkConnection @($existingVpnLinkConnection1, $newVpnSiteLinkConnection2)

$vpnGateway.Connections[0].VpnLinkConnections[1] => This will give newly created VpnLinkConnection with VpnSiteLink: ccc
