#Symptom

VM network is disconnected aligned with correctable memory errors on node. For clustered VMs, they may be restarted due to heartbeat loss over timeout period.

#Cause

When correctable memory errors are detected, host OS mark faulty pages offline and discontinue to use them. During page offline work, Host OS trigger event once for each page. During this event, Accelnet is released and reattached.

#Predictive Failure Analysis

Azure platform performs page offlining of bad memory during runtime, which is called PFA.

If there is a single bit event that is truly a single bit event the correction will occur and be invisible to the user. If it is a persistent single bit error than a single memory page will be offlined. If multiple single bits occur and the physical row address encompasses these events, then the probability of an uncorrected error to occur in the future is more likely. To avoid access to the row, a row-offline event is triggered. This could be 192 pages in worst case scenario.

In recent customer's issue, VM networking was impacted due to row-offline event, causing VF flaps. HostOS team is working on fix to reduce the event to once for offlining multiple pages.

#Resolution

Since the error pages were offlined, VM will not experience issue again on same memory area.

If node is flagged to be degraded, this means our hardware team predicted there is a risk of another failure on memory and redeploy is recommended. In this case you will see nodeAvailabilityState status either in Unallocatable or Suspected. Once all of the containers are evacuated from the node, it will be marked OFR and hardware repair is scheduled.

If node availability state is ok, VM will not be automatically redeployed. Customer can manually redeploy their virtual machine to another healthy physical node.
