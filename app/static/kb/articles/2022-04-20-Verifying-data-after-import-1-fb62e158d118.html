Microsoft Stream

Data Copy to Azure at the Datacenter

Once the Data Box POD device has been received at the datacenter, it will be connected and the copy to Azure will begin. The copy will complete in one of two ways:

Order status Completed — All of the data was ingested successfully, and the data copy percentage is 100%. The copy logs will be available for the customer to review and cross-verify their data in a separate container of the storage account the Data Box job was associated with.

Order status Completed with errors — Some amount of data was not copied to Azure (could be 1% or 99%; 1 file, or multiple files). In most cases, when data fails to copy to Azure, the customer is not charged. Especially when the failure is the fault of Microsoft (i.e., hardware or software issue on our end). Customers can be charged if the failure of the copy is identified to be the fault of the customer in some way. The copy logs, including the verbose and error logs will be available for the customer to review and cross-verify their data in a separate container of the storage account the Data Box job was associated with.

Data Copy to Azure at the Datacenter (For Support)

Lens and ASC

Lens is an extremely useful tool that can be used to view details on an Azure Data Box job, such as device details, job and copy status, as well as information on tracking and relevant IcMs.

For detailed and updated information, go to: Data Box Lens Dashboard (Note: These operations can also be done in ASC)

Causes for Data Copy to Azure

Errors that occur during a copy job to Azure are generally caused by the customer ignoring errors and warnings shown during Prepare to Ship, or skipping Prepare to Ship entirely.

When errors occur during the data copy to Azure, customers can review the copy logs to see how and why the data failed to copy. The copy logs also provide a summary of the job.

For detailed and updated information, go to: Troubleshoot data copy issues

Slow or Stalled Copy

If a customer notices that the data copy to Azure has slowed or stalled completely, verify using Lens or ASC. Once verified, do the following:

Check Lens or ASC for any relevant IcMs that might have been opened automatically.

If no IcMs exist for the Data Box job in question, raise an IcM with the XTDataPathTeam for assistance.
