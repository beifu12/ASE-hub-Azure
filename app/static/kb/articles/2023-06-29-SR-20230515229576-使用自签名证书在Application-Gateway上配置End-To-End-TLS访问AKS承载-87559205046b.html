解决方案

  • 其中后端nginx service客户采用了nodeport的类型，基于客户的AGIC我们建议客户Service使用cluster IP类型且使用默认配置
  • 协助配置客户nginx pod证书格式是中间证书+服务器证书，验证pod上可以通过https正常访问nginx-svc
  • 后端设置：客户设置了“替代新的主机名”为是，由于后端池为ip地址，需要将其设置为否
  • 探测设置：其配置中主机名为默认，导致探测unhealthy，需要修改探测中的hostname
  • 探测恢复正常后，可以通过appgw正常访问aks中的nginx应用

问题排查

确认客户配置：使用AGIC,pod证书包含了根证书，中间证书以及服务器证书，根证书通过yaml方式上传到appgw

查看客户配置的yaml

其中后端nginx service客户采用了nodeport的类型，基于客户的AGIC我们建议客户Service使用cluster IP类型且使用默认配置

---

kind: Service

apiVersion: v1

metadata:

labels:

app: nginx

name: nginx-svc

namespace: default

spec:

type: NodePortClusterIP

ports:

  • name: nginx

port: 443

targetPort: 443

nodePort: 32327

selector:

协助配置客户nginx pod证书格式是中间证书+服务器证书，验证pod上可以通过https正常访问nginx-svc

查看appgw的后端设置以及探测配置

后端设置：客户设置了“替代新的主机名”为是，由于后端池为ip地址，需要将其设置为否

探测设置：其配置中主机名为默认，导致探测unhealthy，需要修改探测中的hostname

修改命令：appgw.ingress.kubernetes.io/health-probe-hostname: <hostname>

参考文档：Annotations - Application Gateway Ingress Controller (azure.github.io)

appgw后端设置上传根证书：

appgw.ingress.kubernetes.io/backend-protocol: "https"

appgw.ingress.kubernetes.io/appgw-trusted-root-certificate: "name-of-my-root-cert1"
