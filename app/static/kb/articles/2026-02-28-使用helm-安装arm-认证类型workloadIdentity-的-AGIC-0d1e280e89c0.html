使用helm 安装arm 认证类型workloadIdentity 的 AGIC

2025/01/18

AGIC的安装文档有了更新，不过文档中提供的步骤中有些权限是缺少的，进一步测试了使用helm安装arm 认证类型workloadIdentity 的 AGIC 步骤如下：

AKS集群需要启用workload-identity，如果创建时未启用，需要使用Azure CLI 执行启用的操作

az aks update \

--resource-group "${RESOURCE_GROUP}" \

--name "${CLUSTER_NAME}" \

--enable-oidc-issuer \

--enable-workload-identity

2   接下来几个步骤会创建一个用户manage indentity 并授予对APPGW的权限以及建立联合的indentity credential，相关的文档： https://learn.microsoft.com/lt-lt/azure/aks/workload-identity-migrate-from-pod-identity

创建Manage indentity 并复制MI的所有信息到记事本中后续需要使用： az identity create --name "userAssignedIdentityName" --resource-group "resourceGroupName" --location "location"

示例： az identity create --name agicv1 -g aks --location chinanorth2

对  MI的principalID 在启用AGIC的APPGW上添加contributor 的权限： az role assignment create --assignee $principalId --role $role --scope $AppGatewayID

示例：az role assignment create --assignee c8c0564d-166c-4922-93fa-b655bb02dcca --role contributor --scope /subscriptions/d02ead13-610a-4745-b4bc-a38c9869741c/resourceGroups/appgw/providers/Microsoft.Network/applicationGateways/v2

对MI授予标识对应用程序网关资源组的 读取 访问权限： az role assignment create --role $role --assignee $principalId --scope $AppGatewayResourceGroupID

示例：az role assignment create --assignee c8c0564d-166c-4922-93fa-b655bb02dcca --role reader  --scope /subscriptions/d02ead13-610a-4745-b4bc-a38c9869741c/resourceGroups/appgw

对MI授予APPGW所在虚拟网络的网络参与者权限： az role assignment create --role $role --assignee $principalId --scope $appgw.Vnet

示例：az role assignment create --assignee c8c0564d-166c-4922-93fa-b655bb02dcca --role "network contributor"  --scope /subscriptions/d02ead13-610a-4745-b4bc-a38c9869741c/resourceGroups/aks/providers/Microsoft.Network/virtualNetworks/aks-net

对MI授权APPGW当前使用的MI的Managed Identity Operator权限：

示例：az role assignment create   --role "Managed Identity Operator"   --assignee  872a4121-2ca5-4fd1-bbfe-89ae6fac436b  --scope /subscriptions/d02ead13-610a-4745-b4bc-a38c9869741c/resourcegroups/appgw/providers/Microsoft.ManagedIdentity/userAssignedIdentities/appgwMI

3  下载helm-config ： https://docs.azure.cn/zh-cn/application-gateway/ingress-controller-install-existing

wget https://raw.githubusercontent.com/Azure/application-gateway-kubernetes-ingress/master/docs/examples/sample-helm-config.yaml -O helm-config.yaml

4   全部修改完毕后，使用helm 安装AGIC，名称是 agic-controller， 会在AKS中创建agic-controller命名开头的service account，如果使用其它的名称，对应的service account名称也要发生变化

helm install agic-controller oci://mcr.microsoft.com/azure-application-gateway/charts/ingress-azure --version 1.7.5 -f helm-config.yaml

5创建 federated-credential  ， 需要的参数有：名称是agic-controller-sa-ingress-azure的service account以及联合先前已经授权的MI的名称和资源组（标黄的部分）：az identity federated-credential create --name federatedIdentityName --identity-name userAssignedIdentityName --resource-group resourceGroupName --issuer ${AKS_OIDC_ISSUER} --subject system:serviceaccount:${SERVICE_ACCOUNT_NAMESPACE}:${SERVICE_ACCOUNT_NAME} --audience api://AzureADTokenExchange

示例：

export AKS_OIDC_ISSUER="$(az aks show --name kk  --resource-group aks  --query "oidcIssuerProfile.issuerUrl" -o tsv)"

az identity federated-credential create --name agicv1 --identity-name agicv1--resource-group aks  --issuer ${AKS_OIDC_ISSUER} --subject system:serviceaccount:default:agic-controller-sa-ingress-azure --audience api://AzureADTokenExchange

6  创建一个clusterrole并对AGIC控制器Pod使用的serviceaccount进行授予集群RBAC相关的权限

使用附件的文件创建一个 名称是agic-controller-sa-ingress-azure的cluster Role：      kubectl apply -f   agciclusterrole.yaml

然后创建一个cluster rolebinding 将 service account和cluster role绑定：

serviceaccount 需要指定安装时ingress控制器所在的名称空间

kubectl create clusterrolebinding agic-controller-sa-ingress-azure --clusterrole=agic-controller-sa-ingress-azure --serviceaccount=default:agic-controller-sa-ingress-azure
