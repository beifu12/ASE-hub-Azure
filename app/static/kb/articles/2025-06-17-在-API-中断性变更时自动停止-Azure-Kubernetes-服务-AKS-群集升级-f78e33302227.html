问题现象 / 场景

  • AKS集群从1.25升级到1.26失败，报错信息：
  • 从Release 2023-10-08后的AKS集群增加了对API版本的检测，如果发现一些目标版本不再支持的API，就会block集群升级操作，所以这次报错是expected的。
  • 从我们收到的其他案例的经验中推测可能是kube-state-metrics在call这个API。因为kube-state-metrics是三方开源的产品，我搜索了一些Github上的issue：Update bundled kube-state-metrics to v2.7.0 to mitigate deprecation warnings · Issue #14487 · DataDog/datadog-agent (github.com)
  • 这个Issue上提到版本较低的kube-state-metrics依然在使用autoscaling/v2beta2， 从kube-state-metrics 2.7.0版本之后对这个问题做了fix。

AKS资源ID：/subscriptions/0b711b65-14f9-491c-9e1d-95c6a8258c44/resourcegroups/Central_Full_Stack_Azure-Pre-prod-vnet-01/providers/Microsoft.ContainerService/managedClusters/CentralFullStackAzure

排查进展：

这个报错信息提示集群中目前正在使用autoscaling/v2beta2这个API，但是这个API在K8S 1.26版本被弃用。从后台日志可以确认到集群CentralFullStackAzure中目前确实仍然有autoscaling/v2beta2 API在使用。

从Release 2023-10-08后的AKS集群增加了对API版本的检测，如果发现一些目标版本不再支持的API，就会block集群升级操作，所以这次报错是expected的。

Releases ·Azure/AKS (github.com)

详情您可以参考这篇链接：在API 中断性变更时自动停止Azure Kubernetes 服务(AKS) 群集升级（预览版） - Azure Kubernetes Service | Microsoft Learn

从我们收到的其他案例的经验中推测可能是kube-state-metrics在call这个API。因为kube-state-metrics是三方开源的产品，我搜索了一些Github上的issue：Update bundled kube-state-metrics to v2.7.0 to mitigate deprecation warnings · Issue #14487 · DataDog/datadog-agent (github.com)

这个Issue上提到版本较低的kube-state-metrics依然在使用autoscaling/v2beta2， 从kube-state-metrics 2.7.0版本之后对这个问题做了fix。

建议：

依据以上排查，建议升级完kube-state-metrics版本后，等待至少12小时（以保证后台相关autoscaling/v2beta2记录失效），之后再次尝试升级AKS版本。
