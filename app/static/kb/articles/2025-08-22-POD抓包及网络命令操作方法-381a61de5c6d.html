注意：现在新版本的集群比如1.18+后的集群，容器运行时已经从Docker升级为containerd了，Node上已经没有docker命令，在Node上查看Container使用crictl命令，简单的说，就是将docker命令统一替换成crictl命令

查看容器 crictl ps

查看容器详细信息：crictl inspect [ContainerID]

相当多的容器为了轻量级，是不包含较为基础的命令的，比如说ip address，ping，telnet，ss，tcpdump等等命令，这就给调试容器网络带来相当大的困扰，可以通过如下方式在node上来对POD进行操作：

通过文档中的方法登陆node：https://docs.azure.cn/zh-cn/aks/ssh

如果想连接多个node，可以通过如下命令创建更多的SSH POD

#kubectl run --generator=run-pod/v1 -it --rm aks-ssh1 --image=debian

#kubectl run --generator=run-pod/v1 -it --rm aks-ssh2 --image=debian

#kubectl run --generator=run-pod/v1 -it --rm aks-ssh3 --image=debian

查看容器的container ID：

#kubectl describe pod xxxx (这个POD可以是Core DNS POD也可以是业务POD)

找到容器ID后，在Node上运行如下命令打印它的NS ID:

#docker inspect --format "{{.State.Pid}}" xxxx(上一步中获取的POD的Containter ID)

或者 Crictl inspect xxxx(上一步中获取的POD的Containter ID)

#也可以使用如下指令获取container ID

kubectl get pod <pod-name> -n <namespace> -o=jsonpath='{.status.containerStatuses[].containerID}' | cut -exid'/' -f3

#使用如下指令打印出POD PID

sudo crictl inspect <container-id> | jq '.info.pid'

#再使用如下指令进入相应的网络Namespace:

sudo nsenter -t <pod-PID> -n sh

#20240905 https://github.com/kvaps/kubectl-node-shell 这样子去获取container PID也是个办法，第2、3步不用在AKS中不用执行：

kubectl node-shell -x <node>

Download crictl

wget https://github.com/kubernetes-sigs/cri-tools/releases/download/v1.28.0/crictl-v1.28.0-linux-amd64.tar.gz -O- | \

tar -xzf- -C /usr/local/bin/

Setup CRI endpoint

export CONTAINER_RUNTIME_ENDPOINT=unix:///host/run/containerd/containerd.sock

Find your container

crictl ps | grep kube-apiserver

#3ff4626a9f10e e7972205b6614 6 hours ago Running kube-apiserver 0 215107b47bd7e kube-apiserver-talos-rzq-nkg

Find pid of the container

crictl inspect 3ff4626a9f10e | grep pid

"pid": 1

"type": "pid"

"getpid",

"getppid",

"pidfd_open",

"pidfd_send_signal",

"waitpid",

Go to network namespace of the pid, but keep mount namespace of the debug container

nsenter -t 2152 -n

在node上进入此容器的网络Namespace：

#nsenter -n -t 6013

运行如下命令抓包，此时会抓取对应pod的包，并保存在node的文件系统下：“

#tcpdump -i eth0 udp dst port 53 | grep xxxx

分析抓取的数据包，确实是对应POD内的抓包。
