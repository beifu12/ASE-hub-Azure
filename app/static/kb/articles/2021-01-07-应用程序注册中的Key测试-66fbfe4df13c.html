经过测试应用程序注册中的Key，可以保存任何形式的密钥字符串。

如创建时指定密钥为123456

将返回值$servicePrincipal.Secret转换为字符串查看，是我设置的密钥：

$BSTR = [System.Runtime.InteropServices.Marshal]::SecureStringToBSTR($servicePrincipal.Secret)

$pwddisplay = [System.Runtime.InteropServices.Marshal]::PtrToStringAuto($BSTR)

但上传证书到CDN中设置的key必须是44字符长度，可以使用如下方法生成随机的密钥，也可以随便写一个44字符的字符串。

$aesManaged = New-Object "System.Security.Cryptography.AesManaged"

#高级加密标准 (AES) 对称算法的管理类,提供的GenerateKey方法生成随机key。

$aesManaged.GenerateKey()

$aesManaged.Key

#将随机key转换为Base64编码数据，长度44字符。

$Password= [System.Convert]::ToBase64String($aesManaged.Key)

如下是保存过程（分别使用Azure PowerShell，Azure CLI以及Azure Active Directory PowerShell，其中AAD PowerShell可以在已有的Service Principal中添加Key）：

#Azure PowerShell

$startDate = Get-Date

$EndDate = $startDate.AddYears(2)

$aadAppName = "zhangapptest1"

#Create the 44-character key for CDN Vault

$Password = "aNqzYMkwfU3Bf+6VbF5idea8TA8D7gYPV51WI6+v4k80"

$aadAppUrl = "https://" + $aadAppName

$SecureStringPassword = ConvertTo-SecureString -String $Password -AsPlainText -Force

$servicePrincipal = New-AzureRMADServicePrincipal -DisplayName $aadAppName -Password $SecureStringPassword -EndDate $EndDate -StartDate $startDate

#Azure CLI

az ad sp create-for-rbac -n "htpp://zhangapptest2" --skip-assignment -p "01234567890123456789012345678901234567891111"

#Azure Active Directory PowerShell

Get-AzureADApplication -ObjectId "3af79988-36c8-4e4f-af47-a8796eb69f2c"

New-AzureADApplicationPasswordCredential -ObjectId "3af79988-36c8-4e4f-af47-a8796eb69f2c" -Value "ohnkXTgCqH682I8v4trXOc+a3d3W0uOUWMjbEwLxDos=" -EndDate $EndDate -StartDate $startDate
