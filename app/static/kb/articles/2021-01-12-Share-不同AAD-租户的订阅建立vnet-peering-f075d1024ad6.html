Hi all ,

当前azure CN的官网给出的说明是不同AAD 租户的订阅无法建立vnet peering

近期得到CSS 工程师的反馈可以通过powershell 方式实现不同AAD 租户订阅间创建vnet peering。 由于没有其他账号可以测试，仅分享一下CSS 工程师的反馈。如下：

Create a virtual network peering - Resource Manager, different subscriptions and Azure Active Directory tenants： Refer to the document：https://docs.microsoft.com/en-us/azure/virtual-network/create-peering-different-subscriptions#cli

If the virtual networks are in different subscriptions, and the subscriptions are associated with different Azure Active Directory tenants, complete the following steps before continuing:

Add the user from each Active Directory tenant as a guest user in the opposite Azure Active Directory tenant.

Each user must accept the guest user invitation from the opposite Azure Active Directory tenant.

Before in the Azure China, it was not supported to add the guest user to the Azure Active Directory tenant. So it was not supported to create Vnet peering between the virtual networks existing in different subscriptions that may belong to different Azure Active Directory (Azure AD) tenants.

And as test, now there is the issue to create peering through the Azure Portal, you could create peering with Powershell or Azure CLI.

Assign UserB permissions to virtual B2BVNTC .

In the Search resources box at the top of the portal, type B2BVNTC Select B2BVNTC when it appears in the search results.

Select Access control (IAM) from the vertical list of options on the left side.

Under B2BVNTC - Access control (IAM), select + Add role assignment.

Select Network contributor in the Role box.

In the Select box, select UserB, or type UserB's email address to search for it.

Select Save.

Or through the Azure CLI.

az role assignment create \

--assignee UserB@azure.com \

--role "Network Contributor" \

--scope /subscriptions/<SubscriptionA-Id>/resourceGroups/myResourceGroupA/providers/Microsoft.Network/VirtualNetworks/myVnetA

Open a CLI session and log in to Azure as UserA using the “az cloud set -n AzureChinaCloud”and “az login” command. The account you log in with must have the necessary permissions to create a virtual network peering.
