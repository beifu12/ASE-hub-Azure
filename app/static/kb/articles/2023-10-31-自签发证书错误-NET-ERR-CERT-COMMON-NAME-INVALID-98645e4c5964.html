https://docs.azure.cn/en-us/application-gateway/self-signed-certificates

如下是完整的命令：

Create the root key:

openssl ecparam -out jiaroot.key -name prime256v1 -genkey

Certificate Signing Request (CSR)

openssl req -new -sha256 -key jiaroot.key -out jiaroot.csr

Generate Root Certificate

openssl x509 -req -sha256 -days 365 -in jiaroot.csr -signkey jiaroot.key -out jiaroot.crt

=====

Create client certificate's key

openssl ecparam -out jiacert.key -name prime256v1 -genkey

Generate client CSR

openssl req -new -sha256 -key jiacert.key -out jiacert.csr

Generate client certificate

openssl x509 -req -in jiacert.csr -CA jiaroot.crt -CAkey jiaroot.key -CAcreateserial -out jiacert.crt -days 365 -sha256

Generate PFX certificate

openssl pkcs12 -export -out jiapfx.pfx -inkey jiacert.key -in jiacert.crt

有些浏览器会给出更详细报错信息，能够看到报错中有关键字“Subject Alternative Names”，意思是这个证书中没有指定这个字段。

现在的浏览器都加强了这个安全措施，Chrome自从版本58，以及原生Edge，都要求证书必须含有这个字段。但是上述文档生成的证书是没有这个字段的。而且根据测试，AppGW也是会报CN不匹配的错误：

什么是SAN（Subject Alternative Name）？

这个字段中罗列了该证书保护的域名和IP。也就是证书能够保护除了本身的CN以外，还能保护这个字段里罗列的域名和IP。例如Baidu证书：

解决方案：

新建一个文件ext.ini，写入以下内容：

basicConstraints = CA:FALSE

keyUsage = nonRepudiation, digitalSignature, keyEncipherment

subjectAltName = @alt_names

[alt_names]

DNS.1 = *.north2vmweb.com

DNS.2 = www .north2vmweb.com

其中的DNS.1 DNS.2 ……是需要修改的部分，这里面填写SAN的域名或IP。可以是多个，按照DNS.3 DNS.4……扩展。

然后在颁发证书时加载这个配置文件即可。如下标黄部分：

Root Certificate

openssl x509 -req -in jiacert.csr -CA jiaroot.crt -CAkey jiaroot.key -CAcreateserial -out jiacert.crt -days 365 -sha256 -extfile /home/jia/ext.ini
