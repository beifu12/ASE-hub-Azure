原始内容清洗稿（保留备查）

#创建相应的资源组以存放新的公共IP，如公共IP已准备好，可以忽略此步：

az group create --name tianPublicIPs --location chinanorth2

az network public-ip create --resource-group tianPublicIPs --name aksLBPIP01 --sku standard --allocation-method static

az network public-ip show --resource-group tianPublicIPs --name aksLBPIP01 --query ipAddress --output tsv

PIP_RESOURCE_GROUP=tianPublicIPs

AKS_RESOURCE_GROUP=aks-test-rg

AKS_CLUSTER_NAME=tian-aks01

#获取系统给AKS集群指定的managed identity，默认在创建AKS Cluster时就会自动生成一个类型为system #assign的managed identity

#如果以下指令输出是msi，则说明AKS集群使用的是managed identity作为身份标识来访问AKS集群外部的资源。

az aks show --resource-group $AKS_RESOURCE_GROUP --name $AKS_CLUSTER_NAME --query "servicePrincipalProfile.clientId" --output tsv

#则继续使用如下指令找到控制层面系统指定的object ID，由Service Principal id来表示Client ID。

az aks show --resource-group $AKS_RESOURCE_GROUP --name $AKS_CLUSTER_NAME --query "identity"

{

"principalId": "971c5de1-88aa-4635-b297-103d7056f13b", #这一项即为object-id

"tenantId": "b388b808-0ec9-4a09-a414-a7cbbd8b7e9b",

"type": "SystemAssigned",

"userAssignedIdentities": null

}

CLIENT_ID=$(az aks show --resource-group $AKS_RESOURCE_GROUP --name $AKS_CLUSTER_NAME --query "identity.principalId" --output tsv)

SUB_ID=$(az account show --query "id" --output tsv)

#为AKS集群授权其可以操作公共ip所在的资源组，通过指令或者Portal都可以完成这一步。

az role assignment create --role "Network Contributor" --assignee $CLIENT_ID --scope /subscriptions/$SUB_ID/resourceGroups/$PIP_RESOURCE_GROUP

#授权成功之后，通过Portal可以查看Public IP所在的资源组中相应的AKS Cluster已经有了network contributor的权限：

#如果将公共ip资源创建在MC_<aks-resource-group-region>这个资源组中，则上述的授权操作可以不在进行。

#

#使用如下YAML文件部署Service

apiVersion: v1

kind: Service

metadata:

annotations:

service.beta.kubernetes.io/azure-load-balancer-resource-group: tianPublicIPs #此处的资源组为公共ip所在的资源组名称

name: tian-lb

spec:

loadBalancerIP: 52.130.146.0

type: LoadBalancer

ports:

  • port: 80

selector:

app: tian-lb

Obtain and use the system-assigned managed identity for your AKS cluster

Confirm your AKS cluster is using managed identity with the following CLI command:

Azure CLICopy

Try It

az aks show -g<RGName>-n<ClusterName>--query"servicePrincipalProfile"

If the cluster is using managed identities, you will see a clientId value of "msi". A cluster using a Service Principal instead will instead show the object ID. For example:

OutputCopy

"clientId": "msi"

After verifying the cluster is using managed identities, you can find the control plane system-assigned identity's object ID with the following command:

az aks show -g<RGName>-n<ClusterName>--query"identity"

"principalId": "<object-id>",

"tenantId": "<tenant-id>",

},

Note

For creating and using your own VNet, static IP address, or attached Azure disk where the resources are outside of the worker node resource group, use the PrincipalID of the cluster System Assigned Managed Identity to perform a role assignment. For more information on role assignment, see Delegate access to other Azure resources.
