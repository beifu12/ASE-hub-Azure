截止2021.11.2 中国区Azure Private Endpoint所连接的Vnet/Subnet仍然不支持通过NSG规则来实现对Private Endpoint的访问控制。之前有过几个工单用户咨询Private Endpoint能否通过NSG实现更精细的访问控制。比如：

用户给Azure MySQL Paas配置了Private Endpoint，这时用户Virtual Network里，如果用户想禁止某些虚拟机去访问Private Endpoint Network Interface私网ip及相应端口，他可以在Private Endpoint所属Subnet中配置相应的NSG规则，但是这一规则对于这个Private Endpoint并不会生效，仍然是只要能够跟Private Endpoint专用ip路由通的，都可以直接访问它。

之前微软官网文档（https://docs.microsoft.com/zh-cn/azure/private-link/private-endpoint-overview#limitations）上明确有写明：开启Private endpoint后会禁用网络策略，NSG规则不对它生效，但对同Subnet的其它节点仍然有效。不能在Private Endpoint侧的NSG上实现更精细的控制，只能从访问源那一侧的NSG上进行限制或者使用其它方式。但这样对于源头多的网络环境配置起来不方便，之前有用户有抱怨和质疑。现在官网文档上已经去掉了这些说明，因为在Public Azure上已经可以启用Private Endpoint支持NSG功能了。

关于这一新功能，官网上的说明如下：

对于Public Azure，NSG作用于Private Link处于preview阶段：Public preview of Private Link Network Security Group Support | Azure updates | Microsoft Azure

Public preview of Private Link Network Security Group Support

Published date: September 02, 2021

Private Endpoint support for Network Security Groups (NSGs) is now in public preview. This feature enhancement will provide you with the ability to enable advanced security controls on traffic destined to a private endpoint. In order to leverage this feature, you will need to set a specific subnet level property, called PrivateEndpointNetworkPolicies, to Enabled. In addition to toggling this property, you will need to also register for the Microsoft.Network/AllowPrivateEndpointNSG feature (note that registation time may take up to 15mins).

At this time, Private Link NSG Support is available in the following regions:

UsEast2Euap, UsCentralEuap, WestCentralUS, WestUS, WestUS2, EastUS, EastUS2, Asiaeast, Australiaeast, Japaneast, Canadacentral, Europenorth, Koreacentral, Brazilsouth, Uksouth, US South, US North, France Central
