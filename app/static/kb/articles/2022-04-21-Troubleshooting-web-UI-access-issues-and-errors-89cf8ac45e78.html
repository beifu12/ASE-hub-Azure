  • To confirm network issue, have the customer try to ping the device’s MGMT IP address 192.168.100.10 from a computer within the same network using a command prompt and assigning to the computer IP 192.168.100.5
  • If the customer is still unable to access the local WebUI of the device after attempting to ping the device, make sure none of the Data Box IP addresses are duplicate IPs on the customer’s network. Also can try accessing Webui by using one of the other ports IP.

As this issue could occur for a number of reasons, it is necessary to check the following items:

Data Box Hardware

Data Box Network Connectivity and Setup

Contact the customer and gather as much information as you can about the issue, error message, screenshots, etc.

Double-check to make sure the device has been properly cabled.

Confirm the System Fault LED on the back of the device is lit or not.

Confirm if the device is powering on. If not:

Power outlet not working, try a different power outlet.

Power cable is damaged and need to be replaced.

Power supply defective, test each one

Try disconnecting all cables for at least 15 mins to fully drain power. Reconnect power cable on the device and on the outlet.

If Webui is accessible check for alerts/warnings, run diagnostics and collect support package.

To confirm network issue, have the customer try to ping the device’s MGMT IP address 192.168.100.10 from a computer within the same network using a command prompt and assigning to the computer IP 192.168.100.5

If the ping is unsuccessful, have the customer try to ping other servers on the same network

If the ping is successful, have the customer to make sure they are using HTTPS to connect to the Data Box local WebUI, and that they are using the IP address to connect instead of a hostname (e.g., https://192.168.100.10).

If the customer is still unable to access the local WebUI of the device after attempting to ping the device, make sure none of the Data Box IP addresses are duplicate IPs on the customer’s network. Also can try accessing Webui by using one of the other ports IP.

Perform a cold reboot and try again.

Check if customer is able to connect by using Power shell and collect logs by CLI.

If none of this work engage TA's or raise ICM
