Hi all，

分享一个网络工单：SR_20210915121544_[S500]生产环境AKS集群节点访问外部地址响应慢

===问题描述：

AKS 集群有6个节点中其中一个节点curl域名api.weixin.qq.com偶发性响应慢，其中api.weixin.qq.com解析可以得到两个IP地址（101.226.212.27, 180.97.7.108）响应慢的问题仅出现在180.97.7.108，访问其他域名如www.baidu.com等没有问题。

===排查小结：

1.        AKS 集群使用basic SKU 负载均衡器的公网IP（52.131.244.251）进行出站公网访问，此时将为每个节点分配1024个SANT端口供集群的出站公网访问（从端口号1024开始分配）。更多关于LB出站SNAT的说明可参考：用于出站连接的源网络地址转换 (SNAT) - Azure Load Balancer | Azure Docs

2.        后台查看节点aks-agentpool-82483739-1分配的出站SNAT端口范围是1024-2048。根据我们之前工单中的经验以及进一步的验证测试，访问IP 180.97.7.108时存在公网ISP对某些IP地址的低位端口封堵的情况，经测试具体被封堵的端口为：1025，1068以及1418，测试访问101.226.212.27时不存在这个情况。

访问180.97.7.108：

访问101.226.212.27，对应端口无超时现象：

====下一步方案：

对于Basic SKU LB 的AKS集群的，该端口是不可自定义配置的，因此无法为虚机指定端口的分配。而该低位端口的封堵行为是公网链路的ISP所实施的，Azure无法去控制该行为。

可以参考的mitigate该问题的方案：

1.        由于API域名解析出的两个IP地址中，仅一个存在低位端口封堵的情况，可以使用目前写定host的方式，虚拟机访问该域名时仅访问101.226.212.27这个IP地址，但是风险在与对方API的IP地址不一定永久固定，因此若出现对方IP地址更换的情况，会导致该节点无法访问该API；

2.        使用NVA的方案。将AKS 集群针对该IP地址的访问强制路由给一台带实例公网IP地址的NVA虚拟机，并由NVA的实例级别公网IP发送出去。（需要在网卡上开启IP forwarding）

备注：具有实例级公网IP地址的虚拟机在进行出站访问时，会使用该实例公网IP，并首先选用高位端口进行出站，此时不存在端口的SNAT行为。

3.        在应用上使用重试的机制，在超过设定的超时阈值后，重新发起请求。
