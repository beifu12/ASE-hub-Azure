Dears

今天接了一个S2S VPN 频繁中断的工单，每次中断时间5s左右。根据以往经验来说，频繁中断一般是感兴趣流或者sa lifetime的问题，可以直接找客户检查参数配置。

不过除了经验之外，也分享一下排查过程，大家可以参考一下。

控制层面的问题，一般只需在 VPN GW抓包就够了，先看了一下wfpdiag.txt的报错，第二阶段失败

Failure type: IKE/Authip Quick Mode Failure

Type specific info:

Failure error code:0x0000363e

Main mode SA assumed to be invalid because peer stopped responding.

再看数据包，Azure VPN GW和本地设备之间第一阶段没问题，第二阶段明显不是正常的交换过程（一对儿感兴趣流对应三个报文）

详细看第二阶段的报文，本地VPN GW返回的包中，只响应了Message ID=2的协商请求，并完成了三次交换

Message ID=1的报文一直在重传，所以日志里的报错虽然不是很准确，但是也是有点依据的

(两个VPN GW之间可以通过一个第一阶段的sa协商多个第二阶段的sa，通过Message ID来标识不同的感兴趣流)

以上，Message ID=2的感兴趣流可以协商成功，说明加密算法，哈希算法等各种算法没问题

由于第二阶段的报文都是加密的，没办法看出具体内容，但可以在日志中找到两个Message ID对应的感兴趣流，最后定位是172.30.0.0/16的感兴趣流有问题（这一步也可以通过Jarvis查本地网络网关的配置，但是就是没办法和Message ID对应上找到具体是哪个地址段）
