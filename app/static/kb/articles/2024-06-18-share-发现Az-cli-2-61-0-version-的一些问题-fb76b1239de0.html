最近接了几个关于az cli 的问题, 经过排查和测试发现问题的原因都是由于升级了az cli到最新的2.61.0 版本的问题, 分享一下我这边的测试和发现 :

=> 遇到的案例

====================================

案例 1: SR_20240610297948_China Azure CLI Issue

客户问题描述: Azure CLI is not available on Azure Portal. I installed Azure CLI on Windows 11 desktop. I tried to run az login command but it not moving further and stuck on same screen. I want to know whether azure CLI work on azure china cloud or not. If yes the how I can use this.

案例 2 : SR_20240613298597 _ Azure CLI无法连接到Azure China portal

笔记本上的Azure CLI无法连接到Azure China portal

=> 分析测试

===========================

Az cli 升级到最新的2.61.0版本, 从 Azure CLI 版本 2.61.0 开始，Azure CLI 在 Windows 上使用 Web 帐户管理器（WAM），默认情况下在 Linux 和 macOS 上使用基于浏览器的登录名

If we upgrade the az cli version to 2.61.0 , the most different is Beginning with Azure CLI version 2.61.0, Web Account Manager (WAM) is now the default authentication method on Windows.

We have test az login and also find the error bellowing:

由于在windows上使用 Web 帐户管理器（WAM）的认证方式, 部分客户会出现以下两种报错情况.

1, 输入az cloud set -n AzureChinaCloud 之后 az login 会出现以下报错: 直接出现报错不会弹出选择账号的窗口.

报错截图:

报错截图文本:

ERROR: User cancelled the Accounts Control Operation.. Status: Response_Status.Status_UserCanceled, Error code: 0, Tag: 528315210

2, 可以弹出选择账号的窗口, 但是没有需要选择的账户, 只有选择2个跳转到global验证的账号页面

如选择并输入账号之后会跳转到global验证并报错 ：

AADSTS51004 : The user account XXXX does not exits in the XXXX directory.

3, 可以弹出选择账号的页面，但是点击账号之后，会长时间没有反应, 无法弹出下一步的窗口，关闭powershell在重新打开依然如此，重启机器后也无法缓解.

=> 解决方案

===============================

出现以上报错情况, 根据文档描述可以还原到以前的基于浏览器的身份验证方法 ：

经测试，还原为基于浏览器的身份验证方法之后客户可以正常登录

You can following the solution mentioned in the bellowing to try :

If you encounter any issue and want to revert to the previous browser-based authentication method, run the following script:

az account clear

az config set core.enable_broker_on_windows=false

az login
