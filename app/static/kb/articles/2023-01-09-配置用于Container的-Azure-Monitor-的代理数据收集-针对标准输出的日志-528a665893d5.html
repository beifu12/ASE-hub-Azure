20200604

Azure Monitor 支持对AKS群集的监视，其中监视容器非常重要，特别是针对运行大规模包含多个应用程序的群集时。默认情况下除了可以收集内存及处理器等指标，容器日志也会被收集。

客户需求：Container log数据量庞大，考虑成本控制，需要设置/修改Log A Workspace上container log的收集设置

解决方案：如果需要调整container log的收集设置，请参考以下步骤：

检查 Log Entry Source:

ContainerLog

| summarize count() by LogEntrySource

下载ConfigMap yaml模板文件，以container-azm-ms-agentconfig.yaml名称保存

参考这个文档修改日志收集器设置并保存

[log_collection_settings]

[log_collection_settings.stdout]

In the absense of this configmap, default value for enabled is true

enabled = true //选择true，默认会应用到所有群集节点/pod，除非在exclude中指定namespace

exclude_namespaces setting holds good only if enabled is set to true

kube-system log collection is disabled by default in the absence of 'log_collection_settings.stdout' setting. If you want to enable kube-system, remove it from the following setting.

If you want to continue to disable kube-system log collection keep this namespace in the following setting and add any other namespace you want to disable log collection to the array.

In the absense of this configmap, default value for exclude_namespaces = ["kube-system"]

exclude_namespaces = ["kube-system"]

[log_collection_settings.stderr]

Default value for enabled is true

kube-system log collection is disabled by default in the absence of 'log_collection_settings.stderr' setting. If you want to enable kube-system, remove it from the following setting.

In the absense of this cofigmap, default value for exclude_namespaces = ["kube-system"]

将以上 container-azm-ms-agentconfig.yaml发送到api server进行部署

kubectl apply -f container-azm-ms-agentconfig.yaml

在配置生效之前需要花费几分钟时间进行配置更改，期间所有AKS群集上的omsagent pods将会被重启，此重启是滚动的，不会在同一时间点全部重启。

Note：

从Container工作流中收集stdout、stderr以及环境变量所支持的最低代理版本为ciprod06142019；

Container log的源是stdout和stderr，通过ConfigMap配置文件我们可以禁用这些源将日志传递到Azure Log Analytics中；

禁用的具体影响：用户将不会在Log页面查询到Container log，如果服务出现异常，用户也不可以从Log页面及时查询Container log来获取相关日志信息；
