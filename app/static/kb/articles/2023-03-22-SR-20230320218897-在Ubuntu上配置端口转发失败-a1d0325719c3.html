问题描述：

=======

在Ubuntu上配置端口转发没有生效。

系统环境/应用程序信息：

===============

Azure Ubuntu VM Network

问题原因：

========

借助iptables DNAT实现端口转发，测试端口连通性，如果是在本机上直接测试，数据包不会经NAT表的PREROUTING链处理，而本机又没有监听相应的端口，所以在其上telnet始终会显示refused.

解决方案*：

==============

借助iptables配置端口转发的步骤：

Azure VM Portal中找到充当转发器角色的NIC，并在ip configurations中启用“ip forwarding”功能。

Azure Ubuntu VM中启用内核级别的ip forwarding功能。

Azure Ubuntu VM中配置如下iptables规则;

iptables -t nat -A PREROUTING -d 10.2.0.5 -p tcp -m tcp --dport 30000 -j DNAT --to-destination 10.3.0.4:80

iptables -t nat -A POSTROUTING -d 10.3.0.4 -o eth0 -j MASQUERADE

iptables -A FORWARD -i eth0 -j ACCEPT  #这条为可选项，确保filter表中Forward链不会阻拦流量就行；如果确认上面那两条配置后仍不通就配置这条。

Azure Ubuntu VM中禁用UFW，避免有额外的拦截。

要实现在端口转发器自身telnet 其自身30000端口也能将数据包转发给目标IP及对应端口：

可以在NAT表的OUTPUT链中增加如下DNAT规则，这样当数据包源IP为本机自身IP时也能进行DNAT转换，从而本机不用监听telnet的那个端口：

iptables -t nat -A OUTPUT -p tcp -d 10.2.0.5 --dport 30000 -j DNAT --to-destination 10.3.0.4:80
