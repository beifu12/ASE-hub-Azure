2024/9/27

问题描述：

用户的Windows 2012 datacenter 虚拟机之前一直备份正常，在8月21日之后出现了备份失败的情况，报错提示如下：

ExtensionfailedRetryableErroraccessdenied

Snapshot operation failed as the windows guest agent encountered the access denied error

Please ensure that windows guest agent is running under "local system" service account and the account is part of Administrator group on the Virtual Machine

排查过程：

===========

1， 首先根据报错提醒可以看出是因为Windows Guest Agent（也称为VM Agent）没有足够的权限来执行必要的操作导致的报错。 于是建议用户排查服务及权限问题：

确认Windows Guest Agent运行状态：

登录到你的Windows虚拟机。

打开“服务”（可以通过搜索“services.msc”来找到）。

在服务列表中，查找“Windows Azure Guest Agent”

确认该服务正在运行，并且设置为“自动”启动。

检查服务账户：

右键点击“Windows Azure Guest Agent”服务，选择“属性”。

在“登录”标签页中，确认服务是否设置为以“本地系统账户”运行。

如果不是，请更改为“本地系统账户”，并确保“允许服务与桌面交互”的选项未被勾选（这通常不推荐用于服务）。

确认账户权限：

打开“计算机管理”（可以通过搜索“computer management”来找到）。

在“本地用户和组”下，点击“组”。

找到“Administrators”组，双击打开它。

确认“本地系统”账户（通常显示为NT AUTHORITY\SYSTEM）是否在该组中。虽然“本地系统”账户默认拥有管理员权限，但在某些特殊配置或策略下可能会被移除。

检查防火墙和安全软件设置：

确保没有防火墙或安全软件阻止Windows Guest Agent或相关服务进行网络通信。

检查是否有任何策略或规则限制了“本地系统”账户访问网络资源或执行某些操作。

重启虚拟机：

在进行上述更改后，重启虚拟机以确保所有设置生效。

2， 用户查询了以上信息后发现该虚拟机的Windows Guest Agent服务运行及账户权限等都是正确配置的。

3， 进一步查询event viewer 中的application log，并对比正常备份的同OS 的虚拟机，发现在21号之后问题虚拟机上一直出现COM+相关的报错提醒：

Removal of an assemble from the global assembly cache failed: C:\Packages\Plugins\Microsoft.Azure.RecoveryServices.VMSnapshot\1.0.92.0\iaasvmazurestorage.dlliaasvmazurestorage,version=3.0.0.0

根据排查 Azure VM 备份错误 - Azure Backup | Azure Docs 提供的排查COM+报错的方法，让用户重启了com+system application的服务

再次执行备份可以正常完成备份作业：

结合Kusto 语句查询备份情况：

BCMBackupStats

| where SubscriptionId == "c635f031-e433-43ce-b9ac-f695348db769"

| where PreciseTimeStamp > datetime(2024-09-25 00:00:00.000)

| where PreciseTimeStamp < datetime(2024-09-27 10:00:00.000)

//|project PreciseTimeStamp ,ContainerName ,  BackupPolicyId , StartTime  ,TaskId, RecoveryPointId ,JobStatus , ErrorCode , SizeOfVm , CloudServiceName

|project PreciseTimeStamp ,ContainerName ,JobStatus , ErrorCode , SizeOfVm , CloudServiceName

|where ContainerName contains "CAFLESWeb01"
