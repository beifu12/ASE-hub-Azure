排查思路

  • 对于Pending在portal的操作，Engineering team每天都会清理一遍（在工作时间内），因此最多不会超过24个小时。
  • CDN dashboard中的Log query查询日志的延迟在20个小时以上，严重影响需要依赖于访问日志排查的问题。
  • 访问控制功能一年多前从v1升级到了v2版本，会导致有的较早的域名无法加载访问控制界面或者显示旧的v1配置，导致无法更改配置。如果客户需要在portal更新访问控制规则，需要找PG手动升级至v2（v1版本的访问控制规则比v2规则的精细度更高，有的规则v2已经不支持了）。
  • 可以在CDN Dashboard中查看域名的CDN启用是否正常
  • 可以尝试更改CDN供应商来验证问题是否为当前CDN供应商的问题。在CDN的dashboard中找到secondary供应商为加速域名配置的CNAME，解析出该CNAME的IP地址，修改host文件，将加速域名指向该IP地址。
  • 图片处理加速不支持Https回源。如果遇到客户创建、更新图片加速配置失败，或者图片加速域名回源失败时（可能返回400），需要特别留意“回源协议”的配置，确认其设置为“http”。
  • 对于客户上传的Https证书（手动上传或者通过KV上传），平台会验证证书中的CDP （Crl Distribution Point）的内容是否为空。如果是的话，那么校验会失败，即使该证书启用了OCSP验证。
  • 图片处理加速在回源时会删除客户端请求中的查询字符串（query string），因此如果源站是Blob，必须允许公开访问。不支持SAS Token访问的方式，因为这种方式就是通过在URL后追加查询字符串来进行鉴权的。
  • will update the doc to explain that multiple origin will be needed to set in CDN portal.

解决方案

  • 默认规则会一直起作用，客户如果不需要缓存某个文件，需要显式定义规则并将TTL设置为0
  • 与供应商有关，不同供应商默认缓存的文件后缀不一样。客户如果明确不需要缓存特定的文件，需要显示定义缓存规则并将TTL设置为0来禁用。
  • 在Portal上无法修改图片处理加速的源站IP地址，只能修改为域名；但通过REST API可以将源站修改为IP地址。
  • This is confirmed to be a CDN bug. Current workaround is to use REST API to modify the origin IP.
  • Workaround: 使用basic=exif参数查看EXIF中的Orientation信息，根据客户具体的情况去使用basic={Degree}r进行修正。
  • provide workaround, fix priority depends on case volume
  • 使用目录刷新时，如果源站文件的last modify值没有变化，那么意味着CDN节点不会到源站重新取数据，这种情况下只能使用文件刷新。使用文件刷新时，必须指定具体的文件名称，否则无法刷新。如果客户需要刷新多个文件时，可以通过API进行。
  • 与供应商的配置有关。建议在目录刷新无法解决问题的情况下，尝试使用文件刷新再试一遍
  • 可以使用F12来查看哪些文件命中了缓存，这个对排查性能问题也很有帮助。客户的网页上可能存在很多不同类型的文件，客户抱怨启用CDN之后没有什么加速效果，可以通过F12查看哪些文件命中了缓存，并用这些文件的加载时间来与源站进行对比。对于没有命中缓存的文件，CDN节点需要回源再将结果返回客户端，可能需要花费更长的时间。
  • 如果是更新证书，建议在域名管理界面绑定（防止回源跟随更改了之前的配置）
  • 用户只有开启Https加速之后，才能从门户选择回源协议（协议跟随，https或者http）。对于没有开启Https的加速域名，实际也是可以配置Https回源的（前端为Http，回源为Https）。如果客户有此需求，可以通过非标操作的流程向PM申请。
  • PG will look for on better solution.
  • 在使用图片加速时，对于一个domain name的请求，如果cache MISS而回源，请求数量将有限制，默认限制为60 requests per 5s，当超限时访问会提示throttled。如有需要可以找PG修改默认限制。

对于客户上传的Https证书（手动上传或者通过KV上传），平台会验证证书中的CDP （Crl Distribution Point）的内容是否为空。如果是的话，那么校验会失败，即使该证书启用了OCSP验证。

此设计已经更改。

用户只有开启Https加速之后，才能从门户选择回源协议（协议跟随，https或者http）。对于没有开启Https的加速域名，实际也是可以配置Https回源的（前端为Http，回源为Https）。如果客户有此需求，可以通过非标操作的流程向PM申请。

CDN默认的回源超时时间为10秒。对于通过CDN上传文件的场景，如果文件不能在10秒之内传完，那么客户端会看到上传失败，返回504的报错。可以联系PG调整这个超时时间，最高配置为1分钟。

CDN可以从后台开启或者关闭Range回源。Range是Http协议中规定的一种请求方式：https://developer.mozilla.org/en-US/docs/Web/HTTP/Range_requests

图片处理加速在回源时会删除客户端请求中的查询字符串（query string），因此如果源站是Blob，必须允许公开访问。不支持SAS Token访问的方式，因为这种方式就是通过在URL后追加查询字符串来进行鉴权的。

创建CDN时，provider会校验客户的域名是否有备案，但是并不会对客户提供的ICP信息进行。如果目前有客户需要更改ICP备案信息的请求，可以直接上IcM请PG处理。(DO NOT deliver this info. to cx.)
