一句话摘要

如果在网络设置中选择Allow public access from all networks则CDN访问Keyvault正常，报错消失

问题现象 / 场景

  • 如果在网络设置中选择Allow public access from all networks则CDN访问Keyvault正常，报错消失
  • 对于Azure China来说，无法实现允许部分网络访问Keyvault来配置CDN与Keyvault的集成

背景信息

  • 2024.8.26
  • 问题描述
  • 查阅文档发现
  • 对于Azure Global来说CDN在KeyVault的受信任微软服务列表中Azure Key Vault 的虚拟网络服务终结点 | Microsoft Learn，所以客户可以在Keyvault防火墙中配置允许部分网络访问Keyvault。
  • 然而172.18.0.121的这类内网地址不支持加入到Keyvault防火墙白名单中
  • 问题原因
  • Azure China中CDN不在Keyvault信任的微软服务列表中，且源地址不支持加入到防火墙白名单中
  • 对于Azure China来说，要正常配置CDN与Keyvault集成，必须在Keyvault网络设置中允许所有网络公共访问

排查思路

  • 配置CDN与KeyVault集成时提示权限问题无法访问密钥保管库，但已经检查过Keyvault中授予CDN应用程序的权限没有问题
  • 排查步骤
  • 经过确认客户Keyvault网络设置中配置了Allow public access from specific virtual networks and IP addresses并且勾选了Allow trusted Microsoft services to bypass this firewall的选项
  • 为Keyvault开启诊断设置，检查Keyvault的访问日志，发现此次访问的CDN节点源IP地址是172.18.0.121，因不在Keyvault防火墙的放行名单被拦截

问题描述

排查步骤

经过确认客户Keyvault网络设置中配置了Allow public access from specific virtual networks and IP addresses并且勾选了Allow trusted Microsoft services to bypass this firewall的选项

如果在网络设置中选择Allow public access from all networks则CDN访问Keyvault正常，报错消失

查阅文档发现

对于Azure Global来说CDN在KeyVault的受信任微软服务列表中Azure Key Vault 的虚拟网络服务终结点 | Microsoft Learn，所以客户可以在Keyvault防火墙中配置允许部分网络访问Keyvault。

然而Azure China CDN并不在Keyvault受信任的微软服务列表中Azure Key Vault 的虚拟网络服务终结点 | Azure Docs，故考虑是否能通过将CDN节点IP或网段加入到Keyvault防火墙白名单以修复此问题

为Keyvault开启诊断设置，检查Keyvault的访问日志，发现此次访问的CDN节点源IP地址是172.18.0.121，因不在Keyvault防火墙的放行名单被拦截

然而172.18.0.121的这类内网地址不支持加入到Keyvault防火墙白名单中

问题原因

Azure China中CDN不在Keyvault信任的微软服务列表中，且源地址不支持加入到防火墙白名单中
