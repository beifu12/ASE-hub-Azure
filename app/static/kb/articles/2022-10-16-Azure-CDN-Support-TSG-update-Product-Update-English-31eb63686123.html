原始内容清洗稿（保留备查）

The latest CDN product updates and problem handling Tips are as follows. Please take note.

1) Origin Path Support in Mooncake CDN

When configuring the CDN in Global, you can specify a path of the source station as Origin Path. In this way, the custom domain name corresponds to a path to the actual source domain name, not the entire site. As shown above, when visiting http://qlitest.azureedge.net/abc.jpg you actually visit the source station at http://test.com.cn/pictures/abc.jpg.

However, in some scenarios, users may wish to use this feature. Especially for users who have experience with Global CDNs, such as configuring CDNs for Azure Blob, they may wish to use a container of blob as the source path of the source. Currently, Mooncake CDN does not support user self-service configuration. Please help collect user requirements and contact the product group for offline configuration.

Information to be provided:

Custom domain name:

ICP number:

Acceleration type:

Source station domain name or IP:

Back to the source Host Header:

Origin Path:

Return source agreement:

2) CDN REST API documentation update

1. Reference to the CDN ARM REST API documentation released by Global does not apply to Mooncake. The document group has been contacted for revocation.

2. The current ASM REST API is tested and available. However, if the customer does not have a CDN endpoint, they cannot access the CDN management portal to obtain the Key ID and Key Value of the API call authorization. In this case, there are two options:

· It is recommended that the customer first create a CDN through the Portal, then go to the CDN management portal to obtain the Key ID and Key Value of the API call authorization, and then perform other operations through the REST API.

· Contact the CDN product group to get the Key ID and Key Value of the relevant subscription, and then create a CDN.

3) CDN Profile in new regions - low priority

At present, customers cannot select China East2 and China North2 when creating CDN profiles. However, if you select a resource group in both areas, you will still encounter problems that result in unavailability.

As shown in the figure above, the area where the CDN Profile is located does not affect the actual CDN service. If the customer does not have strict requirements on the geographical area, it is recommended to use the resource group in China North and China East. At the same time, we also understand that customers may need to create resources in China North2 and China East2 based on reasons such as Policy. The development team is working on the issue and it will take some time. Please excuse us for the time being.

4) Ibiza Portal adds check function to Host header

In a recent product update, Ibiza Portal was added to verify the input Origin Host Header. If the user enters the IP, after clicking Add, an error will be received within one minute: the creation fails.

At present, the user has not been able to judge the cause of the error by giving an error message. The product group is further optimizing this feature to make the error message display information as intuitive as possible to the customer. During this time, technical support can use the Jarvis query below to determine if it is a bug of this type.
