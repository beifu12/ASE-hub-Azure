一句话摘要

AUM将这一批虚拟机统一在同一维护时段重启时，由于可用性集功能的故障域机制，有部分虚拟机无法完成重启。

问题现象 / 场景

  • AUM将这一批虚拟机统一在同一维护时段重启时，由于可用性集功能的故障域机制，有部分虚拟机无法完成重启。

背景信息

  • 问题说明：
  • ========
  • 如上图，客户的一批虚拟机部署在可用性集中，这一批虚拟机属于同一个AUM自动更新的维护范围。
  • 客户需求：
  • 客户提供了2个订阅，需要在AUM更新维护窗口期间，将2个订阅中的虚拟机排除在所在可用性集合的约束以外，所有虚拟机在自动更新维护窗口中可以忽略可用性集合的约束，全部进行重启。
  • 申请流程：
  • 此需求开通了ICM：Incident-713224896 Details - IcM
  • 在ICM中PG提供了Bypass Availability Set patching的申请方法：
  • Bypass Availability Set patching
  • Currently we patch Azure Virtual Machines in availability first manner in case of Schedule Patching. Machines are patched UD by UD. Because of this, all the machines might not get patched in the schedule. In this TSG, if customers want to bypass this constraint (patch all machines parallelly), we need to follow these steps -
  • Get all the virtual machines subscriptions from the customer.
  • Send an email to assing@microsoft.com, aumeng@microsoft.com for registering "Microsoft.Compute/VMInGuestPatchIgnoreAvailabilitySetConstraint" feature flag with cloud environment of subscription (Public/Fairfax/Mooncake).
  • Once feature flag is registered, ask customer to follow below steps -
  • Add IgnoreAvailabilitySetConstraint text as part of exclusion list as part of maintenance configuration as per below screenshot -
  • Save this schedule. It will patch all the machine parallelly in the availability set.
  • 为aumeng@microsoft.com 团队发送申请，为客户订阅启用Microsoft.Compute/VMInGuestPatchIgnoreAvailabilitySetConstraint功能
  • 启用完成后，客户需要在下一次AUM更新维护配置中添加:IgnoreAvailabilitySetConstraint

排查思路

  • 经客户验证，在维护配置中添加配置后，虚拟机已忽略了可用性集的约束，可以进行统一重启。

问题说明：

========

如上图，客户的一批虚拟机部署在可用性集中，这一批虚拟机属于同一个AUM自动更新的维护范围。

AUM将这一批虚拟机统一在同一维护时段重启时，由于可用性集功能的故障域机制，有部分虚拟机无法完成重启。

客户需求：

客户提供了2个订阅，需要在AUM更新维护窗口期间，将2个订阅中的虚拟机排除在所在可用性集合的约束以外，所有虚拟机在自动更新维护窗口中可以忽略可用性集合的约束，全部进行重启。

申请流程：

此需求开通了ICM：Incident-713224896 Details - IcM

在ICM中PG提供了Bypass Availability Set patching的申请方法：

Bypass Availability Set patching

Currently we patch Azure Virtual Machines in availability first manner in case of Schedule Patching. Machines are patched UD by UD. Because of this, all the machines might not get patched in the schedule. In this TSG, if customers want to bypass this constraint (patch all machines parallelly), we need to follow these steps -

Get all the virtual machines subscriptions from the customer.

Send an email to assing@microsoft.com, aumeng@microsoft.com for registering "Microsoft.Compute/VMInGuestPatchIgnoreAvailabilitySetConstraint" feature flag with cloud environment of subscription (Public/Fairfax/Mooncake).

Once feature flag is registered, ask customer to follow below steps -

Add IgnoreAvailabilitySetConstraint text as part of exclusion list as part of maintenance configuration as per below screenshot -

Save this schedule. It will patch all the machine parallelly in the availability set.

为aumeng@microsoft.com 团队发送申请，为客户订阅启用Microsoft.Compute/VMInGuestPatchIgnoreAvailabilitySetConstraint功能

启用完成后，客户需要在下一次AUM更新维护配置中添加:IgnoreAvailabilitySetConstraint

经客户验证，在维护配置中添加配置后，虚拟机已忽略了可用性集的约束，可以进行统一重启。
