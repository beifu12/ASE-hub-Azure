Issue

Customer is not able to see some data sources which are being backup from MABS, DPM 2016 or 2019 on the Recovery Services Vault.

We received some cases, where DPM Data sources appear to be mis matched on service side. As result data sources are not visible on the Recovery Services Vault due the negative impact this create on the gateway service which will upload telemetry data to the Recovery Services Vault every 30 minutes. Below the Service Name which can be found on the services.msc.

We do fail on when BMSAgentObjectsResync call which is done for DSPSDiskSyncGroup, executed from Artifacts, from the default MARS Agent default path or other.

Example for DPM, will be: C:\Program Files\Microsoft Azure Recovery Services Agent\bin\Artifacts\PowerShellScripts\DPM\

Example for MABS, will be: C:\Program Files\Microsoft Azure Recovery Services Agent\bin\Artifacts\PowerShellScripts\DPMVenus\

This is part of BMS and it can fail if Data Source operation such as Data Source ID, PS, ObjectID or overall information about usedDiskSpace, allocatedSpace, storageEntity.totalspace, availableDiskSpace, diskcount also fails to be added on service side.

In this case the PS1 files will try to get data from DPM. As we know every operation DPM does will store this on a SQL Database which means in order to pass this information which will be retrieved from the PS1 files, the data is missing from the DPM DB. As negative side effect this will fail.

As work around we will need to perform an insert on the table tbl_AM_InstalledAgent which contains a dependence from tbl_AM_Server.

Since the telemetry system after PS1 execution is trying to find Data source ID which depends on a Server ID on table tbl_AM_Server and dependency tbl_AM_InstalledAgent this will fail as explained above.
