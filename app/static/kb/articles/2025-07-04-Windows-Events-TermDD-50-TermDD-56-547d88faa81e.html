解决方案

  • 解决方案可以参考下面步骤：
  • a.       Run the following commands on both the client and the server to disable NIC offloading.
  • b.      Modify the following registry key to disable netDMA on the client and the server.
  • HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters\EnableTCPA
  • Note: If this registry entry does not exist, right-click Parameters, point to New, click DWORD Value, type EnableTCPA, and then press ENTER.

关于TermDD 50和TermDD 56的错误原因，可以参考下面两个链接：

https://blogs.technet.microsoft.com/askperf/2010/03/24/the-curious-case-of-event-id-56-with-source-termdd/

https://blogs.msdn.microsoft.com/scstr/2012/02/29/how-to-troubleshoot-the-terminal-server-security-layer-detected-an-error-in-the-protocol-stream-and-has-disconnected-the-client-client-ip-and-the-rdp-protocol-component-x-224-de/

从上面连接中看到，TermDD的原因有如下可能：

This happened in conditions of heavy traffic to the server along with large client packets (i.e. lot of input activity on the client). As a result, the data stream gets corrupted and the TS server disconnects the client. 即可能由于网络流量负载高以及大数据包导致类似问题，该异常可能导致如下情况：

– RDP Session may freeze.

– Black screen inside RDP window.

– Slow connection.

– You may also be disconnected.

解决方案可以参考下面步骤：

a.       Run the following commands on both the client and the server to disable NIC offloading.

netsh int tcp set global chimney=disabled

netsh int tcp set global rss=disabled

b.      Modify the following registry key to disable netDMA on the client and the server.

HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters\EnableTCPA

Note: If this registry entry does not exist, right-click Parameters, point to New, click DWORD Value, type EnableTCPA, and then press ENTER.

Value: 0
