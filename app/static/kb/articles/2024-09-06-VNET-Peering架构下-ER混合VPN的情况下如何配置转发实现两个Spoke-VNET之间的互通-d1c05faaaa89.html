Hub-spoke network topology in Azure - Azure Reference Architectures | Microsoft Docs

在如上网络拓扑中，IDC和Hub VNET之间有VPN和ER混合VPN的两种情况下，测试结果是不同的。

spoke VNET之间如果指定UDR下一跳到虚拟网络网关，在VPN环境下是可以通信的。在ER混合VPN的环境下测试是不能通的。如果把UDR的下一跳改成VPN网关的内网IP（测试两个网关实例的内网IP均可以），则spoke  VNET之间是可以通信的。

原因是ER GW不能够作为UDR中的下一跳，ER混合VPN的情况下，ER网关优先，所以如果Spoke VNET如果指定URD下一跳是虚拟网络网关，那么会把流量默认扔到ER网关上，ER GW不支持作为UDR的下一跳。
