LuYitong

近期在处理工单时，客户反应在2台Azure数据磁盘之间传输数据出现卡顿/传输速率频繁降为0bytes/s。经查看文档和多次测试，现象分析如下：

问题现象：2台D32s_v3数据盘（2T SSD）之间通过共享方式拷贝大文件数据出现卡顿，传输速率频繁降为0 bytes/s。

搭建测试：模拟贵方实际测试场景，搭建了2台VM（同一虚拟网络），通过UNC:\\共享路径访问模式，从A机器数据盘（只读缓存）àB机器数据盘 （读写缓存）进行数据传输（200G大文件）。

测试结果：每当目标机器（B）数据盘“HOST CACHING”配置为“Read/Write”时，在执行大文件传输及频繁写入期间会导致磁盘写入Pending或卡顿。

问题原因：硬盘写入缓存功能可以加快硬盘的读写速度，根据写缓存原理，数据会暂时存储在缓存，硬盘会在空闲（不进行读取或写入的时候）时再将缓存中的数据写入到盘片上。但由于特殊情况下有大量数据写入以致瓶颈，此时系统无法再继续处理缓存写入，造成写入Pending，并优先处理缓存数据到永久磁盘（数据盘），体现为数据写入卡顿/传输速率频繁降为0 bytes/s。

缓存配置：

设置为无   ：如果你的应用基本都是写入，或者超过80%以上的都是写入操作，则缓存设置为无。

设置为只读：这个选项是Premium Storage的默认选项也是最为常见的选项，如果你的应用操作是读写的，或者只读的操作,建议使用该选项。

设置为读写：如果你的程序可以处理缓存数据，并且在需要的时候可以将缓存数据写入到持久化磁盘，对应用程序有较高要求，处理不当可能会有数据损失（例如突然断电）。

相关建议：

需要根据用户具体应用的实际情况进行正确设置获得最佳性能。

对于读取频繁或只读数据磁盘（如 SQL Server 数据文件），可将磁盘缓存策略设置为 ReadOnly。对于写入频繁或只写数据磁盘（如 SQL Server 日志文件），可将磁盘缓存策略设置为 None。具体请参考：https://docs.microsoft.com/zh-cn/azure/virtual-machines/windows/premium-storage-performance#disk-caching。

但是，并非所有 VM 都支持缓存，因此请查看 VM 说明了解你感兴趣的 VM 的大小及更多信息，支持缓存的 VM 将在其说明中以“最大缓存和临时存储吞吐量”度量进行指示。
