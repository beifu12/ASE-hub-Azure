问题现象 / 场景

  • 客户在P2S连接成功后(采用entra登陆方式)，过不了多久就会出现自动断连的现象，断连后client报错信息： Failure in acquiring Microsoft Entra Token. The device that is required by this cyptographic provider is not ready for use

  • 打开 Credential Manager（凭据管理器）
  • 打开“设置 → 账户 → 访问工作或学校”

排查思路

  • 排查步骤：
  • 确认其他用户是否有该问题情况，经过测试，确认没有复现客户问题。
  • 确认客户的其他设备进行连接没有出现该问题，因此判断主要问题出于问题设备下。
  • 根据报错信息，判断与entra token的缓存存在联系，因此排查了客户用于缓存token的相关系统配置。
  • 收集客户的P2S 客户端信息，查看到日志中有新的报错内容：
  • 由于目前您的TPM已经开启，则需要检查一下本地的登陆账号情况，可以先检查一下对应的Azure 账户是否有添加到本机的work or school account当中。如果没有，请先手动connect上对应的azure 账户。
  • 客户确认账号是有正常添加的，并且重新进行了connect，但是没有缓解问题的情况。
  • 删除与 Azure VPN 客户端相关的所有凭据(与azure portal账号相关项)
  • 最终客户确认，采用删除Windows Credential的方式，在重新在连接P2S时，重新进行登陆后，恢复了正常，不再复现断连问题。

2025/12/29

参考工单：SR_20251124383913_vpn总是自动断开

问题描述：

客户在P2S连接成功后(采用entra登陆方式)，过不了多久就会出现自动断连的现象，断连后client报错信息： Failure in acquiring Microsoft Entra Token. The device that is required by this cyptographic provider is not ready for use

排查步骤：

确认其他用户是否有该问题情况，经过测试，确认没有复现客户问题。

确认客户的其他设备进行连接没有出现该问题，因此判断主要问题出于问题设备下。

根据报错信息，判断与entra token的缓存存在联系，因此排查了客户用于缓存token的相关系统配置。

协助客户进行VPN客户端信息的重新导入，再次连接后发生TPM报错，判断主要是客户端没有在BIOS开启该功能。相关介绍：排除 TPM 故障 | Microsoft Learn

开启TPM后，虽然恢复了一阵连接，但是后续再次复现问题。

收集客户的P2S 客户端信息，查看到日志中有新的报错内容：

PipeServer: Message from client: {"PipeCommand":0,"PipeData":"{\"ProfileName\":\"HUB-VNET-CN3-PRD\",\"FailureReason\":\"Failure in acquiring Microsoft Entra Token: Keyset does not exist\",\"FailureErrorCode\":-2146893802,\"FailureCategory\":\"Authentication\",\"ConnectionStatus\":14,\"AssignedIP\":\"172.16.248.3\",\"ConnectTriggerTimeStamp\":1.3408683289963424E+17,\"GatewayVip\":\"159.27.118.115\",\"RouteList\":\"172.16.32.0/21\\r\\n10.224.229.0/24\\r\\n172.16.8.0/21\\r\\n172.16.0.0/21\\r\\n172.16.16.0/21\\r\\n172.16.248.0/24\\r\\n\",\"DNSServerList\":\"\",\"ConnectionId\":\"{81c0294a-956e-447d-b4d8-8ed463e2ec72}\"}"}

针对于这个报错，官方也给出了相应的描述，

由于目前您的TPM已经开启，则需要检查一下本地的登陆账号情况，可以先检查一下对应的Azure 账户是否有添加到本机的work or school account当中。如果没有，请先手动connect上对应的azure 账户。

客户确认账号是有正常添加的，并且重新进行了connect，但是没有缓解问题的情况。

为了进一步确认相关的缓存信息没有进行影响，建议客户：

删除并重建用户级别 DPAPI 密钥缓存

打开 Credential Manager（凭据管理器）

删除与 Azure VPN 客户端相关的所有凭据(与azure portal账号相关项)

打开“设置 → 账户 → 访问工作或学校”

找到你的工作帐户（Azure AD）点击 断开连接

Azure VPN Client重新登录并重新导入连接配置

最终客户确认，采用删除Windows Credential的方式，在重新在连接P2S时，重新进行登陆后，恢复了正常，不再复现断连问题。
