Obtaining the ID of the managed identity / service principal

Cluster configuration

Command

AKS cluster with service principal

az aks show -g <AKSResourceGroup> -n <AKSClusterName> --query servicePrincipalProfile.clientId -o tsv

AKS cluster with managed identity

az aks show -g <AKSResourceGroup> -n <AKSClusterName> --query identityProfile.kubeletidentity.clientId -o tsv

AKSResourceGroup为AKS Cluster所属的Resource Group。

如果不确定AKS cluster是使用哪种方式部署的，当查询Service Principal Client ID时输出为“msi”，证明此AKS Cluster采用的是managed identity方式部署的。

当AKS使用managed ideityty方式部署时，这一步骤中输出的ID实际为AKS Cluster创建过程中平台自动创建的用于代表AKS agent pool的User assigned managed identity，它的Client ID。

Performing role assignments

az role assignment create --role "Managed Identity Operator" --assignee <ID> --scope /subscriptions/<SubscriptionID>/resourcegroups/<NodeResourceGroup>

az role assignment create --role "Virtual Machine Contributor" --assignee <ID> --scope /subscriptions/<SubscriptionID>/resourcegroups/<NodeResourceGroup>

对于启用或者未启用RBAC的AKS Cluster都需要执行上述两条指令；两条指令中的ID即为上一步中输出的ID；NodeResourceGroup即为当创建AKS时平台自动创建的以“MC_”开头与AKS Cluster同名同Region的Resource Group。

如果部署AKS Cluster时指定的User-assigned identities没有在AKS node resource group中，则还需要授予这个AKS agent pool managed identity在AKS Cluster User-assigned identity资源组内的Managed Identity Operator角色。

az role assignment create --role "Managed Identity Operator" --assignee <ID> --scope /subscriptions/<SubscriptionID>/resourcegroups/<IdentityResourceGroup>

Create an Azure identity and give it permissions to ARM

这一identity会被AGIC用来执行Application Gateway的配置更新。它可以创建在任意资源组中，但如果它不被创建在AKS Cluster Resource Group中，后续角色分配中需要多执行一步。

创建这一Azure Identity:

identityName="<identity-name>"

resourceGroup="<resource-group>"

az identity create -g $resourceGroup-n $identityName

并记录这一指令的输出，后面需要用到这一Identity的Client ID（identityClientId）和Resource ID（identityId）。
