Inner Error Message

Please check if backup to URL is also configured for the database 3ppns.

排查过程：

==========

1， 首先根据官网提示，用户遇到的报错是可能是由于其他备份方案的干扰导致截断了日志链。参考：

https://learn.microsoft.com/en-us/azure/backup/backup-sql-server-azure-troubleshoot#usererrorsqllsnvalidationfailure

2， 排查了目标SQL server VM 上的应用日志和system log 均没有发现对应时间点的异常备份情况。

3， 进一步排查task scheduler也没有发现备份异常的情况。

4，查了SQL server 在azure 平台上的extention 也没有看到干扰内容。

5，继续排查问题SQL server 上的所有service，发现除了SQL server agent 与我的测试环境中状态不一致。 默认仅使用ASR 备份的情况下SQL server agent 服务是stop 的状态，用户的是running状态。

6，继续排查，对比用户的环境和我的测试环境，这里发现用户的SQL 服务器bcnace-3ppns-db-qa 本身确实开启了另外一个backup 服务，该服务是SQL server 自身的automated backup 解决方案。而另外一台SQL 服务器BCNACE-3PPNS-DB-P 是保持的默认disabled 的状态。

解决方案：

用户关闭了SQL backup 并在recovery service vault 中做了一次全备份之后问题得到了解决。
