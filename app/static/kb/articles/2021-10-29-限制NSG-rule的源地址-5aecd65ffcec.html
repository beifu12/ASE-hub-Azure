参考工单： SR_2020021706494_[MS-LED]策略的编写中，子网的包含关系怎么写？

需求：

一个用户可以修改NSG规则，但是如果他添加22端口的源地址不是10.0.0.0/8的NSG条目的话，那Policy就Deny这个操作

实现：

使用Azure Policy实现，定义的Policy如下

{

"properties": {

"policyType": "Custom",

"mode": "All",

"metadata": {

"createdBy": "244b217a-b616-49f3-b084-445ad47b3640",

"createdOn": "2020-02-21T09:29:30.3675135Z",

"updatedBy": null,

"updatedOn": null

},

"policyRule": {

"if": {

"allOf": [

"field": "type",

"equals": "Microsoft.Network/networkSecurityGroups/securityRules"

"field": "Microsoft.Network/networkSecurityGroups/securityRules/access",

"equals": "Allow"

"field": "Microsoft.Network/networkSecurityGroups/securityRules/direction",

"equals": "Inbound"

"field": "Microsoft.Network/networkSecurityGroups/securityRules/sourceAddressPrefix",

"notEquals": "10.0.0.0/8"

"field": "Microsoft.Network/networkSecurityGroups/securityRules/destinationPortRange",

"equals": "22"

}

]

"then": {

"effect": "deny"

"id": "/subscriptions/c1fe03e6-ff80-4d91-824d-ba495a000792/providers/Microsoft.Authorization/policyDefinitions/fuzltestpolicy",

"type": "Microsoft.Authorization/policyDefinitions",

"name": "fuzltestpolicy"

启用之后，测试如下：

1、创建源地址是*， 目标端口是22的规则，由于源地址不是10.0.0.0/8, 拒绝创建

拒绝创建

2、创建源地址是10.0.0.0/8，目标端口是22的规则，可以创建

3、添加源不是10.0.0.0/8, 但是目标端口不是22，比如是9000，由于未违反规则，可以创建

以上，如有任何问题，欢迎联系！
