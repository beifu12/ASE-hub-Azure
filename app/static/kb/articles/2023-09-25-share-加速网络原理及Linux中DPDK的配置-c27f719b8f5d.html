===加速网络原理部分===

功能配置

门户上可以在虚拟机>>网络>>网络接口>>编辑加速网络中启用或禁用加速网络功能

架构对比

无加速网络：

Azure主机跟数据中心的交换机之间的流量会经过虚拟交换机中转

有加速网络：

Azure主机跟数据中心的交换机直接交换流量，不再经过虚拟交换机

具体实现：

在创建不带加速网络的Azure虚拟机时，平台会为VM的虚拟NIC配置一个默认接口，在OS中作为VMBUS设备存在，并且使用netvsc驱动，默认接口作为主接口，只有默认接口才可以配置IP地址与应用程序进行流量交互。

开启加速网络功能后，平台会基于物理网卡提供的功能再为虚拟NIC创建一个VF接口，在OS中作为PCI设备存在，使用Mellanox mlx4 或 mlx5 驱动程序。

接口配对

加速网络功能开启后，NIC的默认接口和VF接口会自动完成配对，VF接口作为默认接口的从接口，这两个接口对应的是同一张NIC，所以它们共享相同的MAC地址，请再次注意，应用程序只与默认接口交互。

数据流向

应用程序将数据交付给默认接口，经驱动处理后转发到VF接口中发出。类似地，接收数据时，数据经由VF接口处理后转发到默认接口，并交付给应用程序

===配置DPDK===

DPDK是Data Plane Development Kit （数据面开发工具套件）的缩写，可绕过内核空间，直接通过用户空间调用系统资源，从而避免了内核空间与用户空间的上下文切换，减少了系统开销，有效地提升处理网络数据的速度

先决条件：

操作系统最低要求

Linux OS

内核版本

Ubuntu 18.04

4.15.0-1014-azure+

SLES 15 SP1

4.12.14-8.19-azure+

CentOS 7.5

3.10.0-862.11.6.el7.x86_64+

Debian 10

4.19.0-1-cloud+

Linux 虚拟机上需要启用加速网络。 虚拟机应至少有两张网卡，第一张网卡作为跟Azure控制面通信的管理网卡，管理网卡不能由DPDK应用程序接管，否则会导致SSH断开。

最佳实践

环境：

VM Size: Standard D8ds v4

OS版本： CentOS Linux release 7.5.1804 (Core)

内核版本： Linux version 3.10.0-862.11.6.el7.x86_64

虚拟机要在停机状态下才能添加第二张网卡，由于要客户的场景要测试与公网的交互，这里我们为第二张网卡关联一个公网IP地址以便访问外网，并为此网卡配置NSG出站规则放行到公网的出向流量

在网络接口>>概述>>编辑加速网络中为第二张网卡启用加速网络功能，

开机SSH登录到VM，以root用户登录， ifconfig查看网卡验证加速网络功能。eth1为默认接口，eth2为VF接口从属于eth1(SLAVE)，它们共享相同的MAC地址

安装版本依赖项

yum -y groupinstall "Infiniband Support"

sudo dracut --add-drivers "mlx4_en mlx4_ib mlx5_ib" -f

yum install -y gcc kernel-devel-uname -r numactl-devel.x86_64 librdmacm-devel libmnl-devel

安装meson和ninja

python3 -m pip install meson

python3 -m pip install ninja

下载DPDK，这里推荐下载19.11.14 LTS版本, 这个版本的testpmd命令才有文档中的-w参数，

wget https://fast.dpdk.org/rel/dpdk-19.11.14.tar.xz

解压此压缩包并进入到dpdk主目录

tar -xf dpdk-19.11.14.tar.xz

cd dpdk-stable-19.11.14/

生成配置，编译并安装dpdk, 并进入到dpdk程序目录下

meson builddir

ninja -C builddir

DESTDIR=/tmp/dpdk ninja -C builddir install

cd /tmp/dpdk/usr/local/bin

运行以下命令配置运行环境（虚机每次重启后，要运行testpmd命令都要先配置一遍运行环境）

echo 1024 | sudo tee /sys/devices/system/node/node*/hugepages/hugepages-2048kB/nr_hugepages

mkdir /mnt/huge

mount -t hugetlbfs nodev /mnt/huge

grep Huge /proc/meminfo

使用ethtool查看VF接口的PCI地址, 我这里的地址是0002:00:02.0

ethtool -i eth2

加载ib驱动后运行testpmd, 标黄部分改成自己的PCI地址, 进入到testpmd命令接口

modprobe -a ib_uverbs

./dpdk-testpmd -w 0002:00:02.0 -- -i --port-topology=chained

在testpmd命令接口中查看端口信息，并且对相应端口进行监听

show port info all

start

新开一个ssh窗口，指定一条eth1出站的精确路由，并使用paping工具发包

route add -host 220.181.38.150 dev eth1 gw 172.18.0.1 #(标黄部分为eth1所在子网网关)

wget https://storage.googleapis.com/google-code-archive-downloads/v2/code.google.com/paping/paping_1.5.5_x86-64_linux.tar.gz

tar -xf paping_1.5.5_x86-64_linux.tar.gz

./paping 220.181.38.150 -p 80

切换回监听的ssh窗口，使用stop命令即可看见此端口上的数据包统计信息，这其实就是VF接口处理的包的数量信息
