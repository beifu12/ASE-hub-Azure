Local network gateway ASN 65515 issue

一句话摘要

65515为azure保留的ASN,所以本地网络网关中ASN不能配置65515，除非连接的对端为Azure China VWAN VPN（ASN无法修改为其他，只能为65515）；若客户对端为global azure 的VWAN VPN（ASN：65515），此情况下就无法支持。

问题现象 / 场景

  • 65515为azure保留的ASN,所以本地网络网关中ASN不能配置65515，除非连接的对端为Azure China VWAN VPN（ASN无法修改为其他，只能为65515）；若客户对端为global azure 的VWAN VPN（ASN：65515），此情况下就无法支持。

解决方案

  • If customer needs to configure BGP for the VNG-vWan connection, then this is not supported in a cross-cloud scenario. This is because we have checks in place to validate the BGP ASN and the LNG IpAddress, and these checks will fail if the vWan is not in the same cloud as the LNG - this is the failure that we have observed when trying to configure VNG-vWan interconnect with BGP below. Unfortunately, there is no workaround for this.

VNG-vWan interconnect across cloud instances would work only if BGP is not configured. Customer can configure static routes on the local network gateway instead to get this working.

If customer needs to configure BGP for the VNG-vWan connection, then this is not supported in a cross-cloud scenario. This is because we have checks in place to validate the BGP ASN and the LNG IpAddress, and these checks will fail if the vWan is not in the same cloud as the LNG - this is the failure that we have observed when trying to configure VNG-vWan interconnect with BGP below. Unfortunately, there is no workaround for this.
