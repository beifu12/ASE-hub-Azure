APPGW的WAF:

这里的WAF，是附着在APPGW的instance上，由其中的IIS组件所衍生出的模块来进行使用：

Modsecurity Project

Compilation recipes for v3.x · owasp-modsecurity/ModSecurity Wiki

默认来说，ModSec这个组件会在IIS上直接开启：

我们在APPGW上的WAF，flow的走向为：

NRP->RNM(Resource Network Manager)->BrkGWM->GWT(AppGW instance)

因此，WAF的触发程序，应该在其中的最后一步。

排查“错误的网关”错误 - Azure 应用程序网关 | Azure Docs

根据验证，在网关本身无法路由任何请求的时候，会直接在RNM这步停住，不再向Brk以及GWT（WAF）转发请求，因此直接返回502.

根据目前的测试结果，总结如下：

Client->NRP->RNM(Resource Network Manager)->BrkGWM->GWT(AppGW instance)(WAF)

如果流量可以触发路由规则检测，那么此路由将会受到WAF的限制，返回403（WAF规则匹配则会返回对应HTTP error code）

如果流量未能触发路由规则检测，那么此路由将在RNM上直接被丢弃，返回502。
