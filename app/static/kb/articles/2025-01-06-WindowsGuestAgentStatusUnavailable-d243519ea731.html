c:\windowsazure\logs\WaAppAgent.log

Ignoring) Exception while fetching supported versions from HostGAPlugin: System.Net.WebException: Unable to connect to the remote server ---> System.Net.Sockets.SocketException: No connection could be made because the target machine actively refused it 127.0.0.1:8888

Where 127.0.0.1:8888 is anything other than 168.63.129.16:80  (host’s WireServer)

Collect C:\Windows\Microsoft.NET\Framework64\v4.0.30319\Config\machine.config

Check if there’s a System.Web section with something like:

<system.net>

<defaultProxy useDefaultCredentials="true">

<proxy proxyaddress="http://127.0.0.1:8888" usesystemdefault="True"/>

</defaultProxy>

</system.net>

This is overriding the GuestAgent’s WebClient behavior to connect to Azure Storage / HostGAPlugin and correctly reports status.

and it’s causing the error "System.Net.Sockets.SocketException: No connection could be made because the target machine actively refused it 127.0.0.1:8888"

No plugin manifest file C:\Packages\Plugins\Microsoft.Azure.RecoveryServices.VMSnapshot\<ExtensionVersion>\HandlerManifest.json found under the plugin folder

Extract the contents from Microsoft.Azure.RecoveryServices.VMSnapshot_<LatestVersion>.zip from the path C:\Packages\Plugins\Microsoft.Azure.RecoveryServices.VMSnapshot\<LatestVersion> with replace-files option. Extract files in the same path.

Run the below command from elevated command prompt to enforce Extension reinstall and re-trigger the backup from the Azure portal.

REG ADD "HKLM\SOFTWARE\Microsoft\BcdrAgent" /v IsProviderInstalled /t REG_SZ /d False /f

Root-cause of this issue is that some program is deleting files from VMSnapshot Extension installation path.

Ask customer to find-out which program (virus/anti-virus etc.) is deleting files from VMSnapshot Extension installation path, for this they can monitor the path C:\Packages\Plugins\Microsoft.Azure.RecoveryServices.VMSnapshot.

For the operation to succeed, customer should remove/fix that program.
