What is the customer facing symptom for this failure?

Backup failure with ErrorCode BCMProtGetSaSUriAsyncError

Cause 1: Insufficient permissions for the Recovery services vault to access Azure Key Vault

How to verify if the failure is caused by this specific root cause?

If below query results in some rows as output :

Plain Text

union cluster('mabprod1').database('MABKustoProd1').TraceLogMessage, cluster('mabprodweu').database('MABKustoProd').TraceLogMessage, cluster('mabprodwus').database('MABKustoProd').TraceLogMessage

| where TIMESTAMP > ago(20d)

| where TaskId == "<TaskId>"

| project PreciseTimeStamp, ServiceName, FileNameLineNumber, Message, Level = Level + 1, TaskId

| where Message contains "UserErrorProtCMKAKVAuthFailure"

What is the workaround?

Follow below documentation to provide KeyVault having Customer Managed Key (CMK) access to the RecoveryService Vault

Encryption of backup data using customer-managed keys

Customer Ready Content

Cause 2: The Subscription is migrated to new tenant

If the Subscription (with Recovery service vault, the data source protected say IaaS VM, and key vault used for CMK) are all migrated to new tenant, then the backups on CMK enabled vault might fail with the error BCMProtGetSaSUriAsyncError.

To Check if Subscription of customer has undergone Tenant Migration:

Step1

| where EventCode == 5020

| where Message contains "<SubscriptionId>"

| where Message contains "ShouldRunTEE = True"

| project TaskId

TraceLogMessage

| where TIMESTAMP > ago(21d)

| where TaskId in (<TaskID from above query’s output>)

| where Message contains "tenant"

Search for tenantID in the Message We might trace similar to:

d4p1:Properties"{\r\n "tenantId": "08c69f21-c435-402b-bbdc-8de5ae0bb3e2",\r\n "locationPlacementId": "Public_2014-09-01",\r\n "quotaId": "EnterpriseAgreement_2014-09-01",\r\n "registeredFeatures": []\r\n}"</d4p1:Properties> Ignore any message starting with “Returning stamp details from cache”

Step2: Search in Backup TaskID traces for the tenant ID

Step3: Confirm from the Customer that they have done tenant migration. This is vey important, as this is a user triggered operation

What is the workaround? To resolve this issue, follow the steps listed below on each of the impacted vaults

Solution 1: If the System Assigned Identity is used in Recovery Services Vault

Step 1: Disable the Vault System Assigned MSI

Navigate to 'Vault' -> Identity -> System Assigned -> Change status to 'Off' and Save.

Step 2: Re-enable the Vault System Assigned MSI

Navigate to 'Vault' -> Identity -> System Assigned -> Change status to 'ON' and Save.

Step 3: Regrant Azure Key Vault permission to Vault System Assigned MSI:

Navigate to Key Vault hosting the CMK and re-grant permissions (GET,LIST, WRAP and UNWRAP Key) to the system assigned MSI of the Vault. Detailed steps listed in this article

Step 4: Save and Re-apply CMK with the same settings

Navigate to 'Vault' -> Properties -> Encryption Settings -> just 'Save' the existing settings to reapply the CMK.

Step 5: Validate if the CMK Update succeeds in the Jobs page.

Step 6: After the previous step is complete, re-trigger the backups and check if it succeeds.

Solution 2: If the user Assigned Identity is used in Recovery Services Vault:

Step 1: Remove the User Assigned Identity from RS Vault

Navigate to 'Vault' -> Identity -> User Assigned -> Remove the identity used under CMK settings.

Step 2: Re-add the same User Assigned Identity to RS Vault

Navigate to 'Vault' -> Identity -> User Assigned -> Add the identity used under CMK settings.

Step 3: Save and Re-apply CMK with the same settings

Step 4: Validate if the CMK Update succeeds in the Jobs page.

Step 5: After the previous step is complete, re-trigger the backups and check if it succeeds.
