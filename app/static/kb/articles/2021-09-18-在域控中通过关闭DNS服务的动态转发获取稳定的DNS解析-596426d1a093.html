Nslookup会触发补全dns后缀的动作，这个解析失败时符合区域的，所以我们再正常的log中也会看到针对fqdn+dns suffix这个域名出现一次解析失败的情况，但是在后续fqdn的解析中，转发器Azure平台正常返回了对应的A记录信息，最终dns server返回客户端正常的域名记录。

异常解析

而问题出现时，我们发现dns server再收到fqdn+dns suffix的请求返回预期报错之后，针对原始FQDN，dns server没有往Azure 平台的dns server进行转发，而是直接返回了“no such domian”的报错。之所以会发生这个问题，是由于这时候dns server已经有了negative cache，所以直接返回了上面的结果。那为什么会出现negative cache呢，原因就是之前dns server收到一个关于reddog域名的记录请求，这时候请求被转发到了外部ISP的dns server 202.96.209.133，由于该dns server无法解析reddog的域名，dns server收到该响应报文后就把结果给缓存了下来，最终引起直接给客户端返回解析失败的结果。

查看当前Azure china的dns server 配置，我们发现以上外部ISP的dns server是在配置列表中的。由于server 2012R2的新功能 动态dns转发器 ，当时该dns转发器被列为第一优先级的转发器。

以上的情况是在条件转发器配置不生效的情况下发生的。我们进一步分析dns server的etl trace，与以上网络包的行为是一致的。我们发现dns server收到client关于以下域名的请求时，由于本地权威区域没有对应的zone信息会进行递归查询，在选择转发域名的时候，由于动态forwarder功能，当时选择将该域名转发到外部ISP的dns server 202.96.209.5，由于该dns server没能解析到reddog的域名，直接返回了no such name和SOA记录的结果，最终缓存到了dns 服务器本地。条件转发器不生效的情况，目前的dns server没有cover这个情况。

根据微软技术支持经验，server 2012开始版本支持动态转发器的新功能，对应转发器是根据响应时间来确定最终转发的结果，所以会出现以上行为。具体请参考以上信息，

Dynamic DNS Forwarders

When you add more than one forwarder in the settings for a DNS Server in Windows Server 2012 R2, the DNS service reorders the list of servers in the list of forwarders based on response time of each server in the list. The reordering and response checking operations are enabled by default in Windows Server 2012 R2. If you wish to disable this feature, you need to change the following registry DWORD value to 0:

Copy

HKLM\System\CurrentControlSet\Services\DNS\Parameters\EnableForwarderReordering

除了以上注册表信息，我们也可以通过以下PS命令来关闭动态转发器功能，关闭以上功能后，dns服务器选择转发器时，依然会根据转发器的配置顺序来进行递归查找对应的dns记录。

Set-DnsServerForwarder -EnableReordering $False -PassThru

完成配置后，可以通过重启dns server服务来生效。
