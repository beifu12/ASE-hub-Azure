前言：

本Share主要针对Case 遇到的复杂网络情况下的问题，不讨论没出现的情况（证书等），所有其他激活问题可按步骤参考以下两个文档：

Custom Routes for KMS Activation.

Windows activation watermark continues to be displayed - Virtual Machines | Microsoft Learn

一、问题相关Case：20241211329780、20250122335966

二、问题现象：该问题分两种情况，一种是纯粹的未激活（完整参考解决方案），一种是命令返回信息显示倒计时，但是水印仍在（参考解决方法的方法2）：

1、Windows Server 提示被取消激活，未使用Azure 版本或权益的系统等信息。

2、slmgr.vbs /dli 命令显示激活成功，显示100多天倒计时，但Windows设置显示未激活、桌面水印仍在

三、解决方案：

1、首先确保激活路由从Azure侧出站：Use Azure custom routes to enable KMS activation with forced tunneling - Virtual Machines | Microsoft Learn

PS C:\Windows\system32> (Invoke-WebRequest -Uri "http://ifconfig.me/ip").content 查出口是否是Azure

使用Azure Powershell 在ISE 下运行如下脚本：

First, get the virtual network that hosts the VMs that have activation problems. In this case, we get virtual network ArmVNet-DM in Resource Group ArmVNet-DM:

$vnet = Get-AzVirtualNetwork -ResourceGroupName "ArmVNet-DM" -Name "ArmVNet-DM"

Next, create a route table:

$RouteTable = New-AzRouteTable -Name "ArmVNet-DM-KmsDirectRoute" -ResourceGroupName "ArmVNet-DM" -Location "chinanorth3"

Next, configure the route table:

Add-AzRouteConfig -Name "DirectRouteToKMS" -AddressPrefix 159.27.28.100/32 -NextHopType Internet -RouteTable $RouteTable

Add-AzRouteConfig -Name "DirectRouteToAZKMS01" -AddressPrefix 163.228.64.161/32 -NextHopType Internet -RouteTable $RouteTable

Add-AzRouteConfig -Name "DirectRouteToAZKMS02" -AddressPrefix 42.159.7.249/32 -NextHopType Internet -RouteTable $RouteTable

Set-AzRouteTable -RouteTable $RouteTable

Next, attach the route table to the subnet that hosts the VMs:

Set-AzVirtualNetworkSubnetConfig -Name "Subnet01" -VirtualNetwork $vnet -AddressPrefix "10.0.0.0/24" -RouteTable $RouteTable

Set-AzVirtualNetwork -VirtualNetwork $vnet

此时确保两个域名：azkms.core.chinacloudapi.cn、kms.core.chinacloudapi.cn（两个中的一个），DNS解析能对应上

Test-NetConnection kms.core.chinacloudapi.cn -port 1688

Test-NetConnection azkms.core.chinacloudapi.cn -port 1688

不通就查DNS，是否有自己的DNS，然后自行建host文件解析，并确保系统防火墙放行。

2、此时激活问题一般可以解决，部分用户的网络环境和限制更多，上述步骤无用，需要也放行IMDS服务器

Powershell 敲如下命令，若无响应，放行169.254.169.254的80、443端口

Invoke-RestMethod -Headers @{"Metadata"="true"} -Method GET -Uri "http://169.254.169.254/metadata/instance/compute/azEnvironment?api-version=2018-10-01&format=text"

至此问题基本可以解决，文档提到的证书问题一般不会出现。
