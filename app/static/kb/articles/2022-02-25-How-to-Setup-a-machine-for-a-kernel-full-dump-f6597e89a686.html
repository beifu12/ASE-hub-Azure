When to setup the machine for a dump

On a non-boot scenario where the machine is bluescreening and the last good known config nor reverting the hives worked

On Slow/hang/frozen scenarios

The best way to troubleshoot a case with a dump is always starts with a kernel dump and only if that is not enough, go with a full dump.

Kernel DUMP

If the machine is in a non-boot scenario then the OS disk needs to be attached to another VM then the following keys needs to be changed:

HKLM\SYSTEM\ControlSet001\Control\CrashControl\CrashDumpEnabled = 2

If the machine is in a booting scenario and if you can performed this change while the machine is online, then change:

HKLM\SYSTEM\CurrentControlSet\Control\CrashControl\CrashDumpEnabled = 2

For this configuration to kick in, the machine needs to be restarted.

There's no need to move the pagefile on any other place nor reduce the RAM memory.

By default, the dump if created will be on c:\windows\MEMORY.DMP

FULL DUMP

HKLM\SYSTEM\ControlSet001\Control\CrashControl\CrashDumpEnabled = 1

HKLM\SYSTEM\ControlSet001\Control\CrashControl\DumpFile = d:\memory.dmp

HKLM\SYSTEM\CurrentControlSet\Control\CrashControl\CrashDumpEnabled = 1

HKLM\SYSTEM\CurrentControlSet\Control\CrashControl\DumpFile = d:\memory.dmp

The dump size will be as large as the RAM memory. This will work only if the destination folder has enough space to have a dump file created.

Since the dump that is going to result on this is going to be as big as the RAM, its creating will take a way longer than a kernel dump.

If the machine is in a non-boot scenario then the destination drive to place the dump needs to be a DATA disk which then you can attach to another machine to get the dump

HKLM\SYSTEM\ControlSet001\Control\CrashControl\DumpFile = E:\memory.dmp
