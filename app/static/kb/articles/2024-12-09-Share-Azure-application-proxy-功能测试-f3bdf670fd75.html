测试环境

一、创建应用代理

至少以应用程序管理员的身份登录到 Microsoft Entra 管理中心，浏览到“标识”>“应用程序”>“企业应用程序”。

选择“新建应用程序” 。

选择“添加本地应用程序”按钮，该按钮显示在“本地应用程序”部分的中间位置。 也可以在页面顶部选择“创建自己的应用程序”，然后选择“配置应用程序代理以安全地远程访问本地应用程序”。

在“添加自己的本地应用程序”部分中，提供有关应用程序的以下信息 。注：URL 需要以 http 或 https 开头，以“/”结尾，URL 应为域名，而非 IP 地址

创建好后可以在企业应用中找到应用名称查看

在内部服务器上安装IIS 服务测试（测试过程中安装了验证方法）

在Microsoft Entra 管理中心 下载connector services 安装包

中国区安装需要添加如下参数.\MicrosoftEntraPrivateNetworkConnectorInstaller.exe ENVIRONMENTNAME=AzureChinaCloud

安装成功后使用管理员登录

安装成功后可以在应用代理中看到应用代理服务器的名字和状态。

二、添加用于测试的用户

将用户添加到应用程序之前，请验证该用户帐户是否有权从企业网络内部访问应用程序。

添加测试用户：

选择“企业应用程序”，然后选择要测试的应用程序 。

选择“用户和组”，然后选择“分配用于测试的用户” 。

在“用户和组”下，选择“添加用户” 。

选择要添加的帐户。

依次选择“选择”、“分配” 。

三、测试登录

若要测试对应用程的身份验证：

从要测试的应用程序中，选择“应用程序代理”。

在页面顶部，选择“测试应用程序” 以对应用程序运行测试并检查是否存在任何配置问题。

登录有可以正常访问内网的服务了访问

详细信息可以参考：添加本地应用程序以通过 Microsoft Entra ID 中的应用程序代理进行远程访问。 - Microsoft Entra ID | Microsoft Learn

三、使用自定义域名

如果使用自定义域名，需要添加并验证自定义域名后，选择自定义域名

在 Microsoft Entra 管理中心，浏览到”>“企业应用程序”>找到您的应用 在“应用程序代理”中找到“外部 URL”字段，向下滚动查看列表，再选择你想要使用的自定义域。

并再DNS服务商处设置DNS CNAME 记录 如：web1.vincentjones.cn -> web1-microsoftinternal.msappproxy.cn

验证域名解析

详细信息可以参考：Microsoft Entra 应用程序代理中的自定义域 - Microsoft Entra ID | Microsoft Learn

$certname = "web1.vincentjones.cn" ## Replace {certificateName}

$cert = New-SelfSignedCertificate -Subject "CN=$certname" -CertStoreLocation "Cert:\CurrentUser\My" -KeyExportPolicy Exportable -KeySpec Signature -KeyLength 2048 -KeyAlgorithm RSA -HashAlgorithm SHA256

可以测试为自签发证书，该证书只为测试，导出pfx。如果在实际场景中建议购买证书使用（必须使用 PFX 证书，以确保包含所有必需的中间证书。 该证书必须包含私钥。才能保证验证的完整性）

在应用代理中进行添加

添加后可以通过自定义域名访问（注：如下演示证书为自定义证书，报错为正常 有的浏览器可能会不允许继续访问，建议使用edge测试）

四、为Windows 验证设置SSO

AAD joined 的设备访问，测试用户为Tom jones，首先确认用户有权访问应用代理

在IIS 上启用windows 集成验证，禁用匿名访问

确认web 服务器如下位置为true 使用计算机账户解析Kerberos Ticket

注册SPN到 web应用 计算机账户

setspn -A HTTP/<IIS service name> <VMhostname>

我的web 服务器名称为membertest2，服务名称可以根据自己需要选择（该测试membertest2为IIS 服务器）

注册后在活动目录和计算机中找到该设备并添加SPN授权到 应用代理的服务上（该测试中安装应用代理的计算机为ADFSserver）

以上为IIS服务器上 的设置，仅供参考。详细步骤可以参考 第三方链接：Setting up Kerberos Authentication for a Website in IIS | Microsoft Community Hub

下面我们配置SSO，转到我们创建的应用注册，选择Single Sign-on 并选择Windows Integrated Authentication

填写之前建立的SPN并保存
