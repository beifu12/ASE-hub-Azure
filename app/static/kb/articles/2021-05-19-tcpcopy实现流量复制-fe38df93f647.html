一句话摘要

TCPCOPY可以实现在生产环境的A端将流量复制到指定的机器B端进行准确模拟生产场景去压测即将上线的测试环境，在复制过程中通过修改源IP为其他的地址比如192.168.100.4，在机器B端上配置负载均衡，将流量负载给即将上线的环境进行压测，并且同时调整B端的路由，将其回包丢给黑洞C端，避免B端回包回到生产环境的A端.

2021/05/19

TCPCOPY可以实现在生产环境的A端将流量复制到指定的机器B端进行准确模拟生产场景去压测即将上线的测试环境，在复制过程中通过修改源IP为其他的地址比如192.168.100.4，在机器B端上配置负载均衡，将流量负载给即将上线的环境进行压测，并且同时调整B端的路由，将其回包丢给黑洞C端，避免B端回包回到生产环境的A端.

配置分为两部分：Azure侧配置+虚拟机内部配置

一.Azure侧的配置：

1.在虚拟网络中新加地址空间192.168.100.0/24

2.在该虚拟网络中添加一个新的subnet ，并且该subnet的地址空间 为192.168.100.0/25或者192.168.100.0/26都可以 。

3.新建网卡，该网卡位于上面新建的subnet中，并将该网卡附件到VM1或者VMA（也就是安装tcpcopy的机器），在附加网卡的时候，需要将虚拟机关闭

4.开启VM1的两个网卡的ip_forwarding

同样为第二块网卡配置相同的步骤。

5.新建UDR并关联到步骤2新建的subnet中去

虚拟机内部的配置：

A端：10.3.0.19

yum install nc gcc* -y && git clone git://github.com/session-replay-tools/tcpcopy.git && cd tcpcopy && ./configure && make && make install && nc -k -l 6201

./tcpcopy -x 6201-10.3.0.19:6201 -s 10.3.0.21 -c 192.168.100.4 -d -C 4 -l /tmp/tcpcopy.log

B端：10.3.0.20

yum install pcre-* zlib* gcc* glibc* autoconf* automake* libxml* ncurses-devel* libgcrypt* libtool* bison* cmake* make* openssl* unzip* -y

wget http://nginx.org/download/nginx-1.18.0.tar.gz

mv nginx-1.18.0.tar.gz /usr/local/src/

tar -xf nginx-1.18.0.tar.gz && cd nginx-1.18.0/

./configure --prefix=/usr/local/nginx --with-http_ssl_module --with-http_stub_status_module --with-pcre --with-http_v2_module --with-http_gzip_static_module --with-ld-opt="-Wl,-E" --with-stream

make && make install

修改配置文件并启动nginx:

C端：10.3.0.21

yum groupinstall "Development Tools" -y

git clone git://github.com/session-replay-tools/intercept.git && cd intercept && ./configure && make && make install

./intercept -i eth0 -l /tmp/intercept.log -F 'tcp and src port 6201 and src host 10.3.0.19'

测试：

经过测试，可以实现将来自客户端访问生产主机A端的流量使用tcpcopy将其复制到B端，B端并将其调度至后端的测试系统。
