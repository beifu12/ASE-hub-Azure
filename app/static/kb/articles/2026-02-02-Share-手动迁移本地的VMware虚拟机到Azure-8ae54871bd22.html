思路是将VMDK转换为可用的VHD。但是在Windows中转换成VHD有精度问题，导致经常上传后创建失败。

参考如下的要求。

最稳妥的操作过程为，将vmdk转换为fixed vhdx。这样会尽可能减少转换精度问题。并且可以使用vhdx在本地的hyper-v测试调试。然后再将vhdx去除Sparsefile标记。使其动态的部分的数据完全展开。 然后使用Add-AzVhd完成格式的上传。Add-AzVhd的转换最为稳妥，并且可以直接建立managed disk。

首先将本地的VMware虚拟机导出。以下导出形式仅作为参考。只要可以导出vmdk单文件即可。

使用vdiskmanager将多个vmdk文件整合为一个vmdk。

vmware-vdiskmanager.exe -r "C:\Users\shane\Downloads\New folder\Windows Server 2022-cl1.vmdk" -t 0 "C:\Users\shane\Downloads\ws2022.vmdk"

下载qemu转换工具。使用该工具更改vmdk磁盘为vhdx磁盘。

https://qemu.weilnetz.de/w64/

使用下方命令转换为 vhdx

qemu-img convert -f vmdk -O vhdx -o subformat=fixed "C:\Users\shane\Downloads\ws2022.vmdk" "C:\Users\shane\Downloads\ws2022.vhdx"

使用下方命令检查。

Get-Item -Path "C:\Users\shane\Downloads\ws2022.vhdx " | Select-Object Name, Attributes

需要查看属性中没有Sparsefile。

如果有，解除该标识vhdx。

fsutil sparse setflag "C:\Users\shane\Downloads\ws2022.vhdx" 0

检查是否完成复制。

（可选）此时建议在本地的Hyper-V中测试该系统是否可用。

登录Azure PowerShell

Connect-AzAccount -Environment AzureChinaCloud -UseDeviceAuthentication

使用Add-AzVhd将该vhd上传并创建managed disk。

Add-AzVhd -ResourceGroupName "test" -Location "chinanorth3" -DiskName "vhd2022osdisk" -LocalFilePath "C:\Users\shane\Downloads\ ws2022_fixed.vhdx " -DiskSku "Standard_LRS" -DiskHyperVGeneration "V2"

上传的时候，会转换成vhd，请注意磁盘空间大小。

上传后，可以在对应的资源组中查看磁盘。

请注意，有的时候可能磁盘为ActiveUpload的状态。此时仍然在上传中。

创建虚拟机。

创建后查看是否可以运行。
