配置完成后建议先更新以下组策略服务使其尽快生效，或者重启操作系统。

测试结果如下，如果是在租户限制中没有配置的租户ID或者是阻止登陆的租户ID，在浏览器登录时都将被阻止。

更多排查步骤：

方案 1：测试 cloudidsvc 访问 O365

步骤 1.1：测试 DNS 解析

nslookup endpoints.office.com

步骤 1.2：测试网络连通性

Test-NetConnection -ComputerName endpoints.office.com -Port 443

如果 TcpTestSucceeded: False，说明防火墙或 Proxy 阻挡了 TCP 443 端口。

步骤 1.3：直接访问终结点

curl -v https://endpoints.office.com/version

如果失败，说明 Proxy 服务器阻挡了请求或未附加 TRv2 Header。

方案 2：确认 Proxy 是否正确添加 TRv2 Header

步骤 2.1：抓包检查 TRv2 Header

使用 Wireshark 或 Fiddler 抓包 https://endpoints.office.com/version，检查 是否包含 sec-Restrict-Tenant-Access-Policy 头部：

sec-Restrict-Tenant-Access-Policy: <TenantId>:<policyGuid>

如果 Header 丢失，则 Proxy 服务器配置错误，需要调整规则。

步骤 2.2：使用 curl 测试手动附加 Header

curl -v -H "sec-Restrict-Tenant-Access-Policy: <TenantId>:<policyGuid>" https://endpoints.office.com/version

如果手动添加 Header 后请求成功，说明 Proxy 服务器没有正确添加该 Header，需要 IT 团队修改配置。

方案 3：检查 Windows 代理配置

步骤 3.1：查看当前代理设置

netsh winhttp show proxy

如果设备使用代理： 确保 Proxy 允许 cloudidsvc 访问 https://endpoints.office.com。

步骤 3.2：禁用代理（仅测试）

netsh winhttp reset proxy

如果禁用代理后访问 endpoints.office.com 成功，说明 Proxy 配置问题，需要修正。

方案 4：联系 IT 团队调整 Proxy 配置

需要 IT 团队执行的调整：

确保 Proxy 允许 cloudidsvc 访问 https://endpoints.office.com/。
