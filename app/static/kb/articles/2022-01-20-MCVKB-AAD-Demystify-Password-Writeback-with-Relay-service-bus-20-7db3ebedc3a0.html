原始内容清洗稿（保留备查）

This is from ticket 20220114143791, in which customer tried to enable password writeback without valid license.

In this article we would mainly discuss the mechanism of password writeback with Azure service bus.

Overview

As you know, password writeback is an essential feature for AAD self-service password reset if customer is using hybrid environment. This feature requires AAD Premium P1 feature, is achieved by the PasswordResetService on AAD Connect server.

The PasswordResetService would integrate with Azure service bus service to create a relay, so that the on-prem components would know any password change from cloud in time.

What is relay

From https://docs.microsoft.com/en-us/azure/azure-relay/relay-what-is-it:

The Azure Relay service enables you to securely expose services that run in your corporate network to the public cloud. You can do so without opening a port on your firewall or making intrusive changes to your corporate network infrastructure.

Basic flow

In the relayed data transfer pattern, the basic steps involved are:

An on-premises service connects to the relay service through an outbound port.

It creates a bi-directional socket for communication tied to a particular address.

The client can then communicate with the on-premises service by sending traffic to the relay service targeting that address.

The relay service then relays data to the on-premises service through the bi-directional socket dedicated to the client. The client doesn't need a direct connection to the on-premises service. It doesn't need to know the location of the service. And, the on-premises service doesn't need any inbound ports open on the firewall.

How is relay related to password writeback

When password writeback feature is enabled on AAD Connect, the PasswordResetService will be created and running, no matter if customer has AAD premium license in-place. The service will establish relay connection to Mooncake relay service in China East and China North, with namespace ssprdedicatedsbmcprodcne and ssprdedicatedsbmcprodcnn.

An endpoint will be registered in each namespace, with naming like <Tenant GUID>_<Endpoint GUID>, so we will have two relay listeners for connection:

Sb://ssprdedicatedsbmcprodcne.servicebus.chinacloudapi.cn/<Tenant GUID>_<Endpoint GUID for China East>

Sb://ssprdedicatedsbmcprodcnn.servicebus.chinacloudapi.cn/<Tenant GUID>_<Endpoint GUID for China North>

The endpoint provide an HTTP page for testing, you can use the following PowerShell cmdlet to test the connectivity:

Invoke-WebRequest ssprdedicatedsbmcprodcne.servicebus.chinacloudapi.cn

Logs

Client side: Event viewer -> Application

SSPR server side: https://portal.microsoftgeneva.com/s/8B8DC386

Relay service side log: https://portal.microsoftgeneva.com/s/5E61D8DC

How to check tenant license status

ASC -> Tenant Explorer -> Tenant -> Subscriptions, check if there is any AAD Premium subscription.

Or check SSPR server side log, filter where TraceEnumCode == "TenantServicePlans".

How does PasswordResetService behave with Relay

When password writeback feature is enabled, you will see following events in AAD connect server Application log:

31004 Onboarding started

31041 for China east and China north, note that the endpoint format is <Tenant GUID>_<Endpoint GUID>

31005 Onboarding completed

31033 endpoint online event for China east and north

In relay service log, we will see following events:

When AAD connect service is restarted, the connection between PasswordResetService and relay will be broken, and you will see error 31034 for relay connection in China east and north.

When password writeback feature is disabled, you will see following events in application logs.

Some time you may see following error messages, reenabling password writeback feature may fix them.

31034

32014

Note that the network timeout of firewall (if any) should be set to above 5 minutes, because relay heartbeat interval is 5 minutes. This is identical with the value in proxy idle timeout described in Azure AD Connect: Troubleshoot Azure AD connectivity issues | Microsoft Docs.
