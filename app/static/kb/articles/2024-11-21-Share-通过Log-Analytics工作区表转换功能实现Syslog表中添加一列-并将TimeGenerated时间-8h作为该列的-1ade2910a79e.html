最近接了一个LA 工作区表转换功能案例SR_20241111324269，此处以客户需求“将syslog表中TimeGenerated值+8h显示”为例，梳理下大致转换方法，供大家后续参考。相关历史工单 20240304280689

LA工作区表转换主要分两种场景：

一、由DCR收集的数据，比如syslog，转换需要在收集数据的DCR上更改transfornKql的值，转换由syslog DCR中transfornKql的值控制。 下方有如何实现syslog表格转换步骤

二、由非DCR收集的数据，如旧式代理收集的数据（由于旧式代理已经退役，所以可能比较少见）或者一些资源日志（如LA诊断查询日志）。该场景，可完全参考使用 Azure 门户在工作区数据收集规则中添加转换执行表转换，表转换由创建出的工作区DCR中transfornKql的值控制。

++++++++++如何实现syslog表格转换步骤+++++++++++++++++++++++++++++++++

以下方法可实现由DCR收集的syslog表转换（新建BJTimeGenerated_CF列，BJTimeGenerated_CF=TimeGenerated+8）。

查看原始数据

通过Powershell添加在syslog表中添加新列，参考更新表架构部分。

使用Powershell登录Azure账户，然后运行如下脚本。注：标黄处替换为自己环境实际值

$tableParams = @'

{

"properties": {

"schema": {

"name": "Syslog",

"columns": [

"name": "BJTimeGenerated_CF",

"description": "The list of resources, this query ran against",

"type": "DateTime",

"isDefaultDisplay": true,

"isHidden": false

}

]

'@

Invoke-AzRestMethod -Path "/subscriptions/d3c17595-846b-42e1-8e58-dc872136fbd2/resourcegroups/sentinel/providers/microsoft.operationalinsights/workspaces/sentinel3/tables/Syslog?api-version=2021-12-01-preview" -Method PUT -payload $tableParams

命令返回结果

验证新列已添加

在DCR模版处点击Deploy进入模版编辑模式，更改transformKql至source\n| extend BJTimeGenerated_CF = TimeGenerated + 8h\n

保存，等待30分钟后，查看BJTimeGenerated_CF列数据已是转换后数据

+++++++++++++++++++++++++++++++++++++++++++++++++++

对于syslog表格转换，参考文档https://docs.azure.cn/zh-cn/azure-monitor/logs/tutorial-workspace-transformations-portal 中提及的在表处create transformation操作方法，会在门户中创建新列，但是创建出的工作区转换DCR中转换值并无法关联应用至syslog DCR，在已创建出新列基础上，继续编辑syslog DCR转换，可实现syslog表转换。但不建议，因为会有额外的工作区DCR产生。

建议参考https://docs.azure.cn/zh-cn/azure-monitor/logs/tutorial-workspace-transformations-api 更新表架构，然后编辑syslog DCR实现转换，此操作不会产生额外的工作区DCR。
