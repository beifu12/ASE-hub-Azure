排查思路

  • 至于为什么需要让Azure的探测认为Baclkup上的服务状态是down的？这得从ILB的探测机制说起，ILB会采用Http和TCP进行探测，该探测会检查后端地址池虚拟机的服务状态。如果Backup（s）节点服务也是UP的，因此ILB会认为您的Backup(S)节点也是OK的，这就造成ILB会将客户端请求的流量转发到S。但是backup（S）上是没有浮动IP的，因此会造成ILB访问backup(S)节点失败。

关于Keepalived+Apache的简单示例：

两台虚拟机的内网地址是192.168.10.6和192.168.10.7

1、对于CentOS 6.x可以yum安装keepalived

yum install -y keepalived

2、安装完成之后，在/ect/keepalived/下有配置文件keepalived.conf。。主要部分修改如下：

! Configuration File for keepalived

global_defs {

notification_email {

}

notification_email_from Alexandre.Cassen@firewall.loc

smtp_server 192.168.200.1

smtp_connect_timeout 30

router_id fuzlhavm01  #router id每个成员必须使用一个唯一值

vrrp_instance VI_1 {

state MASTER

interface eth0

virtual_router_id 51

priority 100

advert_int 1

authentication {

auth_type PASS

auth_pass 1111

unicast_src_ip 192.168.10.6

unicast_peer {

192.168.10.7

}                                              /由于Azure Vnet不支持组播和广播，因此需要将VRRP的通告信息改为单播发送

virtual_ipaddress {

192.168.10.220/24   dev eth0 label eth0:0          /定义的虚拟浮动IP地址
