2019/07/08

Hi all，

分享个AWS API Server 发出的HTTP 请求带content type后得到502访问结果的工单。工单号：SR_2019062635020

问题描述：

用户使用Postman通过API 向AppGW做测试，Postman-------->Api server ------------>(port 443)AppGW------------> (port 81) VM， Postman上选择content-type 为application/json时，请求返回502， 不勾选时可以正常返回200ok， 需要协助排查问题。

content type screenshot:

排查经过：

首先可以确认的appgw 对 application/json的content-type的支持没有问题， 经过产品组的确认。

根据jarvis 日志https://jarvis-west.dc.ad.msft.net/1BBF8824查发现appgw_httpStatus 是502， 但backend_httpStatus的结果为空。Timetaken很短， 这里有两点怀疑，一是包根本没有到后端服务器，appgw直接给了502的返回值。 二是包到了后端服务器但在TCP 层出问题，没有到HTTP层的处理。 我们遇到的问题是情况一。

用户在后端虚拟机上进行抓包， 发现请求没有发到VM上。

我们在虚拟机的NODE 上抓包，发现请求没有到虚拟机的node。

我们在appgw实例上抓包，排查了抓包，发现当Postman显式声明content-type为application/json时, 从抓包来看请求并没有发往后端VM，而AppGW 将502的报错页面以text/html的方式返回给API。

wireshark打开了API发送过来的失败的请求， 发现有“http body subdissector failed trying heuristic subdissector”的报错提示， 怀疑与API发过来的format有关。

具体抓包分析：

PC: 本地PC带content-type:application/json 时：请求中没有异常的format报错，也没有带trunked encording ( 用户反馈不管PC端是否带trunked， 都是可以正常访问的，可能与带trunked属性关系不大)

Request:

Response:

API 端： 通过AWS API server发过来的请求中，带了transfer-encording: trunked 属性， 在HTTP trunked response中提示API 发送过来的body 无法获得subdissector， 具体应用层的报错以及调用逻辑请参考RFC文档：https://cs.fit.edu/code/svn/cse2410f13team7/wireshark/epan/dissectors/packet-http.c

在文章中发现关于content-Type ,trunked encording相关的报错场景：

If there was no Content-Length entity header, we should accumulate all data until the end of the connection. That'd require that the TCP dissector call subdissectors for all frames with FIN, even if they contain no data,

which would require subdissectors to deal intelligently with empty segments.

First, if we have a Content-Type value, check whether there's a subdissector for that media type, if We don't have a subdissector or we have one and it did not dissect the payload - try the heuristic subdissectors.

{ &ei_http_chunked_and_length, { "http.chunkd_and_length", PI_MALFORMED, PI_WARN, "It is incorrect to specify a content-length header and chunked encoding together.", EXPFILL }},

{ &ei_http_subdissector_failed, { "http.subdissector_failed", PI_MALFORMED, PI_NOTE, "HTTP body subdissector failed, trying heuristic subdissector", EXPFILL }},

问题排查结果：

用户认可了API 发出的format 与appgw的兼容问题，将对Api 版本进行升级修复。
