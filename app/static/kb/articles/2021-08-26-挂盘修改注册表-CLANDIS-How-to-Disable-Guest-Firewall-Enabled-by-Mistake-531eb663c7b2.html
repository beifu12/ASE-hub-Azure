SUMMARY

For compliance reasons we are not able to make changes to the guest operating system on customer's behalf.

You can use the following steps to disable the Windows guest firewall. You can do this by attaching the OS disk of the problem VM to another VM in Azure so you can edit the registry to disable the firewall so customers can RDP back into it.

DIAGNOSTICS

Perform the following steps to temporarily disable the guest firewall so you can RDP to the VM:

First create a new VM that you will use to troubleshoot the problem VM. Create this troubleshooting VM in the same cloud service as the problem VM.

Use a Windows Server 2012 R2 gallery image to create the troubleshooting VM (although any Windows image should work for this).

In the management portal, go to Virtual Machines, select the problem VM, select Shutdown, and wait for the status to reflect Stopped (Deallocated).

Once the VM is stopped, click Delete, and on the fly-up menu, select Keep the attached disks. This will deprovision the VM, but the disk/VHD file remains as-is with no changes whatsoever.

Once the problem VM is removed (but the disks remain), on the Dashboard of the newly created troubleshooting VM, select Attach Disk, and select the disk for the problem VM.

After that attach disk operation completes, RDP into the troubleshooting VM, launch the Disk Management tool (diskmgmt.msc), and make sure you see the disk you attached from the problem VM - it will likely be the F: drive.

Now run Regedit to open the registry and select HKEY_LOCAL_MACHINE

On the File menu, select Load Hive

Browse to Windows\system32\config on the attached drive (probably F: ) and choose the SYSTEM file and click Open.

In the Key Name field, type Repair and click OK.

Under HKEY_LOCAL_MACHINE, navigate down to HKEY_LOCAL_MACHINE\Repair\ControlSet001\services\SharedAccess\Parameters\FirewallPolicy\Domainprofile and set EnableFirewall to 0.

Also set EnableFirewall to 0 in the following locations:

HKEY_LOCAL_MACHINE\Repair\ControlSet001\services\SharedAccess\Parameters\FirewallPolicy\PublicProfile

HKEY_LOCAL_MACHINE\Repair\ControlSet001\services\SharedAccess\Parameters\FirewallPolicy\Standardprofile

On the left pane, scroll back up to the top, and select the Repair key under HKEY_LOCAL_MACHINE. Then on the File menu, select Unload Hive.

In the management portal, on the Dashboard of the troubleshooting VM, select Detach to detach the problem VM’s disk.

Recreate the problem VM from that same disk by going to New (at the very bottom left of the portal), then Compute, then Virtual Machines, then From Gallery, then select My Disks and select the problem VM’s disk, then provide the remaining details the same way it was created the first time (cloud service, virtual network, etc.).
