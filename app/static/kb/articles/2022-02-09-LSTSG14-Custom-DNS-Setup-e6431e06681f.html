LSTSG14 - Custom DNS Setup

How to change DNS nameserver and search suffix for VM in a vnet with own DNS (override DNS configuration provided by Azure DNS)

Problem Statement:

Name resolution for VM's in a VNET may fail if using Azure provided DNS

Example:

Name resolution between VMs located in the same virtual network (vnet) can be achieved using a DNS solution of your choice (not Azure-provided) alternatively for resolution using FQDN, you can use Azure-provided name resolution for the first 100 cloud services in the virtual network.

If you are to use your own DNS, Linux VM’s will need to be updated with the DNS server to be referenced

The network configuration for DNS resolution is stored in the /etc/resolv.conf and is populated by DHCP when the networking services start-up during the Linux boot process.

The /etc/resolv.conf defines which DNS server to query and which suffix to apply to a request.

In the case of a VM, deployed into a VNET running a DNS you should see in /etc/resolv.conf the IP of the VNETs DNS

Example Configuration

An Azure VNET – called  vflnet  with DNS server configured with a static IP 192.168.1.1

The Linux VM’s in the same vnet will have /etc/resolv.conf  nameserver  pointing to 192.168.1.1

Centos

search vflcentos1.a3.internal.cloudapp.net

nameserver 192.168.1.1

Ubuntu

search vflubuntu1.a4.internal.cloudapp.net

SuSE

search vflsuse1.a4.internal.cloudapp.net

The  search suffix defines what will be appended to the name lookup

Shortname lookup with VNETs

Example

Performing a DNS request using nslookup  in a Linux VM with a  shortname  of the VM we are logged into will fail

nslookup vflubuntu1

Server:         192.168.1.1

Address:        192.168.1.1#53

** server can't find vflubuntu1.vflubuntu1.a4.internal.cloudapp.net: SERVFAIL

From a packet capture, using tcpdump on the same client Linux VM we can see that the request is made to the IP of 192.168.1.1 , our configured DNS server – the request has appended the configured search suffix

Resolution:

Define your own DNS and Search Suffixes - How can I change the DNS server and search Suffixes provided by Azure in a Linux VM?

Here are the instructions and steps required should you need to change the DNS or suffix to utilise for DNS queries

The network configuration file is  /etc/sysconfig/network-scripts/ifcfg-eth0

The directives to add are as follows (values for these parameters will vary depending on configuration)

SEARCH="contoso.com"

DNS1="208.67.220.220"       <<<< This a DNS server provided by opendns.com but can be updated to your vnets

DNS IP

Restart the network using

service network restart

and verify the contents of the /etc/resolv.conf

search contoso.com

nameserver 208.67.220.220

Issuing a lookup for the name microsoft we can see the request with a modified suffix issued to the new DNS server

This fails as we have constructed a query of microsoft.suffix.com which does not exist – The response is coming back from the new DNS server – this is correct behaviour.

The file /etc/dhcp/dhclient.conf can be updated to change the domain suffix and the IP of the server

Append to the end of the file  .conf  file the following directives entering the values you require.

prepend domain-name-servers 208.67.222.222;

supersede domain-name "contoso.com";

Restart the networking by running

service networking restart

This will update the /etc/resolv.conf – note the original Azure provided nameserver currently persists as the last entry however DNS requests will be made to the IP 208.67.222.222 first
