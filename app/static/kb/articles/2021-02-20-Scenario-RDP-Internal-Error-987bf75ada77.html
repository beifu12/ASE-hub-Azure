一句话摘要

SMB connections works with no issues

问题现象 / 场景

  • SMB connections works with no issues
  • If you try to RDP the machine multiple times, you'll get different errors between 'RDP internal error' and 'This computer can't be connected to the remote computer. Try connecting again. If the problem continues, contact the owner of the remote computer or your network administrator'
  • If you see in detail the RDP attempt, the RDP is failling on the phase 'Configuring remote session' or 'Securing remote connections' <-------------------------- That's the key that the issue is on the tcp-listener

背景信息

  • Symphtom
  • Psping will responds just fine
  • When to use this guide:
  • A certificate was push to the tcp listener to secure RDP connections with the wrong hash
  • The certificate is corrupted
  • The certificate is expired
  • The security level of the OS was changed to a more restricted one
  • Action plan
  • If a certificate was pushed to the RDP listener, then remove it on the following keys:
  • HKLM\SYSTEM\CurrentControlSet\Control\Tqweerminal Server\WinStations\RDP-Tcp -------------------> Delete the key named like SSLCertificateSHA1Hash
  • HKLM\SYSTEM\ControlSet001\Control\Terminal Server\WinStations\RDP-Tcp -------------------> Delete the key named like SSLCertificateSHA1Hash
  • HKLM\SYSTEM\ControlSet002\Control\Terminal Server\WinStations\RDP-Tcp -------------------> Delete the key named like SSLCertificateSHA1Hash
  • Or else connect to the certificate repository and remove it from there:
  • run -> mmc -> file -> add/remove snapin -> certificates -> add -> computer account -> next -> another computer -> internalforms
  • then go into personal store -> right clicked on cert -> delete
  • If the security level was changed, then change the following keys
  • HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp\MinEncryptionLevel ----------------> From 2 to 1
  • HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp\SecurityLayer ----------------> From 1 to 0
  • Restart the VM

排查思路

  • If you check the eventlogs remotelly, the machine is running smoothly
