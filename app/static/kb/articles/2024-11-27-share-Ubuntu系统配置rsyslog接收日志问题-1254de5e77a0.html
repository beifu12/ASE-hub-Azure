2024/11/27

最近有个工单20241125326692，Ubuntu系统配置rsyslog接收日志的问题。与李老师沟通是权限问题导致，测试在/var/log下创建的目录，可以正常接收日志。但是客户不采用这种方式，需要解决在自己创建的根目录/mnt/rsyslog下可以成功接受日志。

后续发现是Apparmor安全模块阻止了rsyslog，解决方法分享给大家，供大家参考：

问题背景：

两台Azure Ubuntu vm ，一台vm配置rsyslog接受日志，另一台vm发送日志。

问题描述：

/subscriptions/4a064d3b-b7e9-4566-960f-948b42692735/resourceGroups/rg-itps-cne2-prode1-prod-hub/providers/Microsoft.Compute/virtualMachines/aclmvdpmon02

在另一台vm发送日志，参考命令：logger -n 172.31.1.1 -P 514 -t "test_tag" "This is a test log message"

然后在aclmvdpmon02使用命令查看systemctl status rsyslog.service，出现报错信息且在rsyslog配置文件对应的根目录下没有接受日志存在。

报错信息

Nov 25 11:38:53 aclmvdpmon02 rsyslogd[3577234]: rsyslogd: error during config processing: omfile: creating parent directories for file  '/mnt/rsyslog/10.59.176.69/10.59.176.69_2024-11-25.log' failed: Permission denied [v8.2312.0 try https://www.rsyslog.com/e/2207]

Nov 25 11:38:53 aclmvdpmon02 rsyslogd[3577234]: rsyslogd: error during config processing: Could not open dynamic file '/mnt/rsyslog/10.59.176.69/10.59.176.69_2024-11-25.log' [state -3000] - discarding message [v8.2312.0 try https://www.rsyslog.com/e/2207]

问题原因：

Apparmor安全模块阻止了rsyslog

解决方法：

/etc/apparmor.d/usr.sbin.rsyslogd 这个目录下可以看到Apparmor保护的程序，移除这个进程，就成功了。

测试解决方案参考：

Ubuntu-test作为接受日志的vm，Ubuntu发送日志。

1，Ubuntu-test：

创建目录/test1125，修改rsyslog配置文件/etc/rsyslog.conf，重启rsyslog服务

rsyslog配置文件/etc/rsyslog.conf信息：

重启rsyslog服务，Ubuntu发送日志，查看rsyslog状态，出现报错

2，/etc/apparmor.d/usr.sbin.rsyslogd 这个目录下可以看到Apparmor保护的程序，移除这个进程

新建目录mkdir /etc/apparmor.d/disable/

软链接ln -s /etc/apparmor.d/usr.sbin.rsyslogd /etc/apparmor.d/disable/

执行apparmor_parser -R /etc/apparmor.d/disable/usr.sbin.rsyslogd

查看看不到这个进程后，重启rsyslog服务，Ubuntu发送日志，/test1125可以接受到日志了。
