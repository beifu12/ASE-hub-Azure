问题描述：

=======

网络架构如下：

源虚拟机（FTP 客户端）- Azure 防火墙-互联网-目标虚拟机（FileZilla FTP 服务器）

Azure 防火墙位于客户端虚拟机前面。FTP 客户端可以正常连接到 FTP 服务器，但如果文件名包含 “port + 空格 ”等字符（例如 “port .txt” ），则无法在 FTP 被动模式下获取此类文件，其他文件均可正常获取

排查步骤：

经过和贵方的共同测试排查，整理出以下故障排除思路和结论并升级至产品组同事进一步查看

a. 通过贵方的防火墙获取 “port .txt ”文件会失败，绕过防火墙则成功。

b. 通过其他防火墙获取 “port .txt ”文件成功（如我们搭建的测试防火墙）。

c. 只要不通过贵方的防火墙，就可以正常获取 “port .txt ”文件。我们检查了客户防火墙的配置和日志，暂未发现异常。

产品组同事检查防火墙IDPS配置未见异常，日志未见Drop流量的相关记录

贵方协助复现问题产品组同事在防火墙实例抓包进行分析后发现访问“port .txt”的请求没有SNAT的流量，产品组进一步在实验环境测试验证了客户的防火墙实例处理“port .txt”的请求会错误地将其识别为主动模式的指令传输流量，而FTP主动模式默认是禁用的所以这个流量无法正常发送至FTP服务器端

贵方按照产品组同事的建议为防火墙启用FTP主动模式支持后问题解决，产品组在后期考虑评估修复Azure防火墙这个处理逻辑的缺陷，根据贵方需要已提供此问题的RCA

问题原因：

========

问题的根本原因可追溯到 Azure 防火墙的 FTP 协议处理逻辑中的冲突。具体来说，防火墙的协议意识错误地将涉及文件名为 “port .txt ”的被动模式 FTP 流量解释为主动模式 FTP 流量。这导致这些数据包没有经过防火墙的 SNAT（源网络地址转换）处理。因此，涉及此类文件名的后续操作请求无法到达 FTP 服务器。值得注意的是，这种行为是在客户设置的特定条件下出现的，在孤立的测试环境中无法复现，这进一步证实了影响防火墙 FTP 处理逻辑的配置相关限制。

解决方案*：

==============

客户按照产品组同事的建议（文档https://learn.microsoft.com/zh-cn/azure/firewall/ftp-support#）为防火墙启用FTP主动模式支持后问题解决，产品组会在考虑后期评估修复Azure防火墙这个处理逻辑的缺陷，我们已邮件提供此问题的RCA
