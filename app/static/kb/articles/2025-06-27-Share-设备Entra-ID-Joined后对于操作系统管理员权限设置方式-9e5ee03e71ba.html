问题背景：

客户本地设备没有本地域，仅是Entra ID Joined，使用了Entra ID》设备设置中的两个预览版功能。

问题1：需求使用独立账户作为所有设备操作系统内的管理员，而不想给该用户全局管理员角色。

问题2：同时在设备加入Entra ID后在系统管理员组中看到2个额外账户，需要确认功能。

解答：

问题1：

方法1：

您可以单独找云上的账户作为所有设备的全局管理员，从现有您提出的功能上是给该用户云中的全局管理员角色，根据官方文档也可以设置其它角色，但是文档中提到仅提到windows 10系统。具体您可以参考文档：Microsoft Entra 内置角色 | Azure Docs

方法2：

也可以通过intune策略集中推送，将某一AAD账号加入administrators里，具体路径如下：

问题2，S-1-12-2-*开头的用户是您本地加入Entra ID时自动生成的，分别是用于设备身份验证和策略管理以及任务管理的。不能删除。删除后无法恢复。如果误删除，请尝试将设备退出Entra ID，然后重新加入。

官方文档： https://docs.azure.cn/zh-cn/entra/identity/devices/assign-local-admin#default-local-administrator-accounts

根据官方文档介绍的原理进一步分析：

默认情况下，Azure AD 加入的设备会自动创建以下本地账户：

AzureADJoinedDeviceLocalAccount（SID 格式：S-1-12-2-*）用于设备身份验证和策略管理。

AzureADJoinedDeviceAdmin（SID 格式：S-1-12-2-*）用于设备管理任务（如证书续订、合规性检查）。

这些账户不应手动删除或修改，否则可能导致设备管理功能失效。

如果要验证这些SID用户的合法性，可以使用以下命令查看，合法的 Azure AD 相关 SID 会显示 PrincipalSource: AzureAD

查看本地 Administrators 组成员及其来源

Get-LocalGroupMember -Group "Administrators" | Format-Table Name, SID, PrincipalSource
