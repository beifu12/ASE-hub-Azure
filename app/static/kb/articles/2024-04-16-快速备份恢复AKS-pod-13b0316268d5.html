后续测试过程如下：

方法一、门户创建快照，在门户创建为磁盘，使用该Disk创建POD，该方法，需要自行查找资源ID，恢复方法简化了快照和创建磁盘步骤。

测试yaml文件

---

kind: Pod

apiVersion: v1

metadata:

name: nginx-azuredisk-2024-04-16-2

spec:

nodeSelector:

kubernetes.io/os: linux

containers:

  • image: mcr.microsoft.com/oss/nginx/nginx:1.17.3-alpine

name: nginx-azuredisk

command:

  • "/bin/sh"
  • "-c"
  • while true; do echo $(date) >> /mnt/azuredisk/outfile; sleep 1; done

volumeMounts:

  • mountPath: "/mnt/azuredisk"

name: volume

readOnly: false

volumes:

  • name: volume

azureDisk:

kind: Managed

diskName: 磁盘名称

diskURI: /subscriptions/订阅ID/resourceGroups/资源组名称/providers/Microsoft.Compute/disks/磁盘名称

方法二、用门户创建快照后，在门户创建为磁盘，然后在AKS使用磁盘创建PV、创建PVC绑定，使用该PVC创建POD，该方法为结合文档的流程

一、Create PV

kind: PersistentVolume

annotations:

pv.kubernetes.io/provisioned-by: disk.csi.azure.com

name: pv-azuredisk

capacity:

storage: 10Gi

accessModes:

  • ReadWriteOnce

persistentVolumeReclaimPolicy: Delete

storageClassName: managed-csi

csi:

driver: disk.csi.azure.com

volumeHandle: /subscriptions/订阅ID/resourcegroups/disk的资源组/providers/Microsoft.Compute/disks/磁盘名称

volumeAttributes:

fsType: ext4

二、Create PVC

kind: PersistentVolumeClaim

name: pvc-azuredisk

resources:

requests:

volumeName: pv-azuredisk

三、通过PVC创建测试POD

name: nginx-azuredisk-2024-04-16

  • name: azuredisk01

mountPath: "/mnt/azuredisk"

persistentVolumeClaim:

claimName: pvc-azuredisk

四、测试命令：kubectl exec pod名称  -- ls /mnt/azuredisk
