面临问题：

附上：其他警报查询语句示例：

示例2： 多台计算机处于严重状态

如果有 20 台以上的已复制 Azure VM 进入严重状态，则设置警报，对于警报，请将“阈值”设置为 20。

示例3： 多台计算机超过 RPO

如果有 20 台以上的 Azure VM 的 RPO 超过 30 分钟，则设置警报，对于警报，请将“阈值”设置为 20。

| where rpoInSeconds_d > 1800

| project name_s , rpoInSeconds_d

示例4： 一台计算机超过 RPO

如果只有一台 Azure VM 的 RPO 超过 30 分钟，则设置警报，对于警报，请将“阈值”设置为 1。

| where name_s == "ContosoVM123"

示例5： 多台计算机的测试故障转移超过 90 天

如果 20 台以上的 VM 的上次成功测试故障转移超过 90 天，则设置警报，对于警报，请将“阈值”设置为 20。

| where Category == "AzureSiteRecoveryReplicatedItems"

| where lastSuccessfulTestFailoverTime_t <= ago(90d)

| where name_s == "lyt_VM"

示例5： Site Recovery 作业失败

如果在过去一天，某个 Site Recovery 作业（在本例中为“重新保护”作业）在任何 Site Recovery 方案中失败，则设置警报，对于警报，请将“阈值”设置为 1，将“期限”设置为 1440 分钟，以检查过去一天发生的失败。

| where OperationName == "Reprotect"

| where ResultType == "Failed"

拓展信息：

ASR诊断日志以什么频率从ASR发送到Log Analytics?

AzureSiteRecoveryReplicationStats 和 AzureSiteRecoveryRecoveryPoints 每隔15mins发送一次；

AzureSiteRecoveryReplicationDataUploadRate 和 AzureSiteRecoveryProtectedDiskDataChurn 每隔15mins发送一次；

AzureSiteRecoveryJobs 在一个Job被触发、完成时，都将被发送；

AzureSiteRecoveryEvents 只要生成，将被发送；

AzureSiteRecoveryReplicatedItems 一旦环境有更改的时候，通常数据刷新时间为更改后15mins；

在 Log Analytics中有多少数据可以被保留?

默认情况下，数据保留31天。你可以通过LA workspace中的“使用情况和预估成本”--“数据保留”来扩展数据保留的时间。

ASR诊断日志一般多大?

通常诊断日志大小在 15-20 KB。
